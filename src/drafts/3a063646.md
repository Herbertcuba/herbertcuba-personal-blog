In July 2026, Claude user Om Patel paid $200 for Claude Max, Anthropic's high-usage subscription, and recorded 6.16 billion tokens across 36,881 responses through Claude Code, Anthropic's command-line coding agent. [His usage report](https://x.com/om_patel5/status/2083401185172541449) valued the same activity at $7,470.35 under published API rates. Bought directly, that month would have cost 37.4 times his subscription.

Three numbers matter here. Patel paid $200, the usage had an API list value of $7,470.35, and Anthropic's underlying compute cost remains undisclosed. The subscription gives Patel a real discount, but it also removes the price signal that would teach him which behavior is expensive.

That missing lesson is context engineering: deciding what information a model receives, when it receives it, and what can safely be left behind. I think this will become a core engineering skill, because flat pricing can hide a weak context habit only as long as the flat price survives.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>The direct-API equivalent of Patel's month was $7,470.35, although that was neither his bill nor Anthropic's compute cost. The strategic risk is the efficiency lesson concealed by the $200 subscription.</p></div>

## Most of the bill was old context

An agentic coding tool lets a language model inspect files, call tools, and revise code over many turns. Each model request includes context: system instructions, conversation history, code, tool definitions, and previous tool output. As the session grows, much of that material returns on every turn even when the new question is small.

Prompt caching reduces the price of this repetition by saving computational work for an unchanged beginning of a request. A cache write creates that reusable state; a cache read uses it at a discounted rate. Caching helps, but it does not remove stale material from the model's limited attention or teach the user what should have been excluded.

Patel's report makes the mechanism visible. Cache reads and writes represented 86.2% of the API-list-price total, while generated output represented 13.6%. Across the month, the tool consumed 186 tokens for every token it generated.

A second measurement points in the same direction without turning one case into an industry average. AI practitioner Nate B. Jones, who sells a context-management framework, [instrumented one working day](https://www.youtube.com/watch?v=Y8vAQ1FgNbM) in OpenAI's Codex coding workspace. Of 3.77 billion tokens across 143 threads, 3.59 billion were reused input, almost 96%. Manus, a production AI-agent service, separately [reported in 2025](https://manus.im/blog/Context-Engineering-for-AI-Agents-Lessons-from-Building-Manus) an average input-to-output ratio of about 100 to 1.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>The 96% figure belongs to one instrumented day, but Patel's bill and Manus's production ratio confirm the mechanism: coding agents repeatedly process far more existing context than new output.</p></div>

## Context engineering is careful subtraction

Long context can raise cost and reduce quality at the same time. In *Lost in the Middle*, a peer-reviewed 2024 study by Stanford and University of California, Berkeley researchers, models performed worse when relevant information sat inside a long input rather than near its beginning or end. More material can therefore make the useful evidence harder for the model to use.

Claude Code already uses caching and auto-compaction, which summarizes a conversation as it approaches the context limit. That is a useful default, but a summary is a decision about what to forget. The tool cannot always know which failed attempt contains an important constraint or which old requirement no longer matters.

The engineer still has four practical jobs. Start a fresh thread when the task changes, carrying forward a concise artifact such as the accepted requirements and current diff. Search for the relevant files before invoking the model instead of loading a repository indiscriminately. Keep stable instructions together so caching can reuse them. Finally, cap unnecessary output and use the least expensive model that consistently passes the team's acceptance checks.

Subtraction must remain evidence-led. Difficult one-shot tasks may need broad source material, and aggressive pruning can remove the fact that prevents an error. Good context hygiene preserves the artifact and discards the obsolete discussion around it.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Automatic caching and compaction are a floor, not a complete context strategy. Engineers must preserve task-critical evidence while removing stale history, irrelevant files, unstable instructions, and needless output.</p></div>

## Measure the work that survives

Token totals describe activity, not value. The better unit is cost per accepted result: the API cost of every model call used for a task, including failed attempts, divided by the outputs that pass the agreed test. For a coding team, an accepted result might be a change that passes automated tests and human review.

This measure catches trade-offs that token dashboards miss. A cheaper model that needs repeated retries may cost more per accepted change. An expensive model can also waste money if every call carries an oversized transcript. Track uncached input, cache reads, cache writes, output, retries, and acceptance together, then compare similar task types.

Pricing changes are not hypothetical. Technology critic Ed Zitron [documented](https://www.wheresyoured.at/the-more-you-buy-the-more-you-lose/) how heavy users of GitHub Copilot, an AI coding assistant, consumed more than 25 times their monthly fee before a move to token-based billing triggered a backlash. A subsidy can disappear before the habits it encouraged do.

The $7,470.35 figure is not a forecast of Patel's future bill. It shows what an undisciplined context habit can look like under direct API pricing. Learn to improve cost per accepted result while the monthly invoice is still flat, and a future pricing change becomes an engineering adjustment rather than a budget emergency.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Manage AI coding by cost per accepted result, not raw tokens or subscription price. That measure rewards useful context, exposes retries, and makes the team ready for direct billing.</p></div>
