An [X post from Om Patel](https://x.com/om_patel5/status/2083401185172541449) included a screenshot of a Claude subscriber's July 2026 usage. The plan cost $200. A tracking tool priced the same month at $7,470.35 using API list rates. That is a 37.4x gap.

The subscriber never received a $7,470 invoice. The image gives us no view into Anthropic's internal serving cost. I don't know what the month cost the company. I think the useful signal is simple: a flat plan hid how much text the agent kept moving.

The screenshot counted 6.16 billion tokens across 36,881 responses. Cache reads represented 48.1 percent of the displayed value, one-hour cache writes represented 38.0 percent, and output represented 13.6 percent. Using the dollar line items, reads plus one-hour writes account for 86.2 percent. A write stores content; a read retrieves an existing prefix. That total belongs to cache operations. Retrieval is measured by the 48.1 percent read line.

I think the 48.1 percent cache-read line deserves more attention than the 37.4x headline. It points to behavior a team can change.

## The cache split tells us where to look

The screenshot's reads and writes point to context movement, though they record different events.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Nate B. Jones's tracker classified 3.59 billion of 3.77 billion tokens in one Codex workspace as reused input across 143 threads. That 95.2 percent covers one person's instrumented day.</p></div>

Nate B. Jones [reported those numbers](https://www.youtube.com/watch?v=Y8vAQ1FgNbM) from one working day. The [Messages API](https://platform.claude.com/docs/en/build-with-claude/working-with-messages) keeps no conversation state between calls, leaving the client to send the history with each request. Under [prompt caching](https://platform.claude.com/docs/en/build-with-claude/prompt-caching), a cache hit costs one tenth of the base input rate. That discount tells us how cheaply an old prefix moved. The team still has to decide whether it helped.

Use a hypothetical renewal defect as the test case. One customer is charged twice. The first useful request needs the failing test, the billing rule, and the current function. Nine attempts later, the request can be padded with stale traces, rejected diffs, and explanations for routes that failed. I think context debt is the gap between ever more carried history and a flat count of accepted results.

## Price the artifact that passed review

The double-charge fix gives the budget a cleaner denominator: one patch that passed its test and human review.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Cost per accepted result includes every model attempt and the loaded cost of review. Only an accepted artifact may seed future work.</p></div>

Every attempt contributes model spend, including the rejected patches. Finance supplies a loaded hourly reviewer rate. Sum the attempts, then calculate `(model spend + reviewer minutes / 60 × loaded hourly rate) / accepted results`. Until that rate exists, report model money and reviewer minutes as separate measures. I think reviewer time should remain visible even after Finance converts it to money.

One JSONL record per attempt is enough to start:

```json
{"task_id":"renewal-double-charge","task_type":"billing-defect",
 "policy_version":"expiry-v1","attempt":1,"retry_cap":3,
 "model_version":"PINNED","tool_versions":["PINNED"],"prompt_version":"PINNED",
 "fresh_input_tokens":0,"cache_read_tokens":0,"cache_write_tokens":0,"output_tokens":0,
 "input_artifacts":[{"id":"","version":""}],"output_artifacts":[{"id":"","version":""}],
 "tool_results":[{"id":"","source":""}],
 "model_cost_usd":0,"ci_status":"pending","failure_class":null,
 "reviewer_id":"","reviewer_decision":"pending","reviewer_minutes":0,
 "reviewer_loaded_cost_usd":0}
```

A passing test leaves the artifact in review. Human acceptance unlocks carry-forward. A failed or unreviewed attempt may preserve a short failure note, while its transcript expires. This gives [agent loops](/posts/everyone-discovered-loops/) an economic boundary tied to the result they produce.

## Put the old thread on trial

Thirty closed billing defects can compare the current growing-thread habit with a deliberate carry-forward rule.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Replay matched tasks under fixed conditions. Adopt the expiry rule only when it lowers cost per accepted result without losing accepted fixes or moving correction work to reviewers.</p></div>

For the renewal defect, the expiry rule carries the current test, the relevant source slice, the latest patch, and one failure note. Once the patch is accepted, store its test evidence and review decision. The next task starts clean.

That is the useful part of *Edge of Tomorrow*. Each loop carries the lesson while the battlefield resets. Agent memory should do the same with reviewed evidence.

Give one platform engineer two weeks to instrument and replay the tasks. One product team supplies the closed defects. Two reviewers judge final patches without seeing which policy produced them. Pin the model, tools, prompt, and three-attempt cap.

Predeclare the decision rule. Require at least a 10 percent reduction in cost per accepted result, the same accepted count, and no increase in median review time. A miss leaves the default unchanged and triggers analysis by task type.

## Make the scorecard an operating decision

At month-end, the platform owner brings one page to FinOps with accepted changes, spend, review time, and failed task classes.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>A named owner should report accepted-result economics in the monthly review. Procurement and security govern the supplier terms and retention rules that shape the number.</p></div>

Platform engineering owns the trace contract and its schema. Product engineering writes the acceptance rule, while Finance converts review time into loaded cost. Security approves what may be retained, where it may reside, and what must be redacted. Procurement's supplier checklist covers cache rates, usage caps, export access, and notice before price changes.

The scorecard turns agent usage into capacity planning. The renewal fix counts once, with every model attempt and review minute attached. It shows how many accepted changes a budget buys. That is the economics layer beneath [the orchestration era](/posts/welcome-to-the-orchestration-era/).

The prevalence of 95.2 percent remains an open empirical question. Each team can answer it from its own requests. A curated record also makes the result reconstructable: which evidence traveled forward, which artifact passed, and who accepted it.

When a budget is judged by accepted changes, stale context finally shows up as lost capacity.
