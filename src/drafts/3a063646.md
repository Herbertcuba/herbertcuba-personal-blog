In July 2026, Claude Code user Om Patel [posted a screenshot](https://x.com/om_patel5/status/2083401185172541449) from Claude Code, the terminal-based coding agent made by Anthropic, an AI company. His trace recorded 6.16 billion tokens, the units of text a model processes, over one month.

Patel paid $200 for Claude Max. Routed through Anthropic's API, the metered interface for calling its models directly, the same traffic would have produced a $7,470.35 list-price bill. That is 37.4 times the subscription fee. It is not Anthropic's undisclosed compute cost, and subscriptions have usage limits, but it reveals an important downside of flat pricing: we can use more without learning to use better.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>The direct-API counterfactual is $7,470.35 rather than $200. It is a retail-price comparison, but it shows how much economic feedback the subscription hides.</p></div>

## The bill is mostly yesterday's context

Cache reads and writes, operations that store and reuse earlier context, made up 86.2% of Patel's simulated API bill. Generated output accounted for 13.6%. Across the trace, the agent consumed 186 tokens for every token it produced.

Context is everything the model receives for one request: instructions, conversation history, tool descriptions, code, and results. Because each model request starts without memory of the session, the coding-agent software sends much of that material again. Context caching lets the provider reuse computation for an unchanged beginning of a request at a lower price, but it does not make repeated input free.

The exact ratio varies. AI practitioner Nate B. Jones [measured one workday](https://www.youtube.com/watch?v=Y8vAQ1FgNbM) in which 3.59 billion of 3.77 billion tokens were reused input, almost 96%. The team behind the Manus general-purpose AI agent [reports](https://manus.im/blog/Context-Engineering-for-AI-Agents-Lessons-from-Building-Manus) an average input-to-output ratio near 100:1 in production. Jones's 96% is not an industry average, but the repeated-input mechanism is clearly broader than one user.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Agentic coding repeatedly sends the working history needed for the next step. Caching discounts that traffic, yet old context can still dominate a metered bill.</p></div>

## Long context can also weaken the answer

*Lost in the Middle*, a 2024 peer-reviewed study of how language models use information in long inputs, [found](https://arxiv.org/abs/2307.03172) that performance often falls when the relevant material is buried in the middle, even for models designed to handle long contexts. More available text does not guarantee that the model will use the right text well.

Coding agents already use caching and auto-compaction, which summarizes older conversation when a thread approaches its limit. Both help, but neither chooses what deserves attention. Caching can repeat irrelevant material cheaply, while compaction can omit a constraint or failed attempt that still matters. Some tasks genuinely require a broad source set, so context hygiene means deliberate selection rather than blind deletion.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Accumulated context can raise cost and bury useful evidence. Automated caching and summaries help, but relevance still requires an engineering decision.</p></div>

## Learn context hygiene while it is cheap

Context engineering is the practice of choosing what a model sees, in what order, and in what form. Start a new thread when the objective changes. Before leaving the old one, carry forward a compact artifact with the goal, constraints, decisions, accepted output, unresolved errors, and relevant file locations. Preserve the state of the work without preserving every turn that produced it.

Before each call, search for the relevant files, load only descriptions of tools the task needs, and cap verbose tool output. Put stable instructions first so caching can work, and match the model to an acceptance test instead of using the most expensive model at every step. Track input, cache traffic, output, retries, and accepted results now, while the subscription makes experiments inexpensive.

Pricing can move faster than habits. Technology critic Ed Zitron [reports](https://www.wheresyoured.at/the-more-you-buy-the-more-you-lose/) that heavy users of GitHub Copilot, Microsoft's AI coding assistant, consumed more than 25 times their monthly fee before a shift toward token billing led to a backlash. That does not predict Anthropic's next move. It does show why efficiency learned after repricing is efficiency learned late.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Use flat pricing to practice clean task boundaries, compact handoffs, selective retrieval, cache-friendly requests, and visible usage measurement.</p></div>

## Measure what survives review

Cost per token can reward the wrong outcome because a cheap response that fails three times is still expensive. Cost per accepted result is stronger: divide total model and tool spend, including retries, by the outputs that pass agreed tests or review and are actually kept. It puts context selection, model choice, and quality inside one operating measure.

Can your team connect last month's AI spend to accepted code changes, analyses, or other finished work? If not, it is measuring traffic rather than value. I think the $200 subscription remains an extraordinary bargain. Use that bargain to learn the subtle skill it currently lets us ignore, before the counterfactual invoice becomes the real one.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Optimize for the cost of work that passes review and gets used. That turns context hygiene into a durable production skill.</p></div>
