On August 1, 2026, AI practitioner Om Patel [shared a dashboard](https://x.com/om_patel5/status/2083401185172541449) for an unidentified person’s July use of Claude Code, the command-line coding agent from AI company Anthropic. It recorded 6.16 billion tokens, the units of text a model processes, alongside a reported $200 subscription.

At public API list prices, the dashboard estimated that same mix of usage at $7,470.35, or 37.4 times the subscription fee. That is the direct-API cost comparison the flat plan concealed. It is neither an invoice nor Anthropic’s undisclosed cost of serving the requests, and a negotiated API contract could produce a different bill.

I think the more important gap is educational. A flat fee removes the visible added cost of each request, so teams can build expensive context habits without noticing. If they later move workloads to an API, encounter tighter limits, or face different plan terms, the bill may change before their engineering practice does.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>The measured month would have cost $7,470.35 at public API list prices, but the deeper risk is that a $200 plan hid the habits creating that exposure.</p></div>

## Most of the traffic is old news

Claude Code [sends the full conversation history with each request](https://code.claude.com/docs/en/costs). That context can include instructions, messages, files, tool definitions, and tool results. As a thread grows, each new turn can therefore carry far more old material than new work.

Prompt caching softens the price by storing an unchanged opening segment and reusing it at a lower listed rate. In Patel’s dashboard, cache reads accounted for $3,595.52, while one-hour and five-minute cache writes accounted for $2,841.89 and $2.83 respectively. Those cache operations made up 86.2% of the $7,470.35 estimate. Caching made repetition cheaper; it did not make the repeated material disappear.

A second observation shows the same shape, although it is not an industry benchmark. In July 2026, AI practitioner Nate B. Jones [reported](https://natesnewsletter.substack.com/p/reduce-ai-token-usage) that 3.59 billion of 3.77 billion tokens logged across 143 threads in one working day with Codex, a coding agent from AI company OpenAI, were reused input, meaning text from earlier requests processed again. That is 95.2%, often rounded to 96%. The measurement was self-instrumented, not a provider bill, and Jones promotes a related optimization product.

Volume also affects quality. *Lost in the Middle*, a peer-reviewed 2024 study by researchers from Stanford University, the University of California, Berkeley, and AI company Samaya AI, [found](https://arxiv.org/abs/2307.03172) that models often perform worse when relevant information sits inside a long input. Old context can cost money while making the useful evidence harder to recover.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Two individual measurements point to heavy context reuse, while product mechanics and research explain why repeated history can affect both price and answer quality.</p></div>

## Context engineering is selective memory

Context engineering means deliberately choosing which instructions, evidence, history, tools, and results enter a model request. The aim is a request no larger than necessary but still complete enough for the current task to succeed reliably.

Start a clean thread when the job changes. Carry forward a compact artifact containing the objective, accepted decisions, relevant interfaces, unresolved failures, and evidence locations. Retrieve the necessary file or log excerpt when needed instead of replaying every search result and abandoned path.

There is a real countercase. Removing failed attempts can erase useful evidence, and changing the beginning of a request can break the exact-prefix match that [Anthropic’s prompt cache](https://platform.claude.com/docs/en/build-with-claude/prompt-caching) depends on. Stable instructions and tool definitions should stay early; changing task material can follow them. Automatic caching and compaction help, but they do not remove the team’s responsibility for choosing task boundaries and preserving evidence.

So instrument before pruning. Keep fresh input, cache reads, cache writes, output, retries, and task outcomes separate. Otherwise a lower token total can hide a higher failure rate or more human review.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Good context engineering preserves task evidence, removes irrelevant history, and protects stable cacheable prefixes instead of deleting tokens indiscriminately.</p></div>

## Price the result that passes

Token cost alone cannot tell you whether the change worked. An accepted result is an output that passes a test defined before the run, such as successful automated checks plus reviewer approval for a code change. Full cost per accepted result should include model usage, the allocated subscription or API charge, retries, failed outputs, reviewer time, and any context-management tooling, divided by the number of accepted results.

Run a small comparison on matched task types. Keep the model and acceptance rule fixed, repeat runs because model outputs vary, and compare normal threads with the selective-context approach. Subscription users can estimate what their usage would cost at public API rates; API users can use the actual charge. Reject any apparent saving that lowers acceptance or pushes more work onto reviewers.

The $200 plan gives teams cheap room to learn this discipline. That room may last, but it may also narrow through caps, API migration, or pricing changes. Learning what deserves a place in the request is valuable either way, because a lower cost per accepted result means the system became more efficient without quietly making the work worse.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Judge context changes by the full cost of work that passes, including failures and review, so a cheaper request cannot masquerade as a better system.</p></div>
