Software founder [Om Patel](https://x.com/om_patel5/status/2083401185172541449) posted a screenshot of his July 2026 use of Claude Code, a terminal-based agent for multi-step coding work from Anthropic, the AI company behind Claude. A usage tracker called `claude-cost` priced his 6.16 billion tokens and 36,881 responses at $7,470.35 using Anthropic's published application programming interface rates. An application programming interface, or API, is the metered channel software uses to call a model directly. A token is a unit of text used to meter model input and output. Patel's subscription bill remained $200.

The $7,470.35 is a counterfactual API-list-price estimate, meaning a calculation of what the same recorded traffic would have cost through the API. It is separate from Patel's invoice, any negotiated enterprise rate, and Anthropic's undisclosed cost of serving the tokens. Even with those boundaries, the receipt has teeth: the same model mix and traffic bought directly at the public rate card, the provider's price table, would have carried a 37.4 times larger meter.

The shape of that meter is more revealing than the headline. Cache reads, which retrieve a matching prompt prefix stored earlier, represented 48.1 percent of the displayed value. One-hour cache writes, which create those stored prefixes, represented 38.0 percent. Together they account for $6,437.41, or 86.2 percent, while generated output accounts for 13.6 percent. The combined share measures cache activity, while retrieval belongs to the read line alone. Context means the instructions, history, tool descriptions, and task evidence sent with a model call.

A separate observation points toward the mechanism. AI practitioner [Nate B. Jones](https://www.youtube.com/watch?v=Y8vAQ1FgNbM) reported 3.77 billion tokens moving through 143 threads in Codex, the coding agent from the AI company OpenAI, in one day. His tracker classified 3.59 billion as reused input, his label for material sent in earlier requests, which works out to 95.2 percent for one instrumented workspace. Jones sells a context-management layer called Ringer, and his public video omits the raw export, collection code, model versions, and a reproducible field-level definition of reuse. The commercial interest and missing evidence package make the figure a strong signal with a weak benchmark behind it.

## What $7,470 would have cost without the subscription

Without the subscription, this reported workload would have carried a $7,470.35 API bill at the [public rates](https://docs.anthropic.com/en/docs/about-claude/pricing), assuming the same model mix and traffic. Large customers can negotiate lower rates, while Anthropic's internal compute cost remains undisclosed. The useful comparison is therefore $200 paid against $7,470.35 of retail API value, rather than a claim that Anthropic lost $7,270 on one account.

The screenshot also survives a basic price check. At the July 2026 rates, an Anthropic cache read cost $0.50 per million tokens on its Opus model family and $1 on its Fable 5 model. The workload mixed those models. Its $3,595.52 read charge across 5.878 billion cached tokens implies a blended rate of about $0.61 per million, which falls between the two published prices.

Extend the same heavy-user month across one quarter and the counterfactual becomes $22,411.05 against $600 in subscription fees, an implied list-price discount of $21,811.05. Extend it to one million equally heavy subscribers for six months and the gap reaches $43.6 billion. That second extension is a ceiling case. Anthropic uses [rolling five-hour windows and weekly limits](https://claude.com/pricing), most subscribers consume less, and list prices contain retail margin.

[Epoch AI](https://epochai.substack.com/p/can-ai-companies-become-profitable), an independent research group that studies AI economics, estimated that inference compute, the computation used to serve model responses, consumed roughly two thirds of revenue for a bundle built around OpenAI's GPT-5 model. That is a proxy from another company and another product. I don't know Anthropic's comparable number. No such figure appears in the cited public sources. I think the cleanest reading is still uncomfortable: the true cost sits somewhere below the list-price meter, while the subscription keeps both the cost and the user's operating habits out of view.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Direct API billing at the published rates would have put $7,470.35 on this reported workload. That number overstates Anthropic's serving cost, yet the verified model mix and blended cache rate show that the counterfactual meter itself is internally consistent.</p></div>

## The subscription hides the skill you need

An all-you-can-use plan changes behavior because the next turn feels free. A direct API returns usage fields and charges for the tokens, which creates an immediate learning loop. The team can inspect a request, reduce a repeated prefix, and see whether the next accepted result costs less. An accepted result is an output that passes its check and review. The subscription removes much of that pressure, rewarding throughput today while letting inefficiency become a habit.

This is the downside of avoiding direct API tokens. The plan can remain an extraordinary financial deal for the user, while the team fails to learn how its agents consume context. I think that hidden skill gap is more consequential than this month's discount. A pricing change can arrive in a day; the ability to decide which evidence an agent needs takes practice.

Anthropic can afford the gap for a while. Independent software analyst [Simon Willison documented](https://simonwillison.net/2026/May/29/anthropic/) Anthropic's self-reported fundraise figures: run-rate revenue, an annualized snapshot of the current revenue pace, rose from about $9 billion at the end of 2025 to $47 billion in May 2026, while two funding rounds raised $95 billion. Those figures show capacity to subsidize adoption. They offer no promise that today's prices and limits will remain available.

GitHub Copilot offers a useful precedent. It is the AI coding assistant from GitHub, Microsoft's software-development platform. Technology critic [Ed Zitron reported](https://www.wheresyoured.at/the-more-you-buy-the-more-you-lose/) that its power users once consumed more than 25 times their monthly subscription fee. He described a user revolt when those users were switched to token-based billing. The exact commercial path for Claude may differ, but the direction of travel is easy to imagine.

The skill worth learning is context engineering: deliberately choosing the information an agent receives, retains, and drops as work moves forward. It is subtler than prompt writing because the best intervention often happens before the prompt exists. Search the repository, select the evidence, set an output limit, and decide what earns a place in the next turn. Learning that discipline while the subscription absorbs mistakes may become a lifesaver when the meter moves.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Subscriptions weaken the token-by-token feedback that teaches efficiency. Their temporary generosity creates a useful training window for context engineering, a capability that becomes far harder to build after caps or prices tighten.</p></div>

## Why old text takes over the bill

Anthropic's [Messages API](https://platform.claude.com/docs/en/build-with-claude/working-with-messages) is stateless, which means the model keeps no conversation memory between calls. The client reconstructs that memory by sending the conversation history again with each request. An agent may also attach its system instructions, tool definitions, opened files, and previous tool results. Every turn inherits the material from the turns before it.

Suppose an engineer asks an agent to fix a checkout bug. The first request carries the instructions and bug report. The next carries those items plus the first response and an opened file. By turn twenty, one new question can arrive behind nineteen earlier exchanges and a growing pile of repository text. Request size rises with the history, so long-running loops pay repeatedly for old material.

[Prompt caching](https://platform.claude.com/docs/en/build-with-claude/prompt-caching) softens the price. Anthropic stores a stable prompt prefix and charges a matching cache read at one tenth of base input price. That is delivery efficiency. Relevance requires a separate test. A cheap cache hit can still carry stale debate, superseded patches, or a file that stopped affecting the answer ten turns ago.

Jones's one-day report puts a dramatic number on this pattern, although the missing evidence package limits how far it can travel. A second source supports the shape from a production vantage point. [Manus](https://manus.im/blog/Context-Engineering-for-AI-Agents-Lessons-from-Building-Manus), a company building a general-purpose AI agent, reported in a 2025 engineering post that its average input-to-output ratio was about 100 to 1. Different systems and definitions prevent a clean comparison, yet both observations show input volume dominating generated output in agent loops.

I think context debt is the retained material whose removal lowers total cost without reducing acceptance or increasing review time. That definition makes the idea testable, and it also covers quality. *[Lost in the Middle](https://arxiv.org/abs/2307.03172)* is a 2023 study by researchers affiliated with Stanford University and the University of California, Berkeley. It appeared in 2024 in *Transactions of the Association for Computational Linguistics* (TACL), a peer-reviewed journal. The researchers found that models often perform worse when relevant information sits in the middle of long inputs. Old context can charge twice, once through the meter and again through a weaker answer.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Stateless model calls rebuild memory by resending history, and prompt caching only discounts that delivery. Context debt begins when retained material keeps consuming model or reviewer resources without improving accepted work.</p></div>

## Where context debt comes from

The expensive failure modes look ordinary because each one begins as a reasonable shortcut. A thread stays open for convenience, a whole file replaces a targeted search, or a failed tool call retries with the same growing envelope. Each local choice is small, while the repeated cost compounds across every later turn.

Model Context Protocol, or MCP, is a standard for connecting models to external tools and data. Willison later [documented engineer Geoffrey Huntley's estimate](https://simonwillison.net/2025/Aug/22/too-many-mcps/) that the popular GitHub MCP server exposed 93 tools and consumed about 55,000 tokens of definitions. The exact overhead varies by server and client, but the mechanism is direct: every tool description loaded into the request competes with task evidence for the same working window, the text the model can see during one call.

These five failures share one mechanism: admission by convenience. Material enters the prompt because it is nearby, and it stays because removal requires a decision. Context engineering turns that default around by making continued presence an explicit, reviewable choice.

## The subtle art of context engineering

Modern coding agents already compact long threads. [Claude Code's cost documentation](https://code.claude.com/docs/en/costs), for example, says the tool summarizes conversation history as it approaches its context limit. Compaction helps. Yet the harness, the software that assembles and runs the agent loop, chooses what survives when the model nears that limit. Deliberate context engineering decides earlier and records the reason.

The hardest practice is carrying the artifact. An artifact is the output that can be checked and used, such as a patch that passes continuous integration (CI), the automated checks run when code changes, or an approved decision record. Carry-forward means admitting that artifact or reviewed evidence into a later run. The `carry_forward` field should record that admission decision explicitly, because raw transcripts and unreviewed patches should never inherit approval by proximity.

A small lifecycle makes the rule executable. A trace is the request-and-result record for one agent run. An item can move through `candidate`, `reviewed`, `admitted`, `rejected`, `expired`, and `superseded`. Every transition records a task identity, artifact identity, trace identity, event time, reviewer, and reason. An accepted patch might look like this:

```json
{
  "task_id": "checkout-417",
  "trace_id": "run-9f31",
  "artifact_id": "patch-v2",
  "review": {"status": "accepted", "check": "ci-pass"},
  "retention": {
    "state": "admitted",
    "carry_forward": true,
    "expires_on_event": "artifact-superseded"
  }
}
```

The validator rejects a `candidate` moving straight to `admitted`, a rejected artifact returning as admitted evidence, and any carry-forward after `task-closed` or `artifact-superseded`. A legal hold can preserve the trace in an audit store while keeping it outside future model prompts. Storage policy and prompt admission are separate controls.

This policy builds on established engineering practice. JSON Schema, a standard vocabulary for validating JSON records, and Pydantic, a Python data-validation library, can enforce the record's shape. Temporal, a durable workflow engine, records progress so a process can resume after failure. Those tools enforce shape and continuity, while the retention policy supplies the decision about which evidence deserves another model call.

Observability, the ability to reconstruct what the system did, needs the same precision. For Anthropic, retrieved-input share can be calculated as `cache_read_input_tokens / (input_tokens + cache_creation_input_tokens + cache_read_input_tokens)`. Another provider may use different fields and semantics, so each one needs a named mapping. I think the subtle art lives here: preserve enough evidence to reconstruct the decision, while sending only the evidence that can still change it.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Useful context engineering combines simple habits with an executable admission policy. Typed lifecycle events decide what can move forward, while provider-specific usage mappings show what that decision costs.</p></div>

## Test whether the policy actually works

A retention policy should earn deployment on paired work. Take 30 closed defects from one product domain and run each under two operationally defined versions. The growing-thread baseline carries the raw conversation and accumulated tool output through the task. The admission-policy version starts in a clean environment and carries only reviewed artifacts or evidence whose lifecycle state is `admitted`.

Pin the model version, prompt, tool set, retry cap, rate card, and test environment. Alternate run order and declare task classes before the benchmark, so an easy category cannot hide a failure elsewhere. The result is 60 outputs, one from each version for every defect.

Use two blinded reviewers, who cannot see which policy produced each output, and one fixed set of acceptance rules. At four minutes per output, each reviewer spends four hours scoring all 60 outputs, for eight combined reviewer-hours. Add a declared allowance of two combined hours for calibration and adjudication, the process for resolving reviewer disagreement. If the loaded reviewer rate, meaning salary and employment overhead expressed per hour, is `R`, the planned human cost is `10R` before model and trace costs. Both reviewers must accept an output; a split goes to adjudication and remains rejected until resolved.

For each bootstrap resample of the 30 paired defects, recompute aggregate cost per accepted result for both versions and the percentage change between them. A bootstrap interval estimates uncertainty by repeatedly resampling the observed pairs. Adopt the admission-policy version only when its observed cost per accepted result is at least 10 percent lower and the 95 percent bootstrap confidence interval for the paired percentage reduction excludes zero. Keep the guardrails separate: accepted count cannot fall, median review time can rise by no more than 5 percent, and no predeclared task class can lose acceptance.

I think a policy has earned deployment only after the evidence package can reproduce that decision. Preserve a redacted JSONL trace, which is one JSON record per line, alongside the provider field map, model and rate-card versions, collection date, calculation notebook, and replay harness. The public $7,470 and 95.2 percent observations currently lack that complete package. Their role is to motivate the test, while the local benchmark supplies evidence strong enough to govern.

Rollout should remain small and reversible. A named platform owner maintains the default policy and dashboard. Domain engineers learn the retention classes during onboarding, then review exceptions weekly. A failed task class returns for redesign while successful classes continue. Procurement checks regional processing, supplier terms for trace retention, usage-field changes, and cache-price changes before expansion. This routine makes local workarounds visible and keeps savings from shifting cost into privacy, storage, or coordination.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Compare raw-thread carry-forward with reviewed-artifact admission on paired defects, budget ten reviewer-hours, and predeclare the cost, uncertainty, acceptance, and review-time bounds. Deployment follows reproducible evidence rather than a dramatic token ratio.</p></div>

## Cost per accepted result

My take: the durable unit is cost per accepted result. An accepted result is an output that clears the fixed technical check and human review, such as a patch that passes continuous integration and receives approval. Calculate the unit as `(model spend + loaded review cost + incremental trace and platform cost) / accepted outputs`. Zero accepted outputs fails the policy automatically.

This denominator changes the optimization target because a smaller prompt can lose when it creates more retries, and a cheaper model can lose when it transfers work to reviewers. A compliance rule that requires longer trace retention can also raise operating cost even when token spend falls. The metric catches each case because every saving has to survive the acceptance boundary.

A minimal monthly dashboard row can stay compact: `domain | policy version | model spend | reviewer hours | trace cost | accepted/attempted | cost per accepted result | exceptions`. FinOps, the operating discipline for managing cloud spending, owns the monthly number with the platform team. The domain lead owns the rubric, while Finance supplies the loaded labor rate. Procurement tracks rate-card changes, usage caps, regional processing terms, and provider field definitions.

For a board or budget review, the boundary fits in one sentence: the $7,470 figure is a subscriber-list-price signal, while enterprise exposure comes from the organization's own rate card, usage caps, contract terms, and cost per accepted result. That sentence keeps the shock in proportion without dismissing the behavior it exposed.

Context hygiene also has a failure envelope. One-shot research, difficult reasoning tasks, and broad codebase migrations may need a large body of evidence. Audit rules may require trace retention. In those cases the admitted context can stay large, provided the accepted-result economics justify it and retained audit material stays out of live prompts unless the task needs it.
