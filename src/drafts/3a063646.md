On August 1, 2026, [Om Patel posted](https://x.com/om_patel5/status/2083401185172541449) his July dashboard from [Claude Code](https://code.claude.com/docs/en/costs), Anthropic's coding agent. His $200 Max subscription had carried 6.16 billion tokens. At API list prices, the dashboard valued the same traffic at $7,470.35: 37.4 times the fee.

The screen showed neither an invoice nor Anthropic's compute expense. It translated Patel's activity into retail API prices. Even so, waving it away as price-sheet theater misses the practical lesson. Flat pricing made an expensive usage pattern feel free, removing the incentive to notice what the agent kept resending.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>The subscription absorbed the meter; it did not teach the user to reduce the traffic.</p></div>

## Flat pricing teaches the wrong lesson

Most retail value sat outside model output: cache reads and writes made up 86.2% of the dashboard total. [Prompt caching](https://docs.anthropic.com/en/docs/about-claude/pricing) recognizes an unchanged opening and charges a lower rate, although the instructions, history, tools, files, and results remain in the request.

One day instrumented by [Nate B. Jones](https://www.youtube.com/watch?v=Y8vAQ1FgNbM) showed it: 3.59 billion of 3.77 billion tokens across 143 threads were reused input, almost 96%. Jones sells a context framework, so this is one workspace, not an average. Production evidence shows this. In 2025, the team behind production [AI agent Manus](https://manus.im/blog/Context-Engineering-for-AI-Agents-Lessons-from-Building-Manus) reported about 100 input tokens for every output token.

The habit forms quietly. One useful exchange leaves material behind; the next carries it again. Without pruning, yesterday's clues and dead ends become today's default input.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Reused input is discounted, not removed; flat pricing hides traffic an engineering team should learn to manage now.</p></div>

## Context is part of the product

Long context can weaken the work. The 2024 peer-reviewed study [Lost in the Middle](https://aclanthology.org/2024.tacl-1.9/) found models retrieved relevant information less reliably when it sat midway through a long input. More included evidence can still make the important evidence harder to use.

Context hygiene is an admission rule for the working set. Open a thread when the job changes. Preserve decisions and verified artifacts; leave behind the discussion that created them. Add files and tools when the next step needs them. Keep reusable instructions unchanged for cache discounts. Automatic summaries help, but the tool should not make every retention decision.

Efficiency does not mean the shortest prompt. Open-ended work can need broad evidence. The discipline is excluding material more likely to raise cost and distraction than improve the decision.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Context should preserve useful evidence, not every step taken to find it.</p></div>

## Spend the subsidy on an experiment

For one recurring task, define acceptance first: tests pass, reviewer accepts, no critical errors. Compare an accumulated thread with a curated one containing only the brief, relevant files, and decisions. Repeat both versions on comparable tasks, switch their running order, and log input tokens, cache reads, output tokens, retries, latency, and review time.

Divide each variant's total trial cost by its accepted outputs. That is cost per accepted result. Low token spend is false economy when retries multiply.
