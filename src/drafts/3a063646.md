On August 1, 2026, AI practitioner Om Patel posted a screenshot from Claude Code, Anthropic’s coding agent. He had paid $200 for Claude Max. The screen showed 6.16 billion processed tokens and $7,470.35 at standard API list prices: 37.4 times his subscription.

That figure was not Patel’s invoice, and it was not Anthropic’s compute cost. It was a translation of metered activity into retail API prices. Yet the gap exposes something a subscription makes easy to ignore: an agent can move huge volumes of text while the price reveals almost nothing about efficiency.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>The subscription hid the marginal price, not the work.</p></div>

## Where the traffic comes from

A coding agent reconstructs each request from system instructions, conversation history, tool definitions, and tool results. As the thread grows, that inherited prefix can outweigh the new instruction. Prompt caching lets a provider reuse computation for an identical prefix; Anthropic prices cache reads at one-tenth of ordinary input. A cache read is cheaper, but it is still metered traffic. Cache writes also cost money.

Patel’s screen makes the pattern visible. Fresh input accounted for $14.14. Cache reads and writes accounted for $6,440.24, or 86.2 percent of the displayed total. In a one-day measurement, practitioner Nate B. Jones tracked 143 coding threads and found 3.59 billion of 3.77 billion tokens were reused input, almost 96 percent. That is one workspace, not an industry average.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>In agentic coding, yesterday’s context can dominate today’s request.</p></div>

## Context hygiene is selective memory

The lesson is not “delete context.” Blind pruning can remove a constraint, trigger a wrong answer, and add an expensive retry. Context hygiene is the deliberate control of what enters an agent’s working state, what survives a milestone, and what gets retrieved only when needed.

For a coding agent, that means opening a new thread for unrelated work; replacing a long debate with the accepted decision and current artifact; retrieving relevant files instead of attaching a repository; limiting noisy tool output; and keeping stable instructions at the front so caching can work. Automatic compaction helps near a context limit, but it may discard a detail your acceptance test still needs later.

This is a quality practice before it is a cost practice. Long inputs can bury the decisive fact, and missing facts create retries. The useful target is the smallest sufficient context, not the smallest possible prompt.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Keep decisions and evidence; stop carrying the whole meeting.</p></div>

## Measure the accepted result

Run a matched-task trial. Give one engineer ownership for one week. Hold the model, task cohort, and acceptance criteria constant; compare current context policy with a disciplined policy. Record fresh input, cache writes, cache reads, output, retries, latency, review time, and accepted outcomes.

Cost per accepted result is total cost divided by outputs that pass. Unlike raw token cost, it keeps quality inside the equation.

Subscriptions give teams time to learn without feeling every token. Use it before the meter changes.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Optimize accepted results before the meter changes.</p></div>
