In July 2026, Claude Code power user [Om Patel](https://x.com/om_patel5/status/2083401185172541449) posted an instrumented usage report. Claude Code is Anthropic’s command-line coding agent, and Patel was using its $200 Max subscription. His report showed 6.16 billion tokens, the small units of text models process and providers bill, across 36,881 responses.

At Anthropic’s public application programming interface, or API, rates, the same recorded usage would have carried a list-price charge of $7,470.35. That is 37.4 times the subscription fee. The flat rate protected Patel from that bill while removing the price signal that would have exposed how much old material the agent kept sending back to the model.

I think that missing signal matters more than the headline discount. Subscriptions make coding agents affordable, yet they can postpone the skill teams will need when usage moves onto an API, plan limits tighten, or finance asks what each useful result costs.

## The bill behind the flat rate

The $7,470 figure answers one practical question: what would this workload have been billed at public API rates? It does not reveal Anthropic’s internal compute cost. API rates are retail prices, and the Max plan has rolling session and weekly limits. This is genuine customer price exposure under direct billing, not proof that Anthropic lost $7,270 on one subscriber.

The composition of the bill is more useful than its size. Patel’s report attributed 48.1% of the total to cache reads and 38.0% to cache writes; generated output represented 13.6%. A cache read reuses stored input at a reduced rate, while a cache write stores new input for later use. Caching makes repetition cheaper, but not free.

That repetition comes from context: the instructions, conversation, files, tool descriptions, and results sent to the model on each turn. As a coding thread grows, the newest request becomes a small part of an expanding payload. Patel’s workload consumed 186 tokens for every token it generated.

The precise ratio varies. AI practitioner [Nate B. Jones](https://www.youtube.com/watch?v=Y8vAQ1FgNbM) instrumented one working day and found that 3.59 billion of 3.77 billion tokens were reused input, almost 96%, across 143 threads. Jones sells a context-management framework, so this remains a disclosed single-workspace observation. Separately, a [2025 production account from Manus](https://manus.im/blog/Context-Engineering-for-AI-Agents-Lessons-from-Building-Manus) reported an average input-to-output ratio near 100:1 for its AI agent.

More context can also reduce quality. *Lost in the Middle*, a [peer-reviewed 2024 study](https://arxiv.org/abs/2307.03172) involving Stanford University and the University of California, Berkeley, found that language models often perform worse when relevant information sits inside a long prompt rather than near its beginning or end. Unnecessary context therefore increases billed input while making retrieval harder for the model.

## Context engineering starts with subtraction

Context engineering means deliberately choosing what the model receives, keeps, and drops. Claude Code already uses prompt caching and automatic compaction, which summarizes a conversation as it approaches the context limit. Those defaults help, but compaction is a lossy decision made by the tool on its schedule. Anthropic’s [cost guidance](https://code.claude.com/docs/en/costs) still tells users to clear context between unrelated tasks and match the model to the job.

Start at the task boundary. Open a clean thread when the objective changes, then carry forward a short state record with the decision, constraints, current files, and relevant tests. Retrieve only what the next step needs, remove unused tool descriptions, keep stable instructions at the front for cache reuse, and cap outputs that do not need to be long.

This is curation, not automatic deletion. Broad context remains necessary for some one-shot analyses and difficult reasoning tasks. The practical test is whether a smaller context still produces an accepted result with fewer retries.

<div class="chapter-tldr">
<span class="chapter-tldr__label">In short</span>
<p>Clean task boundaries, concise state records, selective retrieval, and stable instructions reduce repeated input without discarding necessary information.</p>
</div>

## Price the accepted result

Raw token cost cannot show whether an agent was economical. The useful measure is cost per accepted result: all metered cost across attempts divided by the outputs that pass the team’s tests or review. A cheap model needing repeated corrections may cost more than a stronger model that succeeds once, while a premium model may add nothing on a routine edit.

Instrument each task with fresh input, cache reads, cache writes, output, retries, and acceptance. Compare task types and context policies instead of celebrating a low subscription fee or a high token count. Even on a flat plan, teams can estimate their API-equivalent exposure and assign someone to review it.

The $200 subscription may still be an exceptional deal. Its weakness is what it does not teach. Teams that learn context engineering while access is flat-priced will be ready when the meter becomes direct, because they will already know what one accepted result should require.

<div class="chapter-tldr">
<span class="chapter-tldr__label">In short</span>
<p>Govern agent economics by cost per accepted result, with context use and retries visible, so a pricing change does not become an efficiency crisis.</p>
