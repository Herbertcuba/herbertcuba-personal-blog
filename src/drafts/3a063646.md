On August 1, 2026, AI practitioner [Om Patel shared](https://x.com/om_patel5/status/2083401185172541449) a third-party dashboard for an unnamed user's July activity in Claude Code, the coding assistant from Anthropic, the AI company behind Claude. It showed 36,881 responses and 6.16 billion tokens, the units of text that language models process. The user reportedly paid $200 for a Max subscription; the dashboard reconstructed the same traffic at $7,470.35 using posted API prices.

The larger number is a counterfactual, not an invoice or Anthropic's undisclosed cost. It is API list-price exposure: what the recorded traffic would have cost through the pay-per-token interface used to call the models directly. If the dashboard is accurate, removing the subscription would have made that month 37.4 times as expensive.

I think the deeper risk is the lesson the flat price withholds. When the next request has no visible price, teams have little reason to inspect what they keep sending. Context hygiene, the discipline of controlling which history enters the next request, becomes urgent only when plan limits tighten or a workflow moves to direct billing.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>The subscription hid a large API-price counterfactual and, with it, the feedback that would have encouraged efficient context use.</p></div>

## The same context keeps coming back

An agent needs context: its instructions, conversation, code, tool definitions and tool results. Yet useful context accumulates beside stale plans, superseded errors and verbose command output. [Anthropic's Claude Code documentation](https://code.claude.com/docs/en/costs) says the tool sends the full conversation with every request and can send additional requests containing batches of tool results. A longer thread therefore makes later turns carry more earlier material.

Prompt caching lets a provider reuse computation for an unchanged opening block, making repeated input cheaper and faster to process. It does not make that input free. In Patel's dashboard, cache reads and writes accounted for 86.2% of the reconstructed price, while generated output accounted for 13.6%. Those percentages describe one dashboard, not Anthropic's cost base or an industry average.

A second observation shows the same mechanism at a different scale. [Nate B. Jones](https://www.youtube.com/watch?v=Y8vAQ1FgNbM), a practitioner who sells a related context-management framework, reported that his tracker labeled 3.59 billion of 3.77 billion tokens as reused input during one day across 143 threads in Codex, OpenAI's coding-agent environment. That is almost 96%, but the label can include stable instructions, tool definitions and prior conversation. It does not mean 96% was useless.

More context can also reduce quality. The 2024 peer-reviewed paper [*Lost in the Middle*](https://arxiv.org/abs/2307.03172), written by researchers from Stanford University, UC Berkeley and Samaya AI, found that language models often performed worse when relevant information sat inside a long input rather than near its beginning or end. Carrying everything can make the right evidence harder to use.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Cached history is discounted rather than free, and indiscriminate accumulation can raise cost while making relevant evidence harder for the model to use.</p></div>

## Put context efficiency under test

Context engineering means deciding what information the model receives, in what form and at what time. It should be tested as a quality control, not run as a cleanup campaign. Start with one recurring workflow and make the comparison reversible.

| Control field | Trial decision |
| --- | --- |
| Owner | A platform engineer runs the trial; the workflow owner decides whether output is accepted; Finance verifies cost allocation. |
| Baseline | Use current agent defaults for 20 comparable tasks or two weeks, with the same model, repository, tools and tests. |
| Variant | Start a clean thread per task, keep stable instructions first, carry forward current decisions and artifacts, retrieve old logs only when needed, and cap verbose tool output. |
| Limits | Set latency and spend boundaries. Stop and roll back if acceptance falls or omitted context causes a material defect. |
| Evidence | Record input, output and cached tokens, policy version, review time and rework. Keep full logs outside the prompt under existing access, retention and data-residency rules. |
| Decision | Review before plan renewal or API migration. Scale only if total cost falls while acceptance quality holds. |

Automatic compaction, which summarizes a thread as it approaches its context limit, is a useful default. It is also a lossy choice made on the tool's schedule. Aggressive pruning can erase the failed attempt that explains a constraint, so the policy should preserve current artifacts and decision evidence while allowing the complete trace to be retrieved. Efficiency without that safeguard is just a cheaper way to repeat mistakes.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>A bounded trial can reveal whether deliberate context selection saves money without removing evidence that the workflow still needs.</p></div>

## Make accepted work the denominator

An accepted result is an output that passes the workflow's existing tests and human review without being reopened. Cost per accepted result adds direct model charges, or the documented share of a flat subscription assigned to the workflow, to review labour and retry or rework cost, then divides that total by accepted outputs. A plan dedicated to the workflow uses its full charge; a shared plan needs a consistent usage-based allocation.

Track API list-price exposure beside cash spend, but never add the two together. Cash spend describes today's bill. The counterfactual exposure shows what could surface when a plan changes, reaches its limits or moves behind an API. At the trial's review date, compare the baseline and variant on acceptance rate, latency and total cost, then keep the cheaper policy only if quality remains inside the agreed boundary.

The $200 subscription made heavy use affordable, but it also muted the signal that teaches efficiency. Learning the subtle work of context engineering now reduces exposure to later pricing changes. Some cached context is essential. Teams should still know which context earns another trip before a provider, contract renewal or plan limit sets the price.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Cost per accepted result turns context hygiene into a quality-constrained operating decision that remains useful when pricing changes.</p></div>
