In July 2026, Claude user [Om Patel posted a usage report](https://x.com/om_patel5/status/2083401185172541449) from Claude Code, the command-line coding agent made by the AI company Anthropic. His Claude Max subscription cost $200. That month’s 6.16 billion tokens, the units of text a language model processes, were priced at $7,470.35 through Anthropic’s application programming interface, or API. The workload was worth 37.4 times his fee at published rates.

That is not Anthropic’s real expense. API prices are retail, the company’s compute cost is undisclosed, and the Max plan has rolling five-hour and weekly limits. But metered through the API, the same token pattern would have produced a user bill of roughly $7,470. The subscription erased that signal.

The missing signal stops us learning efficiency. Context engineering, the deliberate choice of what an AI model sees on each turn, looks like a subtle technical craft today. I think it becomes financial discipline as more work moves to direct token billing.

## The expensive part is the conversation you keep carrying

Patel’s breakdown shows where the money went. Cache reads cost $3,595.52 and cache writes another $2,841.89, together making up 86.2% of the total. A cache lets the provider reuse earlier prompt processing at a discount; reading or storing that material is cheaper than starting over, but it is not free. Fresh input cost $14.14, while model output cost $1,015.97.

A separate case exposes the same mechanism. AI workflow practitioner [Nate B. Jones measured one day](https://www.youtube.com/watch?v=Y8vAQ1FgNbM) in Codex, the coding-agent workspace from AI company OpenAI. Reused input represented 3.59 billion of 3.77 billion tokens: 95.2%, or almost 96%. It is one self-measured workspace, not an industry average, and Jones sells a related workflow method. Yet [Manus, a general-purpose AI agent service](https://manus.im/blog/Context-Engineering-for-AI-Agents-Lessons-from-Building-Manus), also reports an input-to-output ratio of about 100:1 in production.

The cause is structural. Each turn may include standing instructions, tool definitions, files, tool results, and conversation history again. Caching cuts the price of this repetition, while the growing thread still makes the model process old material.

Cost is only half the problem. [“Lost in the Middle,” a 2023 study by researchers at Stanford University and the University of California, Berkeley, published in a peer-reviewed journal in 2024](https://arxiv.org/abs/2307.03172), found that language models often performed worse when relevant information sat in the middle of a long input. Preserving everything can make useful evidence harder to use.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Old input dominated both measured cases. Caching discounts that reuse, but oversized context still costs money and can bury relevant evidence.</p></div>

## A clean thread is an engineering choice

Claude Code already uses prompt caching and auto-compaction, which summarizes a conversation near the model’s input limit. Those defaults help, but a generated summary cannot know which constraint matters most to the engineer.

When the objective changes, start a new thread with a short brief containing requirements, decisions, relevant files, and unresolved failures. Search the repository before asking the model to search blindly. Keep stable instructions at the front for efficient caching, limit unnecessary output, and choose the least expensive model that still passes the required tests or review.

Some tasks, including cross-system migrations and incident investigations, genuinely need broad evidence. Context hygiene means increasing the share of relevant information, not making every prompt small.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Carry requirements, decisions, evidence, and failures into a clean thread instead of preserving the transcript. The engineer still decides what the next turn needs.</p></div>

The mapping to an AI coding agent is narrow: begin the next attempt with verified findings and a clear objective rather than replaying every exchange that produced them. Preserve the learning, not the whole conversation.

## Count accepted results, not cheap tokens

Direct API billing makes waste visible because every context decision has a price. Subscription users can recreate that signal by recording fresh input, cache reads, cache writes, output, and cost for each task. One named engineering owner should connect those numbers to whether the result was accepted.

Cost per accepted result means total model spend divided by outputs that pass the relevant bar. For code, that could mean tests pass and a reviewer approves the patch. The measure prevents teams from celebrating low token use while engineers discard weak answers and try again.

Generous pricing can tighten. Technology critic [Ed Zitron reported](https://www.wheresyoured.at/the-more-you-buy-the-more-you-lose/) that heavy users of GitHub Copilot, the coding assistant sold by Microsoft-owned developer platform GitHub, consumed more than 25 times their fee before a move toward token billing triggered backlash. Today’s plans may follow a different path, but waiting teaches us nothing.

The durable skill is deciding what the model needs, what the work has settled, and what should be left behind. A subscription can absorb the invoice for a while. It cannot tell us whether that context helped produce work we could accept.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Track token use by task, assign an owner, and divide spend by results that pass tests or review. This prepares teams for stricter billing without rewarding unusable output.</p></div>
