A July 2026 report from `claude-cost`, a local usage-reporting tool for Claude Code, put a $200 subscription beside $7,470.35 of traffic valued at public application programming interface rates. Claude Code is the terminal coding agent made by AI company Anthropic, and an application programming interface, or API, is the metered interface software uses to send model requests. The ratio was 37.4 to one, large enough to look like a bill.

The comparison appeared in [an X post from developer Om Patel](https://x.com/om_patel5/status/2083401185172541449) on 1 August 2026. The screenshot showed 6,156,261,087 tokens across 36,881 responses. A token is a small unit of text processed by a language model. These figures are evidence of what the local tool reported, not independently audited provider logs.

[Claude Code’s cost guide](https://code.claude.com/docs/en/costs) says the software applies standard list rates to local token counts, so its estimate can differ from the customer charge. The subscriber was not billed $7,470.35. That number is a what-if total at retail API rates, and it cannot reveal Anthropic’s internal compute cost, which the public material does not disclose.

A second report supplies the mechanism that the retail-rate comparison cannot show. Coding-agent practitioner [Nate B. Jones](https://www.youtube.com/watch?v=Y8vAQ1FgNbM), who sells Ringer, his framework for coordinating multiple agents, said his tracker recorded 3.77 billion tokens across 143 Codex threads in one working day. Codex is the coding agent from OpenAI, a company that researches and deploys AI systems.

Jones classified 3.59 billion tokens as reused input, meaning previously sent text that appeared again in later requests. The rounded figures yield 95.2 percent, which he described as “almost 96%.” This is one self-instrumented workspace, not an industry benchmark. The cited recording reports the totals but does not include the raw trace needed to reproduce the collection.

I think the useful shock is the distance between the cash meter and the traffic meter. A flat seat can make an expanding request loop feel free while that loop repeatedly moves old instructions, files, tool results, and conversation back through the model. The engineering response is to manage context as state, observe it at the request boundary, and judge it by results the team accepts and uses.

## The expensive part keeps returning

A language model does not carry a private memory from one API call into the next. The client rebuilds what the model can see. Claude Code’s documentation says it sends the conversation with every request, and a tool use leads to another request containing the returned tool results. Here, that complete payload is the request envelope: current instructions, conversation, tool definitions, selected source material, tool output, and the newest message.

This design makes repetition structural. As a session continues, the envelope grows, while each additional tool step creates another occasion to send it. Old material can therefore cross the boundary many times, even when only the final question is new.

The July report uses two cache categories that need to be separated before reading the amounts. Prompt caching is a provider feature that reuses processing for an unchanged prefix, such as stable instructions at the beginning of a request. Cache creation writes input into a new entry; cache retrieval uses an existing entry again.

Cache retrieval accounted for $3,595.52 of the report’s public-list-price value. Cache creation accounted for another $2,844.72, while generated output was $1,015.97 and ordinary fresh input was $14.14. The two cache rows total $6,440.24, or 86.2 percent of the displayed $7,470.35.

That 86.2 percent describes all cache events, so it cannot be read as the share of input retrieved from an earlier request. Combining creation and retrieval reconciles the report’s categories, but a write does not qualify as reused input merely because it created cache state.

The cache-read row supports a narrower arithmetic check. Dividing $3,595.52 by 5.878 billion retrieved tokens gives about $0.61 per million. In [Anthropic’s public price table](https://docs.anthropic.com/en/docs/about-claude/pricing) available in August 2026, cache hits were listed at $0.50 per million tokens for Opus 5 and $1 per million for Fable 5, two Claude model tiers that account for most of the displayed model rows. The blended result falls between those rates. That consistency does not authenticate the unseen request logs, but it shows that the displayed row fits the published range.

Jones’s trace measures a different category. His reused-input figure describes traffic that returned to a separately instrumented Codex workspace, while the Claude report exposes provider cache events and their retail-rate estimate. Treating the two percentages as interchangeable would turn corroborating signals into false precision.

A production account offers another point of comparison. In a July 2025 engineering note, [the team behind Manus, a general-purpose AI agent](https://manus.im/blog/Context-Engineering-for-AI-Agents-Lessons-from-Building-Manus), reported an average input-to-output ratio around 100 to one. That ratio cannot verify Jones’s 95.2 percent or distinguish a cache write from a cache read. It supports only the narrower point that an agent may process far more text on input than it produces on output.

I think this is why a cheaper model can leave the central problem untouched. Model selection changes the price of processing. Request construction changes how much material enters the process, how often it returns, and whether decisive evidence remains easy to find.

The categories differ, yet each reveals how strongly agent traffic can tilt toward reading earlier material.</p></div>

## Give every context item an exit condition

Context hygiene means deciding what enters a model request, why it remains there, and when it leaves. Many agent systems use the transcript as both an audit record and active working state. The first job requires completeness; the second requires selection. Mixing them makes the easiest implementation, “send everything again,” look like the safest one.

My take is to treat admission as a state transition. A candidate item should identify its source, task, purpose, current version, and exit condition before it becomes active context. It should retire from the envelope when its task ends, its evidence is replaced, or its decision is accepted. Retirement removes the item from the next request, not from durable storage.

Consider an agent preparing a database migration that adds a uniqueness rule to stop duplicate payment records. The next decision may require the current schema, the migration policy, the relevant service code, the failing test, and the approved maintenance window. It does not automatically require two rejected index designs, an unrelated dependency log, or every search result that led to the relevant file. If a rejected design exposed a real constraint, carry the constraint and a reference to the full trace rather than the entire debate.

This gives the system two honest records. The durable task log preserves prompts, tool returns, failed attempts, decisions, and source trails for recovery or audit. The active envelope holds the immediate goal, constraints still in force, admitted source material, and the newest working artifact. The archive remains complete while attention stays deliberate.

Automatic compaction helps when a long session approaches a model’s context limit. Claude Code summarizes older conversation so work can continue. Yet a late summary is a recovery mechanism rather than a substitute for application state. The summarizer may preserve a vivid dead end and compress the test that actually defined acceptance unless the client marks those roles explicitly.

Smaller envelopes still need a quality guard. [Lost in the Middle](https://arxiv.org/abs/2307.03172), a study first released in 2023 by Nelson Liu and colleagues and later published in the peer-reviewed journal Transactions of the Association for Computational Linguistics, tested how the position of relevant evidence affects long-prompt performance. Models often did better when that evidence appeared near the beginning or end and worse when it sat in the middle, including models designed to accept long contexts. The study was not a coding-agent cost experiment, but it shows why available context capacity does not guarantee usable attention.

I think the practical rule is purpose rather than a universal token ceiling. A broad investigation may need many sources, while a narrow fix may need one failing test and a small code region. Keep instructions that rarely change and only the required tool definitions at the front, where identical prefixes can benefit from prompt caching.

Changing evidence belongs later in the envelope. Remove duplicates, cap output to what the next step can use, and keep references to retired material so the full record remains available without remaining active.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Context hygiene separates a complete durable trace from a selective active envelope. Each item needs a source, purpose, version, and exit condition, so completed debates can leave the request without disappearing from the record.</p></div>

## Put the meter at the request boundary

A context policy becomes enforceable where the application sends a request to the provider. At that boundary, write one telemetry record that begins with identity: task and request identifiers, policy version, provider, and model revision. The policy version connects a change in request construction to the outcome that followed.

Group the remaining fields by the decision they support. Traffic includes every input counter, generated tokens, envelope size, and latency. Money includes the actual cash charge and any dated public-list estimate. Outcome includes review minutes and the eventual acceptance event. This grouping keeps a long record readable without dropping the fields needed to connect policy, traffic, cost, and result.

The input categories must follow the provider’s documented meanings. Anthropic’s response schema, the structured fields returned with each call, separates ordinary `input_tokens`, `cache_creation_input_tokens`, `cache_read_input_tokens`, and `output_tokens`. Calculate cache-read share by dividing `cache_read_input_tokens` by total input, where total input is the sum of the three input fields.

Cache creation belongs in that denominator because those tokens were processed to make a new entry rather than retrieved from an existing one. The numerator contains only input fetched from an existing cache entry. Call the result cache-read share, not universal reuse.

Another provider may expose different fields or no equivalent field, so the adapter, the code that maps vendor fields into the internal record, needs a provider name, schema version, and tested mapping. If a provider changes a field’s meaning, create a new metric version rather than silently rewriting history.

The same record must keep traffic separate from money. Cache-read share describes the composition of input tokens. Actual cash cost comes from the contracted bill or a subscription allocation chosen before the analysis. Public-list-price value applies a dated retail schedule to the traffic as a comparison. A high cache-read share can coexist with low spend because retrieval is discounted, and repeated policy or source material can be essential rather than wasteful.

The July report makes the boundary concrete: $200 belongs in the cash view, $7,470.35 in the public-list-price view, and the cache fields in the traffic view. Moving one number into another category produces a dramatic dashboard and a bad decision.

I think the useful alert is a change against a task-class baseline, not a universal red line. A task class is a group of jobs evaluated with the same acceptance rules. A repository-wide migration and a one-file correction have different context needs, so compare each class with its own recent distribution and inspect changes in retrieved share, envelope size, latency, retries, and review time together.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Instrument every request with a versioned, provider-specific record. Cache-read share describes traffic, the contract describes cash, and a dated public price schedule describes exposure; none of the three can stand in for the others.</p></div>

## Let accepted work settle the price

Token totals are operational signals, but they are a poor final denominator. Count an output as an accepted result only after its declared checks pass, any required human approves it, and the organization puts it into use. A patch with failing tests, an answer rejected by a reviewer, and an abandoned retry remain costs in the numerator without becoming successes in the denominator.

The metric is the full cost per accepted result. Add actual model charges, or a predeclared share of a flat subscription, to loaded review cost and relevant platform expense, then divide by accepted outputs. Loaded review cost values reviewer minutes at a fully burdened labor rate that includes compensation and employer costs. Keep the $7,470.35 public-list estimate outside this calculation because it was never charged to the plan.

Test a proposed context policy on representative completed work before adopting it. Pair each selected task with two isolated runs, one using the current envelope policy and one using the proposed policy. Hold the model version, tools, retry limit, acceptance checks, and reviewer guidance constant. Randomize run order, hide the condition from reviewers where possible, and set acceptable limits for quality, latency, and review time before seeing the comparison.

Ask which policy will win on a given task class. If the honest answer is “I don’t know,” run the replay before adopting either policy. Fewer tokens are a loss when they create more retries, slower reviews, or lower acceptance. More context is justified when it improves the result enough to pay for itself. For one-shot work where a broad body of evidence is the task, aggressive removal may offer little or cause harm.

The sources cited here do not provide a public controlled benchmark that compares context hygiene with model substitution across every workload. The claim should therefore be tested by task class rather than promoted as a law.

I think ownership belongs with the platform team that controls the agent boundary and can join requests to outcomes. Finance can supply the loaded labor rate, while Procurement can track contract prices, retention terms, and provider schema changes. A monthly review should ask which policy version reduced full cost without crossing the declared quality limits, not which team sent the fewest tokens.

The $200 plan muted the cash signal, and the $7,470.35 public-list meter made hidden traffic visible. Jones’s 95.2 percent trace across 143 Codex threads in one working day gives engineers a reason to inspect their own loops, not a percentage to copy into a forecast. Context earns its place only when it helps create an output the organization accepts and uses.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Count only outputs that clear declared checks and enter use, then divide actual model, reviewer, and platform expense by that total. A context policy succeeds when this outcome cost falls without breaking the agreed quality, latency, or review limits. Context earns its place through accepted work.</p></div>
