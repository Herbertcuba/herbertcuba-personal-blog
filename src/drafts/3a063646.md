A $200 Claude subscription just generated $7,470 worth of API calls. A developer named Om Patel ran his own July usage through a cost tool and [posted the screenshot on X](https://x.com/om_patel5/status/2083401185172541449). One month, one user, 6.16 billion tokens. Eighty-six percent of the bill was cache operations: the agent re-reading context it had already seen.

The mechanism behind that number showed up in a second dataset. In one day of agentic coding, an engineer named Nate Jones logged 3.77 billion tokens across 143 threads, and [96% of that traffic was text his setup had already sent](https://www.youtube.com/watch?v=Y8vAQ1FgNbM). Four percent was new information.

## What $7,470 of usage looks like

Patel ran a tool called claude-cost over his July 2026 usage and posted the output: 36,881 responses in one month.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>86 percent of the bill is cache operations. Actual generation is only 13.6 percent. The usage is real, and the math checks against Anthropic's public price sheet.</p></div>

Cache reads: $3,596, nearly half the total. Cache writes: $2,842. Actual output tokens: $1,016, only 13.6 percent. 86 percent of the money is cache operations, the agent re-reading context it already saw.

I think the shape of the bill says more than the size of it. An agentic coding tool re-reads your files, your history, and its own instructions thousands of times a day, so the context bill dwarfs the generation bill. Patel says CLI tools burn somewhere between 500 and 1,000 input tokens per output token, while a custom toolchain that feeds context directly runs closer to 1:1.5. Treat the 500 to 1,000 figure as his field observation of tools at their worst. His own month, with prompt caching doing its job, came in lower: 186 tokens consumed for every one generated.

Per model: Claude Fable 5 ate $2,794, Opus 4.8 took $2,330, Opus 5 another $2,141.

I tried to poke holes in the screenshot, so I checked the math against [Anthropic's published prices](https://docs.anthropic.com/en/docs/about-claude/pricing). Cache reads run $0.50 per million tokens on Opus and $1 on Fable 5. The screenshot's reads span both models, so the blended rate lands around $0.61 per million, and 5.88 billion cached tokens at that blend sit right on the $3,596 line item. The arithmetic holds. On the last day of July alone, $88.85.

## Three calculations

The 37x is one user, one month. Extend the timeline and the shape changes.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>37x this month. About $21,800 of implied discount over a quarter. And a $43.6 billion ceiling case for a million maxed-out subscribers, which collapses to a small fraction of that the moment you assume people behave like people.</p></div>

One. This month, the subsidy is 37x at list price. Two hundred dollars paid, $7,470 of metered value consumed.

Two. Run that for a quarter. Three months of Patel: $600 paid, roughly $22,410 in API value consumed. Call it $21,810 in discount. For a solo developer, that is a salary. I think this second number is the one that should worry Anthropic, because it repeats every quarter for every heavy user.

Three. Scale it. A million Max subscribers over six months: $1.2 billion in revenue against $44.8 billion in list-price value, a $43.6 billion gap.

That number is fiction, and I want to be precise about why. Most users are light. Anthropic caps usage with rolling five-hour windows and weekly limits it can tighten at will. And list price overstates cost, because the API sticker is retail, set for enterprises building products on top of Claude. Patel himself says it: what serving him actually costs Anthropic in compute is far lower. How much lower, I don't know. Nobody outside the company does. Epoch AI's work on frontier labs suggests compute eats roughly two thirds of revenue, which would put the true cost of Patel's month in the low thousands. The real subsidy is much smaller than $7,470.

## Context is a consumable resource

That 96% comes from one design fact: a language model remembers nothing between requests.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Every turn resends the whole conversation, so threads get expensive in a curve, and stale context degrades answers on top of the cost. Treat context like memory in C: allocate, use, free.</p></div>

A token is the unit of text a model reads and writes, roughly three quarters of a word. The context window is everything the model can see at once, its working memory. And with no memory between requests, every turn works the same way: your agent framework takes the full conversation, the system prompt, the tool definitions, every message, every file the model opened, and sends it again with the new question stapled to the end.

Say I ask an agent to fix a checkout bug. The cart total ignores a discount code. Turn one sends the system prompt, the tool list, and the bug report. Turn two resends all of that, plus the model's first reply, plus the file it opened. By turn twenty, I am resending nineteen replies and a pile of file contents to ask one more question. The thread does not get expensive in a straight line. It gets expensive in a curve, because every new turn pays for every old turn.

I think about this the way C programmers think about memory. You allocate, you use, you free. Leak memory and the process bloats until it dies. Context works the same way. It is a consumable engineering resource with compounding cost, and it deserves the same rigor.

The stale part of a long thread deserves its own name, so here is one: context debt. Like technical debt, it charges interest. The interest comes due on every turn, in dollars. And it costs accuracy too. A [2023 study out of Stanford and Berkeley](https://arxiv.org/abs/2307.03172) found that models get measurably worse at using information buried in the middle of long contexts. A thread a few hundred thousand tokens deep is a liability twice: once on the invoice, once in the answer.

Any team that cannot state its reuse ratio will misprice its agent workloads, and badly. A team with no meter on it is taking the invoice's word for its own behavior.

## The practices that move the number

None of this needs new tooling. It is habits, plus one query against your logs.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Clean threads, carry the artifact, cap the output, pre-search yourself, smallest model that passes, stable prefix for the cache. Boring habits, real money.</p></div>

One caveat before the habits. Modern harnesses already compact long threads automatically. Claude Code, Cursor, and friends will summarize old turns when the window fills. That helps, and it is a lossy default: the harness decides what to forget, on the model's schedule, and you keep paying for whatever it decides to keep. Deliberate hygiene means you decide, before the request goes out.

Start a clean task when the job changes. The checkout bug is fixed, the thread is done. New job, new thread. In my experience, this one habit does more for the bill than any model downgrade I have tried, and it costs one click.

Carry the artifact, skip the argument. When a task ends, move forward the accepted result, the diff plus three lines on why. Leave the forty turns of debate behind. Some frameworks make this explicit. LangGraph is a library that wires agent steps together as a graph and threads a state object between the steps. That state is often a TypedDict, a Python dictionary where you declare the keys and their types up front. The StateGraph, the piece that decides which step runs next, passes that tidy state along and nothing else. The mess stays out by design.

Ask for exactly the length you need. "Reply with the twelve lines and nothing else." Output tokens cost money too, and a long answer gets resent on the next turn, so verbosity bills you twice.

Pre-search sources yourself. You already know the discount logic is in pricing.py. Send that file, or those twelve lines. Making the model search a haystack you can search in one second is pure waste.

Use the dumbest model that still clears the bar. A small model can classify and route. Escalate to the expensive one when the small one fails. Jones takes this further with a layer he calls Ringer, a paid framework that sits between the agent and the provider, intercepts every request, and enforces hard limits. You do not need to buy it to steal the idea. Put something between your agent and the API that is allowed to say no.

Then let the cache do its job. Prompt caching gives you the 0.1x price on repeated input, but only if the front of your request stays identical. Keep the system prompt and tool list stable, append new material at the end, and the reused part of every turn gets 90% cheaper on its own. Change one byte early in the request and the discount vanishes. Caching rewards hygiene. It cannot substitute for it.

The cost of getting here is low: one afternoon with your request logs, a team norm that a thread ends when the job ends, maybe a small proxy in front of the API once you want hard limits. No new platform or procurement cycle. The bar is attention, which is also why it stays undone.

If your agent logs the raw API responses, most providers already split fresh input from cached input in the usage block. With one JSON object per request in a log file, your reuse ratio is a few lines of jq, a command line tool for JSON:

```bash
jq -s 'map(.usage) |
  { fresh:  (map(.input_tokens) | add),
    cached: (map(.cache_read_input_tokens // 0) | add) } |
  .cached / (.fresh + .cached)' requests.jsonl
```

That is your reuse ratio, or at least a rough proxy for it. If the number comes back above 0.5, most of what you pay for is text you already sent. Jones's tracker suggests it will come back a lot higher. If you want the one-month version of the same test, run claude-cost or your vendor's usage export over your own account and read the cache line.

## Cost per accepted result

The industry quotes token prices the way airlines quote seat prices. It is the visible number, and rarely the decisive one.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>The KPI is cost per accepted result: total spend to land one change you actually merge. Context hygiene moves that number directly, and at org scale it becomes a budget line someone needs to own.</p></div>

My take: the KPI is cost per accepted result. How much did you spend, end to end, to produce one change you actually merged, one answer you actually used? Token price is an input to that number. Context hygiene is the multiplier.

It works in two directions at once. Less input per turn shrinks every request. And cleaner context raises the odds the answer is right the first time, because the model reasons over the twelve lines that matter instead of 2,000 lines of noise. Fewer retries and smaller envelopes mean cheaper accepted results.

Now scale it. Say 200 developers each push 50 million tokens a day through agent loops, a fraction of what Jones's setup does. That is 10 billion tokens a day. At his ratio, 9.6 billion of those are reused input. Even at cache-read prices, call it $0.30 per million tokens, that is close to $3,000 a day spent on text already sent. Roughly a quarter of a million dollars a quarter for one mid-size engineering org, or about $5,000 per seat per year on calendar days, closer to $3,700 if you count working days. Multiply that against your own headcount and you get a number a CFO will ask about. The teams that can answer it are the teams where someone owns the context budget. I think every org past a handful of seats needs a named owner for that number. In a governed setup the owner is the platform team, the same people who own the cloud bill and the slow query log, and the report lives where the cloud bill lives: the monthly FinOps review.

How do you get 200 developers to actually close their threads? The same way you get them to write tests. Make the norm a default. Set a thread limit in the harness config. Put the team's reuse ratio on the dashboard next to build time. People follow defaults, and the owner watches the number.

There is a second reason the owner earns their seat. A bounded, curated context makes every agent run reconstructable: what the model saw is what someone decided to show it. As AI regulation tightens, that record stops being optional.

## Who pays for cheap AI

A 37x discount does not vanish so much as move to somebody else's ledger.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>The consumer discount is likely funded by enterprise API margins, though Anthropic's margins are not public. Subscriptions work like unlimited mobile data, where light users cover the heavy ones. And the whole industry is burning investor money to lock you in first and figure out profitability later.</p></div>

My take: the gap between $200 and $7,470 is the business model. API prices carry enterprise margins, and those margins cross-subsidize the consumer plans. That is a hypothesis, and Anthropic's margins are not public. The price structure is consistent with it, and subscriptions are priced like unlimited mobile data: most people never touch their limits, and their fees cover the ones who do.

The land grab is funded. Anthropic's [run-rate went from $9 billion at the end of 2025 to $47 billion this May](https://simonwillison.net/2026/May/29/anthropic/), with $95 billion raised along the way. Ed Zitron's reporting shows the same pattern everywhere: hyperscalers sinking over $1.3 trillion into generative AI through 2026. Investor money goes in, locked-in users come out, and profitability stays a problem for a future quarter. If your company buys seats, there is a question worth taking to your next vendor review: what happens to the price when the land grab ends?

The image that fits is the burning oil derrick in There Will Be Blood: a fire you can meter is a fire you can budget, and Anthropic can show the meter on this one.

We have seen how it ends. [GitHub Copilot let power users burn more than 25 times their monthly subscription fee](https://www.wheresyoured.at/the-more-you-buy-the-more-you-lose/), then switched to token billing, and the user revolt was immediate. I think the meter comes for Claude Max too, eventually. Cheap AI was never cheap. Somebody else is paying, and the invoice is due later.

This is why context discipline beats model upgrades for cost. One honest limit on the claim: for one-shot tasks and frontier reasoning work where broad context is the whole point, hygiene buys little. The claim covers looping, multi-turn agent work, which is where the bills are.

I don't know where the floor is. I do know where the meter starts: one query against your logs, run tonight. I will be running it on mine.

This is the [orchestration thesis](/posts/welcome-to-the-orchestration-era/) at the smallest scale there is. Decide what enters the room. Carry forward only what earned its place. The cheapest token is the one you never send.
