AI coding practitioner [Om Patel](https://x.com/om_patel5/status/2083401185172541449) paid $200 for Claude Max, a fixed-price plan from the AI company Anthropic, in July 2026. He then ran 6.16 billion tokens through Claude Code, Anthropic's command-line coding tool. At the public prices for its pay-as-you-go application programming interface, or API, the same usage came to $7,470.35. That is 37.4 times the subscription price.

The screenshot does not show that Anthropic spent $7,470 serving him. API prices are retail prices, not a receipt for compute, and the company does not disclose that internal cost. Still, Patel would have faced the $7,470 bill if he had bought the same volume directly through the API. The subscription removed that price signal, and with it an incentive to understand where the tokens went.

That is the deeper problem. Fixed-price access lets us develop expensive habits before we learn the subtle craft that corrects them: deciding what an AI tool should remember, what it should retrieve, and what it should leave behind.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>The $7,470 figure is an API list-price equivalent, not Anthropic's compute cost. Its importance is that a $200 subscription concealed the economics of one user's workflow.</p></div>

## The bill is mostly old text

A token is a small unit of text that a language model reads or writes. Patel's usage report counted 33 million output tokens, but 6.16 billion tokens in total: roughly 186 consumed for every one generated. The model's answers were a small part of the traffic.

The cost breakdown makes the mechanism visible. Cache reads accounted for $3,595.52 and cache writes for $2,841.89, together representing 86.2% of the list-price bill. A prompt cache stores repeated input so the provider can process it at a discount. Discounted does not mean free, especially when a coding tool keeps sending the same instructions, file contents, tool descriptions, and conversation history on every turn.

This is one account, so it cannot establish an industry average. Yet the pattern appears elsewhere. AI workflow practitioner [Nate B. Jones](https://www.youtube.com/watch?v=Y8vAQ1FgNbM), who sells a context-management framework, instrumented one day in OpenAI's Codex coding-agent workspace. Of 3.77 billion tokens across 143 threads, 3.59 billion were reused input: almost 96%. In a 2025 production account, the team behind [Manus](https://manus.im/blog/Context-Engineering-for-AI-Agents-Lessons-from-Building-Manus), a general-purpose AI agent, reported an average input-to-output ratio near 100:1.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Repeated input, rather than newly generated code, dominated these measured workflows. Caching lowers its unit price but can still leave enormous volumes moving through the system.</p></div>

## More context can produce less useful work

Agentic coding tools do more than answer a prompt. They inspect repositories, call tools, edit files, run tests, and use the results in later steps. Their harness, the software coordinating that loop, rebuilds the model's context for each call. Context means everything available to the model at that moment, including instructions, history, files, and tool output.

Long threads therefore accumulate context whether or not every old detail remains useful. Automatic compaction helps by summarizing a conversation near its limit, but a summary is a lossy decision about what to forget. Anthropic's own [Claude Code guidance](https://code.claude.com/docs/en/costs) still tells users to clear unrelated tasks and match the model to the job.

The penalty is not limited to cost. “Lost in the Middle,” a [2023 study later published in the peer-reviewed journal *Transactions of the Association for Computational Linguistics*](https://arxiv.org/abs/2307.03172), tested how language models use long inputs. Researchers affiliated with Stanford University and the University of California, Berkeley found that performance often fell when relevant information appeared in the middle. More available text can make the right evidence harder for the model to use.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Context is a finite working resource. As threads grow, they can cost more while making important instructions and evidence harder for the model to recover.</p></div>

The mapping to AI coding is selective continuity. A new thread should retain the useful artifact, such as a tested decision, current specification, or error report, without replaying the entire path that produced it.

## Learn the skill while the meter is quiet

Context engineering is the practice of choosing and shaping the information supplied to a model on each call. Start a clean thread when the task changes. Carry forward a compact artifact instead of a full debate. Retrieve only the files needed for the next decision, remove unused tool definitions, and keep stable instructions together so prompt caching can reuse them efficiently.

Then measure the whole loop. An accepted result is an output that passes the checks required for use, such as tests and review. Even on a subscription, token counts or their API-equivalent price can provide a shadow meter. Cost per accepted result includes the successful run, failed attempts, corrections, and verification. It exposes a cheap model that creates costly rework, but it also exposes an expensive model repeatedly reading irrelevant history.

Context hygiene will not win every comparison. A one-shot analysis may genuinely need a broad source set, and difficult frontier work may justify a stronger model and a larger context. The discipline is to make that choice visible rather than letting a long-running thread make it by accident.

I do not know when subscription economics will tighten. [Anthropic already applies](https://claude.com/pricing) rolling five-hour windows and weekly limits to paid plans, so fixed price has never meant unlimited supply. I think the sensible time to learn token efficiency is while the subscription still softens mistakes. The price plan may change; the ability to produce an accepted result with less wasted context remains useful either way.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Curate context, preserve useful artifacts, and count retries and verification. Cost per accepted result turns invisible token traffic into an engineering decision that survives any pricing model.</p></div>
