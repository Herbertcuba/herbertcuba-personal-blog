A Swedish engineer named Jonas Risbrandt wrote something on LinkedIn this week that landed with me. Agentic coding, he said, moves in four layers: prompt, loop, graph, typed state. Each one was added to fix the failure of the layer below.

I think the order is right. Most engineers, especially juniors, never get a clean map of what each layer is for and why it exists. So here it is.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>The agent stack has four layers — prompt, loop, graph, typed state — and each one was added because the layer below it broke under real workflows.</p></div>

## The prompt is where you start

A prompt is just the instructions you give the model. System prompt, user prompt, tool descriptions, examples. That is it.

```python
prompt = """
You are a research assistant. Given a query, return a JSON object with:
  - answer: string
  - sources: list[string]
Do not invent sources. If unsure, say so.
"""
```

The prompt is honest. It is also fragile. A single prompt can answer one question. It cannot hold a multi-step workflow. The moment your task spans more than one tool call, the prompt stops being a specification and starts being a wish.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>A prompt is a single instruction. It works for one question. It breaks down the moment the task spans multiple steps or tool calls.</p></div>

## The loop retries the prompt

A loop wraps the prompt in a retry. Try the prompt, check the output, if it failed, try again.

```python
def agent_loop(prompt, validator, max_attempts=3):
    for attempt in range(max_attempts):
        output = model.run(prompt)
        if validator(output):
            return output
    raise AgentFailed("Could not produce valid output")
```

This is the layer most teams start at, and the one that hides the most. A 70% pass rate from a retry loop is a 70% pass rate from the system. The loop is buying back certainty the prompt should have provided.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>A loop retries the prompt until output passes a check. It hides deterministic failures behind stochastic retries, and most of what it "fixes" was a prompt problem.</p></div>

## The graph branches the loop

A graph lets the loop take different paths based on what just happened. Branch on success, branch on error, route to a different agent.

```python
def research_graph(query):
    plan = planner.run(query)
    if plan.needs_search:
        facts = search_agent.run(plan)
    else:
        facts = []
    draft = writer.run(query, facts)
    if reviewer.review(draft).has_issues:
        return research_graph(query)  # re-plan
    return draft
```

By the third layer of branching the original author cannot tell you, from one run to the next, what the agent believed it was in. That is not complexity. That is a craft failure.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>A graph routes the agent through different paths based on outcomes. Useful, but with three layers of branching the author loses track of what the agent believed.</p></div>

## Typed state is the layer you can read

Typed state is the schema describing what the agent believes about the world at this moment. In code, it looks like a normal dataclass or Pydantic model.

```python
from pydantic import BaseModel
from typing import Literal

class ResearchState(BaseModel):
    query: str
    plan: list[str] | None = None
    facts: list[str] = []
    draft: str | None = None
    status: Literal["planning", "searching", "writing", "done", "failed"] = "planning"
    confidence: float = 0.0
```

Every node in the graph reads from this state and writes back to it. The state is the artifact the team owns. They can review it, version it, and break it on purpose to see what the agent does next.

This is the moment in *2001: A Space Odyssey* where Dave Bowman opens HAL's logic panel and reads what HAL actually believes. The crew is alive. The mission is wrong. None of it is visible from outside the pod. Dave can act only because HAL's state is something a person can open and disagree with.

That is what typed state gives the engineering team. The read-out panel. Not a log. A schema describing what the agent believes, in a language the team already speaks.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Typed state is the schema describing what the agent believes. Every node reads and writes it. The team can review it, version it, and break it on purpose — the same way Dave Bowman could read HAL's logic panel.</p></div>

## Why this is the layer worth caring about

The leap worth getting excited about is not a smarter model. It is a schema the team can read. Strong typing is the oldest discipline we have in software. The same move that made Rails web apps tractable in 2005 is making agent systems tractable now.

Reversibility, the property a system has when the team can take back a decision after the agent made it, becomes a property of the state machine. The teams I work with keep telling me their agents are unpredictable. Almost every time the answer turns out to be the same. The agent is fine. The state underneath it is untyped. We know how to fix that.
