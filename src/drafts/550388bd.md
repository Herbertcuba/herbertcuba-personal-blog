# Open weights are having their 1999 moment

I tried to read Anthropic's absence from the July 24 open-weights letter as a normal policy disagreement. Then I read the letter, Anthropic's answer, and Microsoft's internal memos from 1998. The same structure showed up in all three.

The letter, [Open Weights and American AI Leadership](https://www.microsoft.com/en-us/corporate-responsibility/topics/open-weight/), launched with 25 companies. Its live list now includes Nvidia, Microsoft, Meta, Google, OpenAI, and Amazon. Anthropic is missing, while OpenAI joined after launch. The term open weights means you can download a model's learned numerical parameters and run them on your own machines.

I think Anthropic now sits where Microsoft sat at the end of the 1990s. Its warnings about open access may be sincere, while open weights also threaten its business. Yet AI models can cross safety lines that Linux never could. That twist makes the old analogy useful and dangerous.

<div class="article-tldr"><span class="article-tldr__label">In short</span><p>Open weights are likely to repeat much of open source's rise. They spread control and reduce dependence on a few providers. Anthropic's safety case deserves serious treatment, so regulation should test what a model can do and apply the same test to open and closed models.</p></div>

## Microsoft has seen this film before

Microsoft's private analysis and public language told two different stories.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Microsoft knew open source could match commercial software, yet fought it with fear, uncertainty, and doubt. Linux and Apache later became basic internet infrastructure, while Microsoft became a major open source contributor.</p></div>

In August 1998, Microsoft engineer Vinod Valloppillil wrote an internal memo titled [Open Source Software: A (New?) Development Methodology](http://www.catb.org/~esr/halloween/halloween1.html). Eric S. Raymond published the leak that October. The memo called open source a "direct, short-term revenue and platform threat" and admitted that commercial quality could be "achieved / exceeded" by open projects.

It also said fear, uncertainty, and doubt, or FUD, would fail as a long-term response. Microsoft's public campaign still leaned into it. Steve Ballmer compared Linux to communism in 2000 and called it a "cancer" in the intellectual-property sense in 2001. Shared Source followed, offering selected access while Microsoft kept control.

Linux and Apache became internet infrastructure. Every TOP500 supercomputer has run Linux since 2018. Microsoft later bought GitHub and became a major corporate open source contributor. Azure now depends on Linux.

The company hosting the 2026 letter is Microsoft itself. I think that reversal deserves more attention than any slogan in the letter.

## What open weights change in your stack

For a junior AI engineer, the argument becomes clearer when it touches a system you could build.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Open weights give you control over the model running inside an agent. They leave training data and much of the model-building code private, which makes open weight AI different from open source software.</p></div>

Suppose you build an incident-response agent for a small security team. It follows ReAct, short for Reason and Act. The model chooses a next step, calls a tool such as a log search, reads the result, and repeats the loop.

You build the workflow with LangGraph, a Python library for agent flows that branch and loop. A TypedDict is a Python type that lists the keys in the agent's shared state. It also records the type of each value, such as `alert`, `evidence`, and `severity`. StateGraph is the LangGraph class that connects each step and passes that state through the workflow.

With a closed model, your StateGraph calls an API while the provider holds the weights. With open weights, you can run the model inside your network and tune it for incident data. Your logs stay under your control, and model swaps leave the graph intact.

This is the engineering side of [who owns the intelligence](/posts/2026-03-13-who-owns-the-intelligence/). Yet open weights expose less than source code. The Open Source Initiative's [Open Source AI Definition](https://opensource.org/ai/open-source-ai-definition) requires more than weights alone. Training data and code may stay private, so you receive a runnable artifact without the recipe.

## Anthropic has a serious point

Dario Amodei answered the coalition three days later, and his position is more careful than critics suggest.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Anthropic rejects broad bans and calls open models without dangerous capabilities a public good. Its strongest point is simple: a released capability cannot be withdrawn from copies running elsewhere.</p></div>

In [Anthropic's July 27 response](https://www.anthropic.com/news/position-open-weights-models), Amodei wrote that the company "has never advocated for a ban on open-weights models." He called models without dangerous capabilities "a public good." His preferred rule is safety testing for every sufficiently capable model, whether its weights are open or closed.

He also backs advanced-chip controls and limits on industrial-scale distillation, where one model's outputs train another. This is a race between states as well as companies. The 1990s analogy says little about export controls or chips.

Anthropic's strongest point becomes concrete in your incident-response agent. An API provider can patch a model or revoke access. Downloaded weights can be stripped of safeguards and run offline. The lab cannot update every copy.

I think Anthropic is right about that one-way release. A future model that can reliably help design a pandemic-scale pathogen would change the risk. Wide release starts to look less like Linux and more like the breeding dinosaurs in *Jurassic Park*. Fixing the fence at the original lab does little once copies are loose elsewhere.

I don't know where that capability threshold sits. Available evidence leaves the defender advantage unresolved across cyber and biology. Anthropic's attacker case also lacks a decisive test.

## The symmetry test for safety claims

Sincere safety work can still produce rules that favor the company proposing them.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Judge AI safety proposals by symmetry. A credible rule tests the same ability in open and closed models. A protectionist rule puts most of its burden on rival ways to distribute a model.</p></div>

Anthropic sells controlled access to closed models. Open-weight competitors lower switching costs and can make the model layer cheaper. That creates a business reason to prefer closed distribution, even when the safety concern is sincere.

The signers have incentives too. Nvidia sells compute. Microsoft and Amazon sell cloud capacity. Meta benefits when base models become less scarce. OpenAI joined the letter after launch, which complicates any clean story about closed incumbents defending one shared position.

Calling Anthropic the new Microsoft describes its role in this market. It says nothing about Amodei's intent. I think the comparison is useful only when it helps us inspect the proposed remedy.

Apply a simple symmetry test:

1. Would the same capability face the same evaluation if it sat behind a closed API?
2. Could the remedy reduce harm after downloadable copies exist?

Return to the incident-response agent. If its model can produce a working exploit chain from a vague request, test that ability in both deployments. The closed API may support monitoring after release. The downloadable model needs stronger checks before release because later control is limited. The capability stays the same, while the available controls move.

Open advocates need the same discipline. Heartbleed remained in open OpenSSL code for about two years before disclosure in 2014. Access made inspection possible, but funded attention never arrived in time. Skilled people still have to do the work.

I think this symmetry test is how we separate credible fear from FUD without pretending either side is free of self-interest.

## Where this ends

The open-source pattern will repeat across much of AI, with a harder boundary around the most dangerous capabilities.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Open weights will likely become the normal base layer for many AI systems, while frontier capabilities stay gated for longer. Engineers should build portable agent workflows now and treat model safety as a capability question.</p></div>

I think open weights will win routine enterprise use for the same reason Linux won servers: teams value control and local adaptation. A broad supplier base will grow around that demand. Closed frontier models will remain useful where they offer a clear capability lead or stronger operational controls.

For your incident-response agent, keep LangGraph independent from one model. A stable TypedDict lets StateGraph route the same steps across a local open model and a controlled frontier service.

That supports the open protocol logic in [who owns the agent layer](/posts/who-owns-the-agent-layer/). Portability gives engineers choices. Safety tests tie the boundary to what a model can do.

Microsoft's 1998 memo correctly saw openness as a threat to its structural advantage. Anthropic may see the same commercial threat, while also seeing a danger the open camp wants to wave away.

History favors openness. AI safety will decide how far that history is allowed to run.
