# Anthropic's open-weights position looks a lot like Microsoft in 1999

I tried to read Anthropic's missing signature on a July 24 open-weights letter as a small policy disagreement. Then OpenAI and Amazon joined the coalition, while Anthropic published its own answer.

The fight has an old shape. An incumbent warns that openness creates unacceptable risk as it threatens a profitable layer. Microsoft did this when Linux came for servers.

I think Anthropic's safety case is far stronger than Microsoft's case was. Downloaded model weights can carry dangerous capabilities that no later patch can pull back. That makes the comparison useful and uncomfortable at the same time.

<div class="article-tldr"><span class="article-tldr__label">In short</span><p>The 2026 fight over open weights repeats Microsoft's old habit of mixing technical risk with commercial self-interest. AI raises the stakes because released weights can spread permanently, so capability-based rules deserve more trust than blanket fear.</p></div>

## The missing signature became part of the product

On July 24, 2026, a policy letter turned open weights into a public lineup.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Twenty-five companies launched a letter backing open weights, and Anthropic became a notable holdout among companies building the most capable models. For engineers, this fight decides where a model can run and who controls its future access.</p></div>

The document is called [Open Weights and American AI Leadership](https://www.microsoft.com/en-us/corporate-responsibility/topics/open-weight/). [Launch-day reporting](https://www.cnbc.com/2026/07/24/nvidia-microsoft-meta-open-weight-ai-models.html) counted 25 companies, including Nvidia, Microsoft and Meta. The letter says downloadable models can strengthen American AI and give defenders more room to inspect weaknesses.

Open weights are the learned numbers inside a model. You can download them and run the model on your own hardware. The code and training data may stay private, which makes open weights narrower than [open source AI](https://opensource.org/ai/open-source-ai-definition).

A security alert agent for suspicious logins makes the choice concrete. It searches company logs, collects evidence and decides whether a human should investigate. With open weights, the team can place the model on a server beside those logs. In the common hosted setup for a closed model, the agent sends a request to a provider's API.

Three days later, Dario Amodei published [Anthropic's response](https://www.anthropic.com/news/position-open-weights-models). He calls open-weight models without dangerous capabilities a public good and supports safety tests for sufficiently capable open and closed systems. His concern is that broad access may help attackers more than defenders.

I think that concern is real. I refuse to treat a policy position as commercially innocent simply because its author believes it. Anthropic sells controlled access to Claude, and downloadable rivals put pressure on that model.

## Microsoft left us the receipts

The Linux fight gave us a rare view of what an incumbent said in public and wrote in private.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Microsoft privately understood open source as a credible technical and commercial threat while its public language painted Linux as dangerous. The company's later embrace of Linux makes that paper trail hard to dismiss.</p></div>

In August 1998, Microsoft program manager Vinod Valloppillil wrote an internal memo titled [Open Source Software: A (New?) Development Methodology](http://www.catb.org/~esr/halloween/halloween1.html). Eric S. Raymond published the leak that October. It became the first Halloween Document.

The memo called open source a "direct, short-term revenue and platform threat" to Microsoft, especially in servers. It also admitted that open projects could meet or exceed commercial quality. One line reads like a warning sent forward in time: "FUD tactics can not be used to combat it."

Microsoft's public language became harsher. Steve Ballmer compared Linux to communism in 2000. In 2001, he called Linux a "cancer" in the intellectual property sense.

The feared software kept spreading. Linux has run every system on the TOP500 supercomputer list since June 2018. Microsoft acquired GitHub in 2018, and it now develops Azure Linux for container workloads on Azure. The company hosting the 2026 open-weights letter is Microsoft itself.

I think the reversal exposes a pattern. Risk language grows easily around a threat to revenue, even when some technical concern is sincere. Anthropic now sits in a similar commercial position: controlled access is its product, while open-weight competitors can run elsewhere.

## The policy fight lands inside one model call

For a junior engineer, all this history becomes concrete inside the alert agent.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>ReAct is the agent's tool-use loop. LangGraph carries the alert and evidence through that loop, so the same saved login cases can test a hosted API and a local model.</p></div>

The names make this sound grander than it is. ReAct, short for reasoning and acting, is the alert agent's loop. The model calls log search, reads the result and chooses its next step. One tool call becomes evidence for the next decision.

LangGraph is a Python framework for workflows that branch or repeat. In our agent, a `TypedDict` is a Python type hint for keys such as `alert` and `evidence`. At runtime it remains an ordinary dictionary. LangGraph's `StateGraph` connects log search and escalation as nodes, while edges route what runs next.

The model call sits in one of those nodes, pointing at a provider API or a model on the team's server. The team can run both against the same saved login alerts. A swap may still require prompt changes and fresh evaluations, but the log-search workflow can survive.

This is [who owns the agent layer](/posts/who-owns-the-agent-layer/) in plain engineering terms. Owning the workflow gives the provider less power over the whole system. The code that gathers evidence keeps its value when the model changes, an effect I wrote about in [When Software Becomes Disposable](/posts/when-software-becomes-disposable/).

I think bounded systems like this alert agent are where open weights will win first. The team has a narrow job and a test set it can replay. Control is useful because the problem has edges.

## Safety changes after the download

The same alert agent becomes a different risk once its model can produce a working exploit.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Downloaded weights create a one-way release because copies can run offline after safeguards change. Heartbleed also shows that public access helps inspection without guaranteeing that skilled people will inspect the right code in time.</p></div>

A closed provider can block a request and update the model later. A downloaded copy can keep running offline. Its owner may remove safety tuning, and later safeguards cannot recover copies already shared.

This is where the Linux analogy breaks. A vulnerable package can receive a patch. A released model behaves more like the dinosaurs in *Jurassic Park*: restoring power in the control room does little once the animals have crossed the fence. Distribution turns a model capability into a one-way door.

Amodei uses biology as his hardest case. He worries that a sufficiently capable model could help someone weaponize a pandemic-level virus quickly, while defense could take years. I think this is the strongest argument for control at the frontier.

Open access also carries no automatic security guarantee. Heartbleed sat in the public OpenSSL codebase for about two years before its public disclosure in 2014. The code was visible for years, and the flaw still escaped notice.

I don't know where the dangerous capability line belongs. The material I read leaves both camps with more confidence than proof. Treating every safety claim as fearmongering would be as lazy as treating every open release as reckless.

## One rule should bind both sides

Policy should start with measured capability, then account for distribution.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Open and closed models should face the same capability tests, with a higher release bar when downloaded copies cannot be recalled. That would test Anthropic's warning against Claude as well as against its open-weight rivals.</p></div>

Evaluators can ask whether the alert agent's model turns a vague request into a working exploit for an unpatched server. They should run that test against the API model and the local model. Distribution changes the consequence: the provider can intervene later, while the downloaded model may stay beyond reach.

Anthropic wants powerful chips kept out of authoritarian hands and industrial-scale distillation stopped. It also calls for safety tests for every sufficiently capable model, open or closed. The testing proposal earns my trust because it reaches Claude too. The other proposals still deserve scrutiny for how they shape competition.

The coalition has incentives too. Nvidia sells chips, while Microsoft sells cloud capacity. OpenAI's later signature complicates any clean story about open challengers facing closed incumbents. Every name on the letter arrives with a business model attached.

My take is that open weights will win the alert agent and thousands of bounded systems like it. The most capable models may stay behind controlled access for longer when tests show dangerous capabilities. Anthropic's missing signature remains a signal, but the signal is incomplete until its preferred rules bind its own models.

1999 teaches us to inspect the speaker. 2026 requires us to inspect the model too.
