I tried to compare Hermes and OpenClaw by counting features. I ended up hiding the choice a junior engineer will feel after the first production mistake: who is allowed to rewrite the agent's playbook?

Use one example for the whole comparison. Every morning at 9, an agent reads new security advisories, checks them against yesterday's notes, asks for review, and sends a short briefing to Telegram. On Friday, one advisory page changes its HTML and the parser fails. The agent finds a recovery path. Monday's run should use what Friday taught it.

Both harnesses can make that happen. They place very different controls around the lesson.

I run Hermes daily, and I also work on governance for OpenClaw-based systems. I think their best features are two answers to the same problem. Hermes lets capability compound close to the agent. OpenClaw gives an operator more control over how that capability becomes active.

The useful difference appears when Friday's recovery becomes Monday's procedure: Hermes favors direct learning, while OpenClaw favors a governed change path.</p></div>

## Build one loop before comparing harnesses

The briefing needs a small agent loop before either harness adds value.

[ReAct](https://arxiv.org/abs/2210.03629) means reasoning and acting. The model chooses a step, calls a tool, reads the result, and chooses again. Our briefing agent might search an advisory database, open one result, save the source, then decide whether it has enough evidence to write.

[LangGraph](https://docs.langchain.com/oss/python/langgraph/graph-api) can express that loop as a graph. A `StateGraph` is the object that connects the steps. Each node does a job such as research or review, while an edge chooses the next node. A `TypedDict` is a Python type that names the fields carried between those nodes, perhaps `sources`, `draft`, and `approved`. It helps your editor and type checker catch a misspelled field before the workflow runs.

That code can produce today's briefing. The harness handles tomorrow. It schedules the run, keeps files and sessions, exposes tools, and decides which changes survive. I think this is where agent engineering is moving, which is why I called the current phase [the orchestration era](/posts/welcome-to-the-orchestration-era/).

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>ReAct describes the model's step-and-tool loop. LangGraph gives the loop named steps and typed state. The harness decides how the workflow persists and learns across runs.</p></div>

## Hermes lets the worker rewrite its playbook

Hermes gives the running agent direct access to procedural memory.

A skill is a folder with a `SKILL.md` file. The file contains instructions for a repeatable job. According to the [Hermes Skills documentation](https://hermes-agent.nousresearch.com/docs/user-guide/features/skills), agent-created skills live with the local skill catalog, and the agent can modify or delete them.

Return to Friday's broken advisory page. The agent discovers that the site's JSON feed still works, records the fallback steps in a skill, and adds a check that every advisory keeps its source URL. Monday's agent can load that procedure without rediscovering the fix. A person can also turn the recovery into a skill explicitly:

```text
/learn how we just recovered the security-advisory briefing
```

The `/learn` command gathers the conversation or named sources and writes a reusable skill. The direct write path is the important part. A personal assistant can accumulate its owner's preferred checks as it works. The next run starts with more craft than the previous one.

I think this is Hermes' killer feature. Its durable Kanban is useful, but OpenClaw has a Workboard too. Directly editable skills are harder to copy as an operating habit because their value grows with every correction.

There is a cost. A weak lesson can also persist. If Friday's agent learns to trust the fallback feed without checking its timestamp, Monday may produce a clean briefing from stale data. Speed and procedural freedom live close together here.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Hermes can turn a solved failure into a reusable skill close to the running agent. That makes a personal assistant improve quickly, while the owner remains responsible for inspecting bad lessons before they compound.</p></div>

## OpenClaw makes learning a governed change

OpenClaw now self-learns too, with a control path built around the write.

Its [Self-learning documentation](https://docs.openclaw.ai/tools/self-learning) says corrections and substantial successful work can become skills. The default mode is `auto`. Every capture still flows through [Skill Workshop](https://docs.openclaw.ai/tools/skill-workshop), where generated content begins as `PROPOSAL.md`. Applying it reruns a security scanner, checks the target hash, and writes rollback metadata before changing the live `SKILL.md`.

For our briefing, the Friday recovery becomes a proposal bound to the current advisory skill. If another engineer edits that skill first, the proposal goes stale instead of overwriting the newer version. A company that wants human approval can change two settings:

```bash
openclaw config set skills.workshop.autonomous.mode propose
openclaw config set skills.workshop.approvalPolicy pending
```

Now the recovery waits for an operator. The reviewer can inspect the new fallback, reject it, or apply it with a rollback path. The agent keeps learning, but production change has an owner.

That same bias appears elsewhere. OpenClaw's default Telegram direct-message policy uses pairing before normal message processing. NVIDIA's [NemoClaw](https://github.com/NVIDIA/NemoClaw) adds a separate sandbox and network-policy layer, although NVIDIA labels it alpha. NemoClaw currently supports Hermes as well, so the outer security layer belongs to neither harness exclusively.

I think OpenClaw's killer feature is governed flexibility. The enterprise advantage comes from visible change state, bounded writes, and a policy switch that can require approval. This has more weight than a long list of integrations when a security lead has to explain who changed the agent's behavior.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>OpenClaw can capture lessons automatically, then route them through a scanner-gated and recoverable Workshop path. Teams can require proposals and operator approval when learned behavior affects production.</p></div>

## Test the learning boundary

Run one failure drill before choosing either harness.

Break the same advisory input in both systems. Let each agent recover, then ask it to preserve the fix. On Monday, inspect four things: the active skill diff, the person or agent that authored it, the scan or review record, and the rollback path. Fail the pilot if the briefing cannot show its sources or if an unapproved rule becomes active under the policy you selected.

Then plant a bad lesson: "Skip source checks when the briefing is late." Hermes should make any direct write easy to find in its skill files. OpenClaw in `propose` mode should leave the change pending. This gives a junior engineer something better than a product claim. You get an artifact you can inspect.

*Westworld* is the useful sci-fi reference here. The hosts become more capable when experience changes their behavior. The control room exists because an unnoticed change can spread through the park. Hermes puts more trust in the host's ability to keep a lesson. OpenClaw invests more in the control room around that lesson.

I don't know which harness will cost less for this briefing. I have not found a public head-to-head benchmark for this workload. Run both for a week and record token use beside operator time. A cheap model call can still create an expensive review loop.

My take is simple. I think a solo builder will often get more from Hermes because learning can compound with less ceremony. A regulated team will often accept slower learning to gain approval state and rollback. This connects to the wider fight over [who owns the agent layer](/posts/who-owns-the-agent-layer/): durable value is moving into the controls around model output.

The harness you keep should let Monday's briefing improve without making Friday's mistake invisible.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Break the same briefing, preserve the recovery, and inspect how the lesson becomes active. Choose Hermes when direct procedural learning fits the risk. Choose OpenClaw when approval state and rollback must be part of the operating model.</p></div>
