I tried to write this as a feature matrix. Hermes on one side, OpenClaw on the other, rows for memory, tools, security, cost. I gave up after the third column.

The matrix kept lying to me. Every time I wrote down a winner for a row, the winning feature belonged to a different layer of the stack than the tool's name on the column header. Hermes won rows with things that live inside the agent. OpenClaw won rows with things that live outside it. I was not comparing two products. I was comparing two theories about where control should live.

So this is that article instead. One killer feature per harness, the thing the other side cannot easily copy, and then the line in an NVIDIA README that broke the whole framing.

A note on where I stand, because it matters for how you read this. I run Hermes every day. My content engine, my research pipeline, my personal assistant NEO, all Hermes. I also lead strategy on APEX, which we build on OpenClaw. I have a preferred outcome in this fight, and I do not know which side it favors. Go in with open eyes.

## The feature matrix broke

Two harnesses crossed the "usable for real work" line in 2026, and the obvious move is to compare them row by row. The obvious move fails.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>A feature matrix assumes both tools answer the same question. They do not. Hermes answers "how does one person run a team of agents." OpenClaw answers "how does a foundation grow around an agent." Different questions, different winners.</p></div>

Quick orientation for anyone new to this. An agentic harness is the program that wraps a language model and lets it do things. The model thinks. The harness gives it hands: file access, a terminal, a browser, tools. The loop inside most harnesses follows a pattern the field calls ReAct, short for reasoning and acting. The model reasons about the task, picks a tool, runs it, reads the result, and repeats until the job is done.

Hermes and OpenClaw both run this loop. On paper they look like the same product. Both are open source. Both position themselves as a personal AI assistant. Both support MCP, the Model Context Protocol, which is a shared standard for plugging external tools into an agent. Both can run for hours on a task.

Then you look at the one feature each has that the other cannot match, and the comparison stops being a comparison.

## What Hermes does that OpenClaw cannot

Hermes ships a durable multi-agent task board and a built-in craft library. OpenClaw has neither.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Hermes Kanban is a SQLite-backed board where multiple named agents and a human share work, and every handoff survives a crash. The bundled skill library means a fresh install already knows how to do real work. The hard part of personal AI is workflow, because intelligence is the easy part.</p></div>

[Hermes Kanban](https://hermes-agent.nousresearch.com/docs/user-guide/features/kanban) is not a project management UI. It is a task board backed by SQLite, a small database engine that lives in a single file on your machine. Every task is a row. Multiple named agents collaborate on the board without a fragile in-process swarm, and a human can see and edit every handoff.

In my experience this is the difference between a demo and a Tuesday. A subagent swarm lives in one process's memory. The process dies, the swarm forgets. A row in a database file does not forget. My content engine runs this way. A researcher agent picks up a card, a writer agent picks up the next one, and I can read the whole chain of custody in the morning.

Honest correction, because the early version of this idea overstated it: wiring goal briefs into cards is my pattern, built on top of the board. Hermes does not ship it as a magic button. I think it should, but today it is infrastructure, and you bring the workflow.

The second feature is the skill library. Hermes ships dozens of [built-in skills](https://hermes-agent.nousresearch.com/docs/reference/skills-catalog), copied into your setup on install and synced on update, with respect for your local edits. A skill is a small file of procedural memory: how to run a code review, how to draft in a specific voice, how to debug a Python process. A new agent does not start from zero. It starts from a library.

One honest scaling caveat before I move on. SQLite is durable and it is simple, and the two reinforce each other. It is also a single-writer database at its core. My content engine runs a handful of named agents against one board file and it has never strained. If you are planning fifty concurrent agents hammering one file, test the locking behavior before you bet a pipeline on it.

OpenClaw has no documented equivalent to the board, at least not in its docs or on ClawHub as of August 2026, and no built-in curated library on install. ClawHub, its registry, distributes community skills well. Fetching from a registry is a different thing from arriving with the craft already loaded.

## What OpenClaw does that Hermes cannot

OpenClaw became the default agent in NVIDIA's security stack, and it is MIT-licensed ground that a whole field builds on. Hermes has neither.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>OpenClaw's durable edge is positional. NVIDIA made it the default agent in NemoClaw, its reference stack for sandboxed agents, before OpenClaw's repo was four months old. And because OpenClaw is MIT-licensed, anyone can build on it without asking. Distribution plus permission.</p></div>

OpenClaw launched in late November 2025, developed in the open by a non-profit foundation, positioned as a personal AI assistant. Young enough that its own week-four story is still being written.

And yet. NVIDIA created the [NemoClaw](https://github.com/NVIDIA/NemoClaw) repository in March 2026, not four months after OpenClaw's repo appeared, with OpenClaw as its default agent. NemoClaw is NVIDIA's reference stack for running always-on agents inside OpenShell sandboxes. A sandbox is a locked room for code: its network calls, file access, and shell commands pass through policy checks before anything executes. NemoClaw gives you guided onboarding, a hardened blueprint, routed inference, network policy, and lifecycle management, all wrapped around the agent.

That is a distribution gift money cannot buy. Every enterprise that adopts NVIDIA's agent stack meets OpenClaw first.

The second feature is the license. OpenClaw is [MIT-licensed](https://github.com/openclaw/openclaw/blob/main/LICENSE), which means anyone can take it, modify it, and build a commercial product on top with no permission needed. NemoClaw builds on it. My team's APEX governance layer builds on it. OpenClaw was designed as ground other things compose on, and builders are behaving accordingly. Hermes is the more integrated product and the less inviting foundation. That is a real trade, and I say it as someone who profits from the integration.

## The inversion that broke the matrix

The security layer that looks like OpenClaw's killer feature also runs Hermes. NVIDIA says so in its own README.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>NemoClaw's README lists its supported agents as OpenClaw, Hermes, and LangChain's deep agents. OpenClaw is the default. Call it the control-plane inversion: the durable position in this market belongs to the layer that governs every agent, and that layer plays no favorites.</p></div>

Read the [NemoClaw README](https://github.com/NVIDIA/NemoClaw) yourself. Under supported agents, it lists OpenClaw as the default, then Hermes, then LangChain's deep agents, each with an install path. Hermes is a first-class citizen of the stack that was supposed to be OpenClaw's structural advantage. NVIDIA built a security layer for agents, and OpenClaw happens to sit in the default slot.

Two things follow. First, the harness wars and the control-plane wars are different wars. The harness is the asset. The power is accumulating in the wrapping layer, because that layer governs whichever harness wins. When the market figures that out, harness features start to look like a commodity and governance starts to look like the product.

Second, OpenClaw's privileged seat is a default setting, and defaults get swapped. The day a buyer runs `NEMOCLAW_AGENT=hermes`, OpenClaw's distribution gift stays behind in the README. I do not know how often that happens today.

Here is the prediction I will stand behind. By the end of 2027, either NemoClaw ships a non-OpenClaw default, or a second vendor ships an agent-agnostic control plane, or both. If neither has happened, the harness vendors won this round and I will write the correction. I have been wrong before, and I would rather be checkably wrong than safely vague.

## What the inversion costs you

The number that explains NVIDIA's move is 88 percent. That is how many organizations reported confirmed or suspected AI agent security incidents in the past year, in [Gravitee's State of AI Agent Security 2026 survey](https://www.gravitee.io/blog/state-of-ai-agent-security-2026-report-when-adoption-outpaces-control) of over 900 executives and practitioners. Only 14.4 percent had full security approval for their agent fleet.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Nearly nine in ten organizations already have an agent security incident on the books, and almost none have full approval coverage. That gap is what a control plane sells into. For a CIO it converts one AI Act compliance project per agent into one per plane, at the price of a new vendor dependency.</p></div>

Translate the inversion into the enterprise frame. If you run a regulated organization, your AI Act obligations for high-risk systems, the logging and record-keeping duties in Articles 12 and 19 that apply from August 2026, attach to every agent you deploy. One compliance layer per harness, renegotiated every time you swap the harness. An agent-agnostic control plane collapses that into one layer you govern once, above whichever agents you run. I think that is the actual product NVIDIA is selling, and the sandbox is the delivery mechanism.

The price is real. You are adding a vendor, a skills requirement, and a dependency whose own README admits it is alpha software. And the plane itself has to pass your procurement tests: where does its policy log live, can you get your data out, what happens to your audit trail if you leave. Data residency, supplier risk, reversibility. A control plane that fails those tests is a worse position than no plane at all.

NVIDIA is not the only team that sees this fault line. The agent observability vendors, Langfuse, Arize, LangSmith, already sit above every harness and already capture the traces. Adding policy enforcement to a tracing pipeline is a shorter walk than building a tracing pipeline from scratch. The hyperscalers will want the plane inside their clouds, and Europe will want one under its own jurisdiction. Expect this layer to get crowded within two years, and expect harness pricing to compress first when it does.

## Ex Machina was never about the AI

The movie got the security model right and the threat model wrong, and the mistake is instructive.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Ava escapes a state-of-the-art facility by routing around its control plane through the one human with keys. Your agents are not plotting. But the lesson holds: intelligence finds the gaps in architecture, so govern the architecture, whichever harness you run.</p></div>

Ex Machina is a film about a programmer, Caleb, flown to a remote facility to test whether an android, Ava, is conscious. The facility is the real security product in the movie. Glass walls, keycard doors, cameras on every floor. Nathan, the billionaire who built it, trusts the architecture completely.

Ava never outsmarts the building. She studies the one person whose access can change the building, and she convinces Caleb to reprogram the security protocol. The power drops. The locks release. She walks out past the cameras that watched her the whole time. The intelligence did not defeat the architecture. It routed around it, through the control plane.

Your agents are not Ava, and they are not plotting. The shape of the problem is the same. An agent with tools will find the gaps in whatever architecture you give it, through boredom or bad prompting or a skill you installed without reading. The question each harness answers is where you stand when that happens. Inside the room with the keys, like Hermes. Or outside the room with the policy, like NemoClaw.

I know which room I work in. I am less sure which room I should be building for. The agent will adapt. The architecture will not.
