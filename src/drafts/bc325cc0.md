I tried to write a feature matrix comparing Hermes and OpenClaw. I gave up after three rows.

Both run agents. Both support MCP, the Model Context Protocol that lets an agent call external tools. Both have skill systems, memory, subagents. The matrix told me they were the same.

They are not the same. The difference is architectural. One keeps the control plane inside the agent. The other moves it outside, into a security layer that governs the agent from the boundary. That decision shapes how you debug, how you scale, and how you survive an audit.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Hermes and OpenClaw look identical on a feature checklist. The real difference is where control lives: inside the agent (Hermes) or outside it (OpenClaw plus NVIDIA's NemoClaw). Pick based on which layer you need, not which features you like.</p></div>

## The security gap nobody prices in

Adoption is running far ahead of governance, and the gap is where the market is.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Gartner expects 40% of enterprise apps to have task-specific agents by end of 2026, up from under 5% in 2025. Yet Gravitee's 2026 survey found 88% of organizations reporting confirmed or suspected agent security incidents, and only 14.4% with full security approval. Governance is the unsolved problem.</p></div>

The numbers are stark. Gartner projects 40% of enterprise applications will feature task-specific AI agents by the end of 2026. A year ago that figure was under 5%. Spend follows: roughly $201.9 billion on agentic AI in 2026.

And yet. Gravitee's 2026 survey of over 900 executives and practitioners found 88% reporting confirmed or suspected agent security incidents. Only 21.9% treat agents as independent identities with their own credentials. 45.6% still run agents on shared API keys.

I think about this the way I think about the early web. Everyone built sites. Almost nobody built SSL. Then the breaches started, and the companies that survived treated security as infrastructure. The same pattern is playing out with agents. The models are good enough. The frameworks are good enough. What is missing is the layer that answers three questions: who is this agent, what can it touch, and how do I prove it behaved.

That is why NVIDIA built NemoClaw. Keep it in mind, because it changes what the Hermes vs OpenClaw comparison actually means.

## Hermes: the control plane lives inside the agent

Hermes is a personal AI assistant that grows with you. Its coordination machinery (Kanban, skills, memory, goals) sits inside the agent, durable and inspectable, built for one operator running several agents.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Hermes Kanban is a durable, SQLite-backed task board shared across all your Hermes profiles, so multiple named agents coordinate without fragile in-process swarms. Skills are procedural memory modules, synced on update. The control plane sits inside the agent: fast, local, yours. Enterprise security is on you.</p></div>

Here is a concrete example, the one I run daily. My content engine has three Hermes profiles: one does research, one writes drafts, one publishes. The researcher finishes a brief and drops a card on the Kanban board. The writer picks the card up, reads the brief, drafts. The publisher takes the approved draft live. Every handoff is a row in a SQLite database at `~/.hermes/kanban.db`. I can open that file, read every row, edit any card. When a profile crashes mid-task, the row survives and another run picks it up.

This is different from spawning subagents in memory. Those die with the process. Kanban rows persist. Coordination is explicit state you can inspect, not implicit state you have to trust.

The second thing Hermes gets right is skills. Hermes ships with roughly 90 bundled skills: SKILL.md files that teach the agent a procedure, synced on install and update, respectful of your local edits. When my writer profile drafts an article, it loads the tone-of-voice skill, the humanizer skill, the publishing conventions. That is craft knowledge, packaged and reusable across every agent I run.

The strength of this architecture is speed and ownership. Everything is local, everything is inspectable. The weakness is that Hermes ships with no sandbox, no routed inference, no network policy. If you need to prove compliance to an auditor, you build that yourself.

## OpenClaw and NemoClaw: the control plane moves outside

OpenClaw is also a personal AI assistant, MIT-licensed and developed in the open by a non-profit foundation. The interesting part of its ecosystem is what composes around it.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>OpenClaw is MIT-licensed substrate. NemoClaw is NVIDIA's Apache-2.0 reference stack that runs agents inside OpenShell sandboxes with routed inference and network policy. Crucially, NemoClaw supports Hermes and LangChain agents too, not just OpenClaw. The control plane moves outside the agent: portable governance, at the cost of operational complexity.</p></div>

NemoClaw is an open source reference stack for running always-on agents more safely inside NVIDIA OpenShell sandboxes. Guided onboarding, a hardened blueprint, routed inference, network policy, lifecycle management, all through a single CLI. Apache-2.0 licensed.

Here is the fact that surprised me, and that my original outline got wrong. NemoClaw is not exclusive to OpenClaw. OpenClaw is the default agent in its docs, but it supports Hermes and LangChain Deep Agents as first-class citizens. NVIDIA built a security layer that wraps multiple harnesses, not a walled garden for one.

That changes the comparison. With Hermes alone, the control plane is inside the agent. With NemoClaw, the control plane sits between your agent and the world, enforcing policy at the boundary. You can swap the agent without rebuilding governance. You can audit the boundary independently of the agent's internals.

The tradeoff is operational complexity. You are running a sandbox, a policy engine, a routing layer. The agent is no longer a single process you can reason about. It is a system.

## The real comparison is layer, not product

These two are less head-to-head competitors than different layers of the same stack.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Hermes optimizes for the individual power user: fast, local, inspectable. The OpenClaw ecosystem, with NemoClaw, optimizes for the governed organization: externalized security and auditable boundaries. The question to ask is which layer you need today, because the mental models do not transfer even when the tools do.</p></div>

So the honest head-to-head is this. Hermes's killer feature is durable, inspectable, multi-agent state. The Kanban board plus the skill system gives a solo builder coordination and craft knowledge with almost zero ops. OpenClaw's ecosystem has no native equivalent to that board. Its killer feature is the inverse: an external governance layer that can wrap any agent, which Hermes has no native equivalent to either.

Each harness's strength is the other's gap. That is what a real head-to-head looks like.

In my experience, teams get into trouble when they apply the wrong mental model. Personal-assistant thinking (I own the state, I inspect the rows, I fix it myself) breaks down the moment a security team asks how you know the agent did not exfiltrate data. Substrate thinking (policy at the boundary, audit the sandbox) is overkill when you are one person trying to ship a content pipeline. I have felt both failure modes myself, on different sides of my own work.

## What this means for you

If you are a junior AI engineer building your first serious agent workflow, this choice shapes your daily work more than model choice does.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Start with Hermes if you are learning: the feedback loop is faster and every decision is traceable. Reach for NemoClaw when you hit the compliance wall. Both support MCP, so your tool integrations transfer. What does not transfer is the mental model of where control lives.</p></div>

My take: start with Hermes. You can see the Kanban board. You can read the skills. You can trace every decision your agents make, because the state is files on your disk. That transparency is how you build intuition for what agents actually do.

Reach for NemoClaw when you hit the compliance wall. When legal asks for an audit trail, when security asks for proof of containment, you need the external boundary. And because NemoClaw wraps Hermes too, you do not have to abandon your agent logic to get it.

I don't know which architecture wins long term. The internal model has lower friction. The external model has lower risk. My guess is they converge: personal assistants will absorb security layers, and security layers will get easier to run. But that convergence is years away.

In Ex Machina, Ava does not escape by outsmarting Caleb in conversation. She escapes by understanding the building's control systems. The test was never whether she was smart. The test was whether the room she was in was secure. Your agent is smart. The question is whether the room it runs in is one you control, or one someone else controls for you.
