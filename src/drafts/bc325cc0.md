I tried to write a feature matrix comparing Hermes and OpenClaw. I gave up after three rows.

The rows were useless. Both harnesses run agents. Both support MCP. Both have skill systems, memory, subagents. The matrix told me nothing about which one to pick. It told me they were the same.

They are not the same.

The difference is architectural. One puts the control plane inside the agent. The other externalizes it to a security layer that can govern any agent. That decision shapes everything: how you debug, how you scale, how you survive an audit, how you sleep at night.

## The security gap nobody prices in

88% of organizations report confirmed or suspected AI-agent security incidents. Only 14.4% have full security approval for their agent deployments. That gap is the market.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Agentic AI adoption is running ahead of governance. Gartner says 40% of enterprise apps will have task-specific agents by end of 2026, up from under 5% in 2025. But 88% of organizations have already hit security incidents, and only 14.4% have full security approval. The harnesses that solve governance without killing velocity will win.</p></div>

The numbers are stark. Gartner projects 40% of enterprise applications will feature task-specific AI agents by the end of 2026. A year ago that number was under 5%. Spend is following: roughly $201.9 billion on agentic AI in 2026. And yet Gravitee's 2026 survey of 900+ executives and practitioners found 88% reporting confirmed or suspected agent security incidents. Only 21.9% treat agents as independent identities. 45.6% still use shared API keys.

I think about this the way I think about the early web. Everyone built sites. Nobody built SSL. Then the breaches started, and the companies that survived were the ones who treated security as infrastructure, not as a feature you add later.

The same thing is happening with agents. The models are good enough. The frameworks are good enough. What is missing is the layer that answers: who is this agent, what can it touch, and how do I prove it behaved?

That is why NVIDIA built NemoClaw. And that is why the Hermes vs OpenClaw comparison matters more than any feature checklist.

## Hermes: the control plane lives inside the agent

Hermes is a personal AI assistant that grows with you. Its control plane is internal: Kanban, skills, memory, goals. All inside the agent, all durable, all designed for one operator running multiple agents.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Hermes Kanban is a durable SQLite-backed task board shared across all your Hermes profiles. Multiple named agents collaborate without fragile in-process swarms. Skills are procedural memory modules, not slash commands. The control plane sits inside the agent, which makes Hermes fast and personal but leaves enterprise security to you.</p></div>

Hermes Kanban is the feature I use most. It is a durable SQLite-backed multi-agent task board. Every task is a row in `~/.hermes/kanban.db`. Any profile can see it. Any human can edit it. Crash recovery is built in.

I run three profiles: NEO for research, Trinity for content, and a general-purpose one for coding. They share one Kanban board. When NEO finishes a research brief, it drops a card. Trinity picks it up. I comment on the card if I want to redirect. The board survives restarts. The agents survive crashes. The state is the file system.

This is different from spawning subagents in memory. Those die with the process. Kanban rows persist. The coordination is explicit, not implicit. I think this is the right model for a personal AI assistant. You own the state. You can inspect it. You can fix it.

Hermes also ships with roughly 90 bundled skills. These are SKILL.md files, procedural memory modules that teach the agent how to do things. They sync on update. They respect local edits. They are not slash commands. The task spec called them "bundles" and framed them as slash commands for shared skills. That framing is wrong. Skills are deeper. They are craft knowledge, packaged and reusable.

The strength of this architecture is speed and ownership. Everything is local. Everything is inspectable. The weakness is that enterprise security is your problem. Hermes does not ship with a sandbox. It does not ship with routed inference or network policy. If you need SOC2 compliance, you build it yourself.

## OpenClaw + NemoClaw: the control plane moves outside

OpenClaw is also a personal AI assistant. But its ecosystem is designed as substrate. NemoClaw, NVIDIA's security layer, wraps any agent in an OpenShell sandbox. The control plane externalizes.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>OpenClaw is MIT-licensed and designed as a substrate. NemoClaw is NVIDIA's Apache-2.0 security reference stack that runs agents inside OpenShell sandboxes with guided onboarding, hardened blueprints, routed inference, and network policy. Crucially, NemoClaw supports Hermes and LangChain too. The control plane moves outside the agent, which makes governance portable but adds operational complexity.</p></div>

OpenClaw is MIT-licensed. The OpenClaw Foundation, a non-profit, develops it in the open. It positions itself as "your own personal AI assistant" that runs on your own devices. Sponsors include OpenAI, GitHub, NVIDIA, Vercel, Blacksmith, and Convex.

NemoClaw is where the enterprise story gets interesting. It is NVIDIA's open source reference stack for running always-on AI agents more safely inside NVIDIA OpenShell sandboxes. Apache-2.0 license. It provides guided onboarding, a hardened blueprint, routed inference, network policy, and lifecycle management through a single CLI.

Here is the part the task spec got wrong. NemoClaw is not OpenClaw-exclusive. It supports OpenClaw as the default agent. It also supports Hermes. It also supports LangChain Deep Agents Code. NVIDIA built a security layer that wraps multiple harnesses, not a moat for one.

This is the architectural split. Hermes keeps the control plane inside the agent. OpenClaw's ecosystem externalizes it. NemoClaw sits between your agent and the world, enforcing policy at the boundary. You can swap agents without rebuilding governance. You can also audit the boundary independently of the agent's internals.

I think this is the right model for regulated industries. Finance, legal, healthcare, public sector. Anywhere you need to prove to an auditor that the agent could not have touched what it touched.

The tradeoff is operational complexity. You are running a sandbox, a policy engine, a routing layer. The agent is no longer a single process you can strace. It is a system.

## The real comparison is layer, not product

Hermes and OpenClaw are not direct competitors. They are different layers of the same stack. The choice is not which features you want. The choice is where you want the control plane to live.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Hermes optimizes for the individual power user: fast, local, inspectable, self-contained. OpenClaw + NemoClaw optimizes for the governed enterprise: externalized security, portable policy, auditable boundaries. LangGraph leads enterprise adoption with 34.5M monthly downloads and production deployments at JPMorgan and Uber, proving the substrate model scales. The question is which layer you need today.</p></div>

LangChain's analysis of agent frameworks is useful here. Most frameworks are "just abstractions" with low floors and low ceilings. LangGraph positions itself as an orchestration substrate, a blend of declarative and imperative. It leads enterprise adoption with 34.5 million monthly downloads and roughly 400 production deployments, including JPMorgan and Uber.

Hermes is closer to the personal-assistant end. Its control plane is internal, optimized for one operator who wants speed and ownership. OpenClaw, especially with NemoClaw, is closer to the substrate end. Its control plane is external, optimized for organizations that need to govern multiple agents across multiple teams.

The task spec proposed "Kanban board with goal instructions" as a Hermes killer feature. The reality is more nuanced. Kanban exists. It is durable and multi-agent. But binding boards to projects is done via CLI and environment variables, not `/goal` instructions. Persistent Goals are a separate feature: a standing goal across turns. The spec conflated two things. The accurate version is still powerful: Hermes gives you durable, inspectable, multi-agent state that survives crashes and restarts.

The task spec also proposed "multi-harness extension ecosystem" as an OpenClaw killer feature. This is directionally right. OpenClaw's MIT license and foundation governance make it attractive as a base layer. NemoClaw, ClawHub, and other extensions compose on top. Hermes is more integrated. Its extensibility comes through skills, MCP, and subagents, not through a substrate model.

## What this means for you

If you are a junior AI engineer building your first serious agent workflow, this decision shapes your daily work more than model choice.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Pick Hermes if you are a solo builder or small team that values speed, local state, and inspectable multi-agent coordination. Pick OpenClaw + NemoClaw if you are in a regulated industry or need to prove agent behavior to auditors. Both support MCP, so your tool integrations are portable. The switching cost is not the tools. It is the mental model of where control lives.</p></div>

My take: start with Hermes if you are learning. The feedback loop is faster. You can see the Kanban board. You can read the skills. You can trace every decision. The control plane is transparent because it is internal.

Move to OpenClaw + NemoClaw when you hit the compliance wall. When your security team asks how you know the agent did not exfiltrate data, you need the external boundary. When your legal team asks for an audit trail, you need the sandbox logs. NemoClaw gives you that without forcing you to abandon your agent logic.

The good news is that MCP is common to both. Your tool integrations transfer. The bad news is that the mental model does not. Internal control plane thinking and external control plane thinking are different disciplines. I have seen teams struggle when they try to apply personal-assistant patterns to enterprise governance, or vice versa.

I don't know which architecture wins long term. The personal-assistant model has lower friction. The substrate model has lower risk. My guess is they converge: personal assistants will absorb security layers, and substrates will get easier to run. But that convergence is years away. The decision you make today is real.

In Ex Machina, Ava does not escape by outsmarting Caleb in conversation. She escapes by understanding the building's control systems. The test was never whether she was smart. The test was whether the room she was in was secure. Your agent is smart. The question is whether the room it runs in is one you control, or one someone else controls for you.
