On July 21, engineer Jonas Risbrandt summed up agentic coding [on LinkedIn](https://www.linkedin.com/posts/jonas-risbrandt-8309263_i-find-the-evolution-of-agentic-coding-slightly-activity-7485292345890865152-xymz):

> First, we talked about prompting.
>
> Then we realized one prompt was not enough, so we added loops.
>
> Then loops were not enough, so we introduced graphs.
>
> Now we are adding typed state, control flow, persistence, retries, error handling, observability, reusable components, and testing.

He followed it with a question: "Haven't we just invented... a programming language?"

Three days later, Anthropic [announced Claude Opus 5](https://www.anthropic.com/news/claude-opus-5). The company said an automated behavior audit before deployment found it to be its "most aligned model to date." The [Hacker News thread](https://news.ycombinator.com/item?id=49038433) drew over 1,700 points.

I think the timing exposed a gap. Opus 5 improved the model. Teams still have to control the facts carried through a long run. Jonas listed four features. In production, each wave inherits the fault line from the one before it.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Agent frameworks have moved through prompts, loops and graphs toward typed state. The model can improve while the production system still lacks a clear record of what the agent knew before it acted.</p></div>

## One article card, four waves

### Wave 1: the prompt carries the job

A prompt is the instruction sent to a language model. Our article card could begin with one large instruction:

```text
Research this article idea.
Write the draft and check every source.
Ask for human approval.
Publish the approved version.
```

This works for a demo. Incidents add more lines: keep the source URL, avoid an exact count, stop after repeated kickbacks. The prompt starts wearing a toolbelt, carrying policy and memory in prose. It can request a fact without giving the answer a field such as `sources_verified`.

### Wave 2: the loop keeps working

ReAct is short for reasoning and acting. The 2022 [ReAct paper](https://arxiv.org/abs/2210.03629) alternates a model's next step with an action and its result. Our pipeline might look like this:

```python
while card_status != "done":
    action = model.choose_next_action(messages)
    observation = run_tool(action)
    messages.append(observation)
    card_status = update_status(card_status, observation)
```

The loop gives the agent another chance. The message history now carries its state.

That failed on this article. The spec contained an exact Hacker News count. Fact-check changed it to "over 1,700," but a later revision pulled the stale number from old context. Both versions lived in the messages. I think this is where a useful loop turns into chat-log archaeology.

### Wave 3: the graph shows the route

A graph makes control flow visible. [LangGraph](https://docs.langchain.com/oss/python/langgraph/graph-api) is a Python framework for agent workflows. Its `StateGraph` connects steps, called nodes, through possible routes called edges.

```python
graph = StateGraph(MessagesState)
graph.add_node("research", research_node)
graph.add_node("draft", draft_node)
graph.add_node("fact_check", fact_check_node)
graph.add_conditional_edges("fact_check", route_by_verdict)
```

`MessagesState` is LangGraph's built-in state for conversation messages. The graph shows that fact-check can send the card forward or back to draft.

LangGraph supports shared schemas, including Pydantic models with runtime validation. When a team carries only messages or loose domain fields, the diagram shows which node ran while verified sources and approvals remain buried. A node may also contain its own prompt and loop.

### Wave 4: typed state names the facts

[`TypedDict`](https://docs.python.org/3/library/typing.html#typing.TypedDict) declares the keys and value types expected in a Python dictionary. `Literal` limits a value to fixed choices. A proposed, simplified contract for this pipeline looks like this:

```python
from datetime import datetime
from typing import Literal
from typing_extensions import TypedDict
from pydantic import TypeAdapter

class CardState(TypedDict):
    status: Literal[
        "research", "draft", "fact_check",
        "human_approval", "publish"
    ]
    draft_hash: str | None
    source_url: str
    source_checked_at: datetime | None
    sources_verified: bool
    approved_by: str | None
    trace_id: str
```

Type checkers inspect this shape before the program runs. Pydantic is a Python library that checks incoming values during the run. Here, strict mode keeps a string such as `"false"` from passing as a Boolean. A transition rule decides which move is legal, and persistence saves the accepted state.

```python
ALLOWED_TRANSITIONS = {
    "research": {"draft"},
    "draft": {"fact_check"},
    "fact_check": {"draft", "human_approval"},
    "human_approval": {"publish"},
}

def request_publish(raw_state: dict) -> CardState:
    state = TypeAdapter(CardState).validate_python(raw_state, strict=True)

    if "publish" not in ALLOWED_TRANSITIONS.get(state["status"], set()):
        raise IllegalTransition("status cannot move to publish")
    if not state["sources_verified"] or state["approved_by"] is None:
        raise IllegalTransition("publish requires verified sources and approval")

    save_transition(state["trace_id"], state["status"], "publish")
    return {**state, "status": "publish"}
```

The stale count can now be tied to a source record and check time. This proposed publish guard rejects unverified sources through a code path another engineer can test.

| Wave | Inspectable object | Failure exposed in the article pipeline |
|---|---|---|
| Prompt | Instruction text | A required fact has no declared field |
| Loop | Message history | A stale count returns from old context |
| Graph | Nodes and routes | Bad state crosses a clean edge |
| Typed state | Named facts and legal moves | An invalid publish request gets rejected |

I call this the State Contract Ladder. Each step makes a different part of the agent easier to inspect.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Prompts describe the job, loops repeat it, and graphs expose possible routes. Typed state adds named domain facts, while runtime checks and transition rules can stop a bad card at the publish boundary.</p></div>

## A useful contract has four parts

The proposed `CardState` needs static checks, runtime checks, transition rules and a saved record. Static types define the expected shape. Runtime validation checks the data that actually arrived.

Transition policy decides whether `human_approval` may move to `publish`. A persisted record keeps the before state, the after state and a trace ID.

I think typed state is the first wave in Jonas's sequence that exposes the failure below it. Types catch a string in a Boolean field. Source checks decide whether a claim is true. Each job can now fail loudly.

This pays down [Verification Debt](/posts/2026-03-09-verification-debt-crisis/). A reviewer can compare the declared fields with the payload carried during the run. Saved snapshots plus an implemented rollback or compensation path make [reversibility an architectural property](/posts/reversibility-is-the-new-correctness/) of the state machine.

Static type discipline reaches back to ML and Hindley-Milner work in the 1970s. Rails is a useful comparison from a dynamically typed stack. [Rails 1.0 shipped in 2005](https://rubyonrails.org/2005/12/13/rails-1-0-party-like-its-one-oh-oh), and [migrations](https://guides.rubyonrails.org/active_record_migrations.html) put database changes into versioned code. Typed state applies that review habit to facts moving through an agent run.

I don't know whether "typed state" will remain the label. [AgentKit](https://github.com/inngest/agent-kit), [MemState](https://github.com/scream4ik/MemState), [GraphFlow](https://github.com/a-agmon/rs-graph-llm) and [Agd](https://news.ycombinator.com/item?id=47224560) explore parts of the design in four languages. Four small projects support a hypothesis. They cannot prove adoption.

A one-shot classifier can stay simple. The contract earns its cost once an agent carries facts across steps or crosses a costly boundary.

I think the test is simple. Teams running long-lived agents with costly side effects will standardize state contracts at approval boundaries before they replace their orchestration framework again. If those teams scale safely with message history alone, this thesis is wrong.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>A state contract combines static shape, runtime validation, legal transition policy and a persisted trace. Type discipline catches structural errors, while source verification and tests still carry their own load.</p></div>

## Alignment needs a production record

Anthropic audited Opus 5 before deployment. A production article card keeps collecting state afterward.

A live agent receives tool output, edits drafts and reads old messages. Its state can drift while the base model behaves well in a lab.

The Voight-Kampff test in *Blade Runner* tells Deckard something about the subject in the chair. A production audit also needs door logs, tool receipts and a record of what entered each room.

I think "alignment theater" begins when a team cites the model audit while leaving the run impossible to rebuild. A clear [AI Operating Model](/posts/building-the-ai-operating-model/) assigns owners to state and costly transitions. The product team owns what the deployed system may remember and do.

For high-risk systems, Article 12 of the [EU AI Act](https://eur-lex.europa.eu/eli/reg/2024/1689/oj) requires automatic event logging. Article 26(6) requires deployers to retain logs under their control. Persisted state gives an engineering team a concrete record to inspect.

Several agents can share the same corrupt source status. A contract keeps that stale fact from crossing into approval as silently as it crossed between messages.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Predeployment model testing says little about the state built up during a live workflow. Production alignment requires owners, saved transitions and enough structured evidence to rebuild a costly decision.</p></div>

## Guard one costly transition on Monday

Start where a bad state can create an expensive side effect. For this pipeline, that boundary is `human_approval -> publish`. A finance agent may use `reviewed -> payment_sent`. The same mechanism works when customer service makes an account change final.

Write one small contract:

| Contract item | First version |
|---|---|
| Boundary | `human_approval -> publish` |
| Required state | `sources_verified`, `approved_by`, `draft_hash`, `trace_id` |
| Rejection behavior | Keep the prior state and write a rejection event |
| Success record | Save before and after state with the same trace ID |
| Ownership | Decision owner defines required facts; platform owner enforces and retains them; risk owner approves the boundary |
| Failure signal | Count invalid requests that reach the boundary and how many the guard rejects |

Keep the first sprint narrow. Inventory one workflow's fields, compare them with the actual payload, and guard its most costly move. Review schema changes like any other contract change.

My take is that junior engineers can lead this work. Write the type, add runtime validation, test an illegal transition and inspect the saved event. A larger model cannot do those jobs for you.

Jonas described the cycle this way: "We replaced the code with a prompt, and then slowly started reintroducing the code around the prompt."

I think the code is returning because uncertain model calls need reviewable boundaries. Once state lives in a contract, a team can argue about behavior in a pull request instead of a postmortem.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Choose one agent with a costly action and turn that boundary into a state contract. Before the action runs, another engineer should be able to inspect the state and stop the move.</p></div>
