AI engineering moves so quickly that each solution reveals the next problem. In a [July 2026 LinkedIn post](https://www.linkedin.com/posts/jonas-risbrandt-8309263_i-find-the-evolution-of-agentic-coding-slightly-activity-7485292345890865152-xymz), engineer Jonas Risbrandt described the progression:

> “Then we realized one prompt was not enough, so we added loops. Then loops were not enough, so we introduced graphs. Now we are adding typed state, control flow, persistence, retries, error handling, observability, reusable components, and testing.”

His punchline was, “Haven't we just invented... a programming language?” A day earlier, Anthropic, the AI company behind Claude, had [announced Claude Opus 5](https://www.anthropic.com/news/claude-opus-5), a language model for long-running agents. Anthropic said a pre-deployment behavioral audit found it to be “our most aligned model to date.” The Hacker News discussion, on a technology news forum, drew [over 1,700 upvotes](https://news.ycombinator.com/item?id=49038433). That shows attention, not production reliability.

I think the useful shift is typed, persisted state: a defined record of what an agent knows, what it may change, and where it may go next. Better model behavior cannot reconstruct a deployed system's state.

## Four architectures inside one content card

Our content engine runs eight specialist agents through Hermes CLI, a command-line agent runtime: `ideator`, `researcher`, `writer`, `slop-reviewer`, `fact-checker`, `persona-panel`, `visual-designer`, and `publisher`. In the `content_engine.tasks` table of a Postgres relational database, cards move through 12 statuses: `ideas_inbox`, `approved`, `research`, `draft`, `slop_review`, `fact_check`, `persona_panel`, `design`, `human_approval`, `publish`, `done`, and `escalated`.

The audit question is simple: what did the writer know at the state transition, the move into `slop_review`?

### Prompt

A prompt is the plain-language instruction sent to a language model:

```text
Research, draft, review, fact-check, design, approve, and publish.
Never use an exact Hacker News score.
```

Every incident adds another instruction. The prompt starts carrying the duties of a workflow, schema, and runbook without recording any of them.

### Loop

ReAct, short for Reason and Act, is a 2022 agent pattern that alternates model reasoning with tool calls:

```python
while card.status != "done":
    result = worker.act(messages)
    messages.append(result)
```

The message history becomes state. A fact-checker can replace a stale count with “over 1,700,” yet a later writer run may retrieve the old claim from the same history. Finding what the agent knew requires tracing the chat log by hand.

### Graph

[LangGraph](https://docs.langchain.com/oss/python/langgraph/graph-api) is a framework that expresses agent work as connected nodes and routes. Its `StateGraph` builder makes control flow visible:

```python
graph = StateGraph(MessagesState)
graph.add_node("draft", writer)
graph.add_node("fact_check", fact_checker)
graph.add_conditional_edges("fact_check", route_verdict)
```

`MessagesState` stores shared messages. LangGraph supports typed schemas, so it is not inherently untyped. Trouble remains when critical facts stay in free-form text, because a node can hide a loop carrying corrupted context.

### Typed state

A Python `TypedDict` declares the fields and types a dictionary should contain. Runtime validation, database constraints, and saved snapshots enforce that contract:

```python
class CardState(TypedDict):
    status: PipelineStatus
    brief_version: str
    writer_run_id: str
    claims: list[VerifiedClaim]
    sources_verified: bool

if next_status == "publish" and not state["sources_verified"]:
    raise IllegalTransition("unverified claims")
save_snapshot(state)
```

`PipelineStatus` is the 12-value set above, while `VerifiedClaim` stores claim text, source, and check result. The snapshot shows those inputs at the transition, and the guard stops unverified publication.

## Types create evidence, not truth

A valid field can still be false. Typed state does not make agents correct; it turns some silent corruption into loud rejection, preserves evidence, and lets retries start from a known snapshot.

This pays down verification debt: future checking work created when sources and approvals are not captured when they matter. Saved snapshots also make reversal a system property because an earlier state can be restored and replayed.

Static type systems have described allowed values and caught invalid combinations since the 1970s. Ruby on Rails, the web framework released as version 1.0 in December 2005, later made database changes easier to manage through explicit migrations and conventions. Typed state brings that craft to agent workflows.

Calling a model aligned while its production state cannot be reconstructed risks alignment theater: model-level evaluation presented as system-level assurance. For AI systems covered as high-risk, Articles 12 and 26(5) of the [European Union's 2024 AI Act](https://eur-lex.europa.eu/eli/reg/2024/1689/oj) require automatic event logs and retention by deployers. This pipeline is not necessarily high-risk, but a legible AI operating model still needs durable state.

<div class="chapter-tldr">
<span class="chapter-tldr__label">In short</span>
<p>Types cannot prove that an agent is right. They reduce verification debt by preserving evidence, rejecting defined illegal moves, and making recovery and accountability part of system design.</p>
</div>

The mapping is narrow: an agent retry becomes useful when it starts from a named state snapshot and records the next transition. Replaying an opaque message history produces another run, but no reliable account of what changed.

## Start with one transition on Monday

Choose one long-running agent and a consequential transition, such as `draft` to `slop_review`. Write its schema, save a boundary snapshot, add one illegal-transition test, and assign one engineer to own schema changes through code review. Bound the pilot to two engineers and two weeks, without a platform rewrite.

Repeat the audit question. If the team cannot show the brief, source claims, worker run, validation result, and status used at that boundary, the system still depends on informal state.

Risbrandt wrote, “We replaced the code with a prompt, and then slowly started reintroducing the code around the prompt.” I think that return is healthy. Keep the uncertain language task inside the model, but put state, transitions, and evidence under ordinary engineering discipline.

<div class="chapter-tldr">
<span class="chapter-tldr__label">In short</span>
<p>Run a bounded pilot around one consequential transition. If its inputs, validation result, owner, and resulting state survive inspection, typed state is becoming an operating practice rather than another framework feature.</p>
</div>
