On July 21, 2026, engineer [Jonas Risbrandt described the evolution of agentic coding](https://www.linkedin.com/posts/jonas-risbrandt-8309263_i-find-the-evolution-of-agentic-coding-slightly-activity-7485292345890865152-xymz). Agentic coding is software development in which an AI model can plan work and call tools instead of only answering a question.

> “Then we realized one prompt was not enough, so we added loops. Then loops were not enough, so we introduced graphs. Now we are adding typed state, control flow, persistence, retries, error handling, observability, reusable components, and testing.”

Risbrandt then asked, “Haven't we just invented... a programming language?” I think he named the pattern correctly, but typed state adds something more specific: an authority record. It can show which version, evidence, approval, and rule allowed uncertain model output to affect a live system.

Three days later, Anthropic, the company behind Claude, [announced its Claude Opus 5 model](https://www.anthropic.com/news/claude-opus-5) for long-running, multi-step work. Anthropic said a pre-deployment automated behavioral audit found it to be “our most aligned model to date.” The related [Hacker News discussion](https://news.ycombinator.com/item?id=49038433), on a technology forum, drew over 1,700 points. I think the timing exposes the gap: a model evaluation can describe behavior in a test, but it cannot prove which production facts authorized a later action.

## Four waves, one publication card

Follow one article card through research, drafting, factual review, human approval, and publication. Its Hacker News citation must remain “over 1,700 points.” The task history held an exact score, its correction, and the stale figure's return. Only the corrected, approved revision may publish.

### Prompt

A prompt gives a model work and constraints in natural-language prose.

```text
Research the card, write the article, verify every source,
and publish only the approved revision.
Use “over 1,700 points,” never an exact score.
```

“Approved revision” names no machine-checkable object. As retry and recovery rules accumulate, prose starts serving as schema, state machine, and runbook. The prompt is wearing a toolbelt it cannot reliably inventory.

### Loop

A loop lets the model act, inspect the result, and repeat until a stopping condition.

```python
while card.status not in {"done", "escalated"}:
    action = model.choose(message_history)
    result = tools.run(action)
    message_history.append(result)
```

The message history now acts as informal state: facts carried between steps. The stale score and its correction remain equally valid-looking messages, so a later pass can retrieve the wrong one without violating the loop. I think state corruption can look like progress until the external action occurs.

### Graph

A graph connects named workflow nodes with directed edges, exposing routes and kickbacks.

```text
research → draft → fact_check → human_approval → publish
             ↑          |
             └─ kickback┘
```

A failed fact check now has an explicit route. The graph still does not prove whether the next node received the corrected revision or an older message, and any node can contain another prompt or loop. Visible control flow does not make the state moving through it inspectable.

### Typed state

Typed state declares allowed fields and values; persistence stores the record beyond one model call. This illustrative boundary uses [Pydantic, a Python library that validates data at runtime](https://docs.pydantic.dev/latest/concepts/models/), inside a locked database transaction:

```python
class PublishState(BaseModel):
    model_config = ConfigDict(strict=True)
    card_id: str
    version: int
    status: Literal["fact_check", "human_approval", "publish"]
    revision_id: str
    content_hash: str
    fact_report_id: str | None
    sources_verified: bool
    approved_revision_id: str | None
    approved_content_hash: str | None
    approved_by: str | None

with transaction():
    current = PublishState.model_validate(lock_card(request.card_id))
    require(request.expected_version == current.version)
    require(current.status == "human_approval")
    require(current.sources_verified and current.fact_report_id is not None)
    require(current.revision_id == current.approved_revision_id)
    require(current.content_hash == current.approved_content_hash)
    write_publish_intent_once(request.idempotency_key, current)
    advance_if_version(current.card_id, current.version, "publish")
```

The schema declares expected fields; runtime validation rejects malformed values. A content hash fingerprints the draft. The expected-version check rejects a request whose version no longer matches the locked current record. The `require` statements are transition guards, rules that block a well-formed record from taking an unauthorized route.

`write_publish_intent_once` stores a durable outbox instruction for delivery after commit. Its idempotency key names one intent, so a matching retry does not create another. These checks do not prove the article true or make every destination retry-safe. They bind publication to one accepted revision, review, and approval. Invoice and access-provisioning agents need the same link among value, evidence, approver, and version.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Prompts express intent, loops repeat work, and graphs expose routes. Typed, persisted state adds a checked record that can reject stale, malformed, duplicate, or unauthorized publication attempts.</p></div>

## Why the fourth wave changes the boundary

Typed state does not require replacing graphs. [LangGraph, LangChain's framework for graph-based agent workflows](https://docs.langchain.com/oss/python/langgraph/graph-api), already supports shared state schemas. In March 2025, [Inngest's TypeScript AgentKit described a “fully typed state machine” used in routing](https://news.ycombinator.com/item?id=43426164). These examples show an architectural direction, not broad adoption.

Strong typing has no single universal definition. Here, typed state means a declared schema enforced at runtime and at the database transition boundary; Python annotations alone do not police inputs. Types cannot verify a source or choose an approver. They can turn a missing report, mismatched revision, or illegal transition into a loud rejection instead of silent corruption.

I think this gives typed state more weight than the next framework feature. Retries need to identify their starting state, observability needs stable fields, and persistence needs storage rules. The contract makes each control answerable against named facts.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>The fourth wave exposes the state that earlier waves carried informally. Its win is bounded but important: software can refuse an action whose evidence, version, or approval does not match.</p></div>

## What implicit state costs

An execution trace records which steps ran. It may show `human_approval` before `publish` while omitting which revision the person approved. When that link is absent, an incident review has to reconstruct authority from prompts, messages, and tool traces.

I call that gap verification debt: the distance between what a workflow assumes and what its records can prove. It can surface as a stale claim or, in invoice approval and access provisioning, as a corrupted field that consumes audit hours, delays a close, or stalls a useful pilot.

This is also where model alignment and system accountability separate. Anthropic's statement concerned behavior measured before deployment. It could not establish that a live request later carried current evidence and approval. My take is that alignment theater begins when a model evaluation is presented as proof that a production action had authority.

An AI Operating Model is the ownership, evidence, decisions, and controls around an AI system. It is legible when business defines a transition, engineering enforces it, and reviewers inspect accepted and rejected records. The [European Union's 2024 AI Act](https://eur-lex.europa.eu/eli/reg/2024/1689/oj) points in this direction without prescribing typed state. For high-risk systems in scope, Article 12 requires automatic event recording, while Article 26(6) requires deployers to retain generated logs under their control. A publishing workflow is not automatically high risk, but a version-linked rejection is stronger audit evidence than a transcript containing the right sentence somewhere.

Typed state also clarifies reversibility: a return to an earlier accepted version or a named correction after an external effect. Versioned records support replay, and idempotency can prevent a duplicate intent, but neither can unsend an email or reverse a completed payment. The state machine needs an explicit compensation path. Shared memory across several agents also needs an owner, a version, and allowed transitions, or the same verification debt returns at a larger scale.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Activity logs show what ran, while authority records show which facts and approval allowed it to run. Without that link, verification debt grows across incidents, audits, and attempts to scale a pilot.</p></div>

## Put the contract into review

Type discipline is old. Computer scientist Robin Milner's [1978 paper “A theory of type polymorphism in programming”](https://doi.org/10.1016/0022-0000%2878%2990014-4) presented a formal discipline and compile-time checking algorithm for polymorphic procedures. The craft is to declare valid forms and reject invalid combinations before action.

[Ruby on Rails 1.0, a web-application framework released in December 2005](https://rubyonrails.org/2005/12/13/rails-1-0-party-like-its-one-oh-oh), included database migrations. Rails defines a [migration as a reproducible database-schema change](https://guides.rubyonrails.org/active_record_migrations.html), with each migration acting like a new version. I think the relevant craft move was making structural assumptions reviewable. Typed state applies that discipline to facts carried toward an external action.

On Monday morning, ask the enterprise architect and system owner to convene a 30-minute review with the engineering lead. Choose one write-capable agent and one consequential transition. Name its version, required evidence, approving role, retention rule, and one forbidden move. The business owner accepts the rule; engineering owns enforcement.

Then give a small team a two-week pilot rather than a platform rewrite. Persist both acceptance and rejection, and test the boundary before changing the wider architecture:

```text
stale approved revision → rejection, no publish intent
current approved revision → one publish intent
retry with the same key → existing intent, no second record
```

Run the incident review from persisted state alone. If the team cannot explain what was accepted, which guard decided, and what followed, it has found verification debt it can fix. This is how a pilot earns production ownership instead of remaining a demonstration.

I don't know which agent framework will dominate. Risbrandt's sharper line was, “We replaced the code with a prompt, and then slowly started reintroducing the code around the prompt.” I think the state contract will endure because it can survive changes in models and orchestration. The next agent wave begins when a team can show, in software, why an uncertain model was allowed to act.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Review one consequential transition as a software contract, test its refusal paths, and demand an incident explanation from persisted state. Craft discipline is back when authority becomes executable.</p></div>
