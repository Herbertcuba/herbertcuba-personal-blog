On July 21, [Jonas Risbrandt wrote on LinkedIn](https://www.linkedin.com/posts/jonas-risbrandt-8309263_i-find-the-evolution-of-agentic-coding-slightly-activity-7485292345890865152-xymz) about the path from prompting to loops and graphs. He then wrote:

> Now we are adding typed state, control flow, persistence, retries, error handling, observability, reusable components, and testing.

His punchline was better: "Haven't we just invented... a programming language?"

Three days later, [Anthropic launched Claude Opus 5](https://www.anthropic.com/news/claude-opus-5) and said an automated pre-deployment behavioral audit found it to be the company's "most aligned model to date." The [Hacker News thread](https://news.ycombinator.com/item?id=49038433) drew over 1,700 points.

I think the timing captured our engineering problem. Production teams still struggled to answer what the agent believed when it acted. I don't know whether "typed state" will remain the label. Long-running agents still need smaller loops around a working record people and code can inspect.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Jonas's sequence names the missing object: a structured record of what an agent knows and which action is legal next.</p></div>

## Four waves inside one publishing pipeline

Take a pipeline that researches an article, drafts it, checks the claims, and publishes after approval.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>The first three waves can leave state inside prose or chat history. Typed state puts it behind validation and transition rules.</p></div>

### Prompt

The first version looks wonderfully small:

```text
Research, draft, fact-check, and publish after approval.
Use "over 1,700" for a changing Hacker News score.
```

Each incident adds another sentence. Source policy and workflow status collect in one instruction. I think teams first confuse instruction with state here.

### Loop

Then comes a ReAct-style cycle, named for reasoning and acting:

```python
while card.status != "done":
    result = run_agent(card.history)
    card.history.append(result)
```

Its working record is the transcript. Here, an HN score began as 1,723, was corrected to "over 1,700," then returned from stale context during revision. No field rejected the old value.

### Graph

A graph exposes the route:

```text
research -> draft -> fact_check -> human_approval -> publish
                     | fail
                     +-------> draft
```

We can see where work goes, while each node still carries its own payload. [LangGraph supports shared state schemas](https://docs.langchain.com/oss/python/langgraph/graph-api), so typed state fits the graph model. Enforcement remains an engineering choice.

### Typed state

The fourth version declares evidence. A small contract for the publish boundary looks like this:

```python
class Evidence(BaseModel):
    display: Literal["over 1,700"]
    source_url: HttpUrl
    checked_at: datetime

class CardState(BaseModel):
    status: Literal["fact_check", "human_approval", "publish"]
    hn_score: Evidence
    sources_verified: StrictBool
    approved_by: str | None

def transition(state: CardState, to: str):
    if to == "publish" and (
        state.status != "human_approval"
        or not state.sources_verified
        or state.approved_by is None
    ):
        raise IllegalTransition
```

The model defines shape, Pydantic validates writes, policy guards transitions, and persisted records retain evidence. A schema alone cannot do all four jobs.

## We are rebuilding an old discipline

Static type discipline reaches back to ML and Hindley-Milner work in the 1970s.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Types give uncertain model output a shape that ordinary software can validate and review.</p></div>

[Rails 1.0 shipped in 2005](https://rubyonrails.org/2005/12/13/rails-1-0-party-like-its-one-oh-oh) with migrations that put database schema changes into versioned code. Ruby is dynamic. The useful Rails lesson is that schema changes became reviewable.

[Inngest's AgentKit](https://github.com/inngest/agent-kit) describes routing through a fully typed state machine. LangGraph accepts shared schemas. These are signals from builders without proving broad adoption.

I think Jonas's joke works because we removed ordinary software to discover what models could do, then rebuilt contracts around the unreliable semantic function.

## A model audit cannot see production state

Anthropic scoped its Opus 5 claim to pre-deployment testing, before a production agent receives tools and stored records.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Pre-deployment testing measures model behavior. Production accountability also needs the evidence and approval state behind an action.</p></div>

That agent's state can change before it publishes an article, approves a refund, or updates a finance system.

In *Blade Runner*, the Voight-Kampff test measures a subject during an interview. It gives Deckard no ledger of every door the subject opens afterward. A behavioral audit has a similar boundary.

I think alignment theater begins when a team presents a model audit as control for a workflow it cannot replay. This is where [verification debt](/posts/2026-03-09-verification-debt-crisis/) becomes operational: the team cannot reconstruct the claim behind the action. An [AI Operating Model](/posts/building-the-ai-operating-model/) needs that reconstruction. Persisted transitions support [reversibility](/posts/reversibility-is-the-new-correctness/) because the team can restore the last accepted state and run the decision again.

## Guard one boundary on Monday

Start with one long-running agent that has delegated authority or a costly side effect.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Define the state required for one consequential transition, then reject the action when evidence is missing.</p></div>

List every field the agent carries into that boundary. Compare the list with the stored payload. Give the decision owner responsibility for evidence, the platform owner responsibility for validation and retention, and the risk owner authority over the transition.

A one-shot classifier may need none of this. The thesis fails if ordinary logs can reproduce every decision made by a long-running agent with delegated authority. My bet is that teams will standardize state contracts at approval boundaries before replacing their orchestration framework again.

Jonas described the direction precisely: "We replaced the code with a prompt, and then slowly started reintroducing the code around the prompt." Start with the code around the transition that can cost you. Make the system produce its evidence before the action runs.
