On July 21, engineer Jonas Risbrandt [described agentic coding](https://www.linkedin.com/posts/jonas-risbrandt-8309263_i-find-the-evolution-of-agentic-coding-slightly-activity-7485292345890865152-xymz) moving from prompts to loops, then graphs, and now “typed state, control flow, persistence, retries, error handling, observability, reusable components, and testing.” His punchline was sharper: “Haven't we just invented... a programming language?”

Three days later, Anthropic [introduced Claude Opus 5](https://www.anthropic.com/news/claude-opus-5) and said a pre-deployment behavioral audit found it to be “our most aligned model to date.” The [Hacker News discussion](https://news.ycombinator.com/item?id=49038433) drew over 1,700 upvotes. I think the juxtaposition captures the fault line. Better model behavior still leaves production trust to the machinery around the model.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Better models expand what agents can attempt. Typed state determines whether teams can inspect, recover, and authorize their actions.</p></div>

## Four waves in one publishing job

Take one article. A **prompt** is the instruction handed to the model. The first version puts the whole job into prose:

```text
Research, draft, fact-check, get approval, then publish.
For HN scores, use a durable phrase such as “over 1,700.”
```

Incidents add more sentences. The prompt starts carrying policy, workflow, and recovery rules in one block. It becomes a prompt wearing a toolbelt.

A **loop** repeats reasoning and action until the model declares the job complete. ReAct means Reason and Act:

```python
while card.status != "done":
    result = agent(card.history)
    card.history.append(result)
```

The loop can retry and call tools, but its state is often the entire chat history. In this article's pipeline, a stale exact HN score survived beside the corrected phrase, then returned during a later revision. Both values remained in the transcript, with no field declaring which one had been accepted.

A **graph** makes control flow visible through nodes and edges:

```text
research -> draft -> fact_check -> approval -> publish
               ^        |
               + kickback
```

The graph exposes order. A draft node can still run a loop over stale history, leaving corruption hidden inside the node. LangGraph already [supports shared state schemas](https://docs.langchain.com/oss/python/langgraph/graph-api); the engineering step is to enforce the schema at every boundary.

**Typed state** defines the allowed fields and values for the persisted job record:

```python
class CardState(TypedDict):
    status: Literal["draft", "fact_check", "approval", "publish"]
    accepted_hn_claim: str
    approved_revision: str | None
    sources_verified: bool
```

A **transition** is a checked move between statuses. Publication fails when revision 8 carries approval for revision 7, or when `sources_verified` is false. The accepted transition writes the new state and an **outbox** item, a pending side effect, in one database commit. An **idempotency key** uniquely names that publication, preventing a retry from publishing the approved revision twice.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Prompts hold instructions, loops accumulate history, and graphs expose order. Typed state records accepted facts and blocks an unauthorized transition.</p></div>

## Typed state changes the engineering

Types leave model accuracy unchanged; they turn silent corruption into rejected writes. I think that is why typed state carries more weight than another framework feature. Jonas put it precisely: “We replaced the code with a prompt, and then slowly started reintroducing the code around the prompt.” Persistence, retries, observability, and testing can now inspect one record.

Rails made a similar craft move in 2005. Schemas and migrations, meaning versioned changes to a data contract, made web state operable across releases. Software has used type discipline since the 1970s, and agent systems are rediscovering it. [Inngest AgentKit](https://github.com/inngest/agent-kit) described fully typed state routing in 2025, while LangGraph documents schemas inside graph workflows. I don't know which framework will dominate. I think the convergence toward explicit state is clear.

The distinction sharpens the alignment debate. Anthropic's audit is useful evidence about model behavior under controlled conditions. In *Blade Runner* terms, it resembles a Voight-Kampff test before deployment. A production incident asks which evidence and approval caused the live action.

That answer belongs in the operating model. A trace shows execution history; accepted state shows authority. This pays down verification debt because reviewers can see the gap between what the agent carried and what policy allowed. Reversibility also becomes a property of the state machine because the previous accepted record remains available for recovery. For high-risk AI systems, the [EU AI Act](https://eur-lex.europa.eu/eli/reg/2024/1689/oj) points in the same direction through event logging and deployer retention duties.

I think alignment theater begins when confidence in a model substitutes for evidence about a deployed action. At enterprise scale, that gap becomes incident-review time, delayed approvals, and an owner unable to reconstruct the decision.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Typed state improves auditability rather than model truth. It gives retries, reviews, retention, and recovery one persisted account of what the system accepted.</p></div>

## Put one boundary under contract

Start Monday with a 30-minute review of one consequential move, such as `approval -> publish`. Record the accepted evidence, decision owner, retention and access rule, and exact illegal transition. “Revision 8 cannot publish with approval for revision 7” is specific enough to test.

Give one named engineer two weeks to encode the schema, persisted transition, outbox, and idempotency key. Crash the worker after the database commit and before the publishing API returns. On retry, the record should recover the authorized action while the key suppresses a duplicate.

A one-shot classifier may need no durable state. A long-running agent with external side effects carries a different burden. I think approval-boundary state contracts will be normal by July 2027. If design reviews still accept chat transcripts as the recovery plan, that prediction has failed.

The next agent wave begins when the authorized next action survives the crash.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Choose one consequential transition, encode its evidence and authority, then prove through a crash-and-retry test that the authorized action remains recoverable and duplicate-safe.</p></div>
