[Engineer Jonas Risbrandt recently described agentic coding](https://www.linkedin.com/posts/jonas-risbrandt-8309263_i-find-the-evolution-of-agentic-coding-slightly-activity-7485292345890865152-xymz) as a progression from prompting to loops, then graphs, followed by “typed state, control flow, persistence, retries, error handling, observability, reusable components, and testing.” He asked, “Haven't we just invented... a programming language?”

Around the same time, [Anthropic said](https://www.anthropic.com/news/claude-opus-5) its pre-deployment audit found Claude Opus 5 to be its “most aligned model to date.” The [Hacker News discussion](https://news.ycombinator.com/item?id=49038433) drew over 1,700 points. I think both events expose the same fault line: stronger models can improve behavior, while production control still depends on small loops around inspectable state.

Earlier waves buried each new failure inside the next abstraction. Typed state records what the system accepted and why.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>The next agent gain comes from making evidence and authority inspectable in workflow state.</p></div>

## Four waves through one publishing card

Follow one publishing card from research through human approval. The task stays fixed as its architecture changes.

### Prompt

A prompt puts the workflow and safeguards into natural language:

```text
Research, draft, fact-check, request approval, then publish.
Describe the changing HN score as “over 1,700 points.”
```

Incidents add sentences until the prompt carries policy and recovery advice, becoming a prompt wearing a toolbelt.

### Loop

A loop repeats model reasoning and tool use. [ReAct](https://arxiv.org/abs/2210.03629) means reasoning and acting:

```python
for step in agent.iterate(card.history):
    card.history.append(step)
```

If an early message contains an exact score and fact-check later accepts the durable wording above, both versions survive in history. A revision can revive stale copy. I think the loop has memory without a declared accepted version.

### Graph

A graph names work as nodes and routes as edges:

```text
research -> draft -> fact_check -> human_approval -> publish
                    ^       |
                    | revise|
```

The route is visible, yet each node can hide a loop and transcript. [LangGraph supports shared state schemas](https://docs.langchain.com/oss/python/langgraph/graph-api); the engineering decision is whether teams enforce one at the publication boundary.

### Typed state

Typed state gives important values a declared shape. A transition moves between named states under an explicit rule:

```python
class Claim(BaseModel):
    text: str
    source_url: HttpUrl
    observed_value: int
    checked_at: datetime
    verifier_id: str
    accepted_revision: int

class PublishState(BaseModel):
    status: Literal["fact_check", "human_approval", "publish"]
    draft_revision: int
    claim: Claim
    approval_record_id: UUID
    owner: str
    retain_until: date
    version: int


def publish(s: PublishState, transition_id: UUID):
    guards.require(s.status == "human_approval", "approval required")
    guards.require(s.claim.accepted_revision == s.draft_revision,
                   "stale evidence")
    facts.verify(s.claim)
    approvals.verify(s.approval_record_id, s.draft_revision)
    accepted = state_store.save(s.model_copy(
        update={"status": "publish", "version": s.version + 1}
    ))
    return publisher.put_once(transition_id, accepted)
```

Validation rejects data that fails the declared shape before the transition runs. The fact service checks whether the source supports the sentence, while the approval service authenticates the reviewer. I think types earn their place by making missing or mismatched proof rejectable, without pretending to make a claim true.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Prompts describe the job, loops accumulate history, and graphs expose routing. Typed state makes the accepted claim and evidence explicit alongside approval and the legal next move.</p></div>

## Why the state record changes control

Suppose publication succeeds and the worker crashes before acknowledging it. Persistence means the accepted record survives after the process stops. A retry carries the same transition ID, so `put_once` returns the existing result; this is idempotency, the rule that a retry cannot publish twice. Durable workflow history records completed steps so execution can resume, while typed state records the data and authority accepted at the boundary. Observability uses traces and metrics to show what ran.

Strong type discipline reaches back to [ML research in the 1970s](https://doi.org/10.1016/0022-0000(78)90014-4). [Rails 1.0 arrived in 2005](https://rubyonrails.org/2005/12/13/rails-1-0-party-like-its-one-oh-oh), and [Rails migrations](https://guides.rubyonrails.org/active_record_migrations.html) made durable database changes explicit and versioned. Their mechanism differs from strong typing, yet the craft move is shared: hidden assumptions become reviewable code. [AgentKit described fully typed state-machine routing in 2025](https://news.ycombinator.com/item?id=43426164), before Jonas named the pattern. I think agent systems are rediscovering this discipline around uncertain model outputs.

Anthropic’s claim concerns model behavior under pre-deployment testing. Production authorization asks which evidence, approval, and state version allowed an action. In *Blade Runner*, a Voight-Kampff test examines a subject under controlled conditions, while a flight recorder would preserve what happened after departure. Using the test as the production record is the narrow form of alignment theater worth rejecting.

A legible [AI Operating Model](/posts/building-the-ai-operating-model/) names the owner, access rules, retention period, and recovery path for consequential transitions. When the record cannot reproduce an accepted action’s evidence, [verification debt](/posts/2026-03-09-verification-debt-crisis/) stays hidden. To support [reversibility](/posts/reversibility-is-the-new-correctness/), add a typed withdrawal transition that references the stored published version. [EU AI Act Articles 12 and 26(6)](https://eur-lex.europa.eu/eli/reg/2024/1689/oj) require event logging and deployer retention for high-risk systems. The publishing example does not establish that those duties apply to a content pipeline.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Persisted, versioned state connects safe retries with audit retrieval, clear ownership, and recovery without confusing structural validation with factual verification.</p></div>

## Test one boundary on Monday

A one-shot classifier with no lasting side effect may need ordinary logs only. Start with a long-running agent crossing a consequential boundary such as publication, refund, or release.

Run a 30-minute design review around four fields: evidence, owner, retention and access, and illegal transition. Give two engineers two weeks to guard one action, then test whether its state can be retrieved during an incident. Procurement can ask whether a vendor exports accepted state and approval history.

I don't know whether “typed state” will remain the label. I think state contracts at consequential approval boundaries will become a normal production artifact by July 2027, before most teams replace their orchestration framework. The prediction fails if ordinary traces consistently reproduce the authorized state change, its evidence, and accepted version without such a contract.

Jonas wrote, “We replaced the code with a prompt, and then slowly started reintroducing the code around the prompt.” An agent system becomes accountable when that code sits at the boundary where authority becomes action.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Choose one consequential transition, assign its owner and evidence rules, retain the accepted record, and make retries or reversals explicit.</p></div>
