AI engineering is evolving so quickly that each abstraction soon exposes a limit. On July 25, 2026, engineer [Jonas Risbrandt](https://www.linkedin.com/posts/jonas-risbrandt-8309263_i-find-the-evolution-of-agentic-coding-slightly-activity-7485292345890865152-xymz) described the progression:

> “Then we realized one prompt was not enough, so we added loops. Then loops were not enough, so we introduced graphs. Now we are adding typed state, control flow, persistence, retries, error handling, observability, reusable components, and testing.”

His question was: “Haven't we just invented... a programming language?” The previous day, AI developer Anthropic had [announced its Claude Opus 5 model](https://www.anthropic.com/news/claude-opus-5) as its “most aligned model to date.” That meant closer adherence to its behavioral rules in pre-deployment tests. Its thread on technology forum [Hacker News](https://news.ycombinator.com/item?id=49038433) drew over 1,700 upvotes.

Typed state declares the data an agent may carry and the changes a system accepts. I think this inspectable boundary is the important shift around the model.

## Begin with the state you need to prove

Our content engine moves an article through 12 statuses: `ideas_inbox`, `approved`, `research`, `draft`, `slop_review`, `fact_check`, `persona_panel`, `design`, `human_approval`, `publish`, `done`, and `escalated`. Its Hermes CLI command-line workers run eight roles: ideator, researcher, writer, slop-reviewer, fact-checker, persona-panel, visual-designer, and publisher. Postgres, a relational database, stores each article card in `content_engine.tasks`.

Ask what the writer knew when it moved a card into `slop_review`, the prose-quality gate. This article’s task history records a stale, exact Hacker News score returning after fact-checking set the durable wording “over 1,700.” A transcript holds both versions as messages. Typed state can preserve the brief version, source record, claim policy, and transition time as separate fields.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>If one transition requires chat-log archaeology, the operating model is not auditable.</p></div>

## Four designs for the same article

A **prompt** is a natural-language instruction treated as the program:

```text
Research, draft, review, fact-check, and publish this article.
Never publish an unverified source.
```

Incidents add instructions until the prompt carries policy and recovery rules without a reliable checkpoint.

A **loop** repeats model reasoning and tool use:

```python
while not done:
    action = model(context)
    context.append(run(action))
```

The 2022 ReAct pattern, short for “reason plus act,” popularized this approach. State is often smuggled through a growing message history, where stale context can displace a correction.

A **graph** names steps and allowed routes. [LangGraph](https://docs.langchain.com/oss/python/langgraph/graph-api), a library for agent workflows, provides a `StateGraph` builder:

```python
g = StateGraph(MessagesState)  # shared message history
g.add_edge("draft", "slop_review")
g.add_conditional_edges("fact_check", route_by_verdict)
```

The graph exposes control flow, yet a node may still hide a prompt and loop. LangGraph supports custom typed schemas, so the gap concerns production enforcement rather than a missing feature.

With **typed state**, the payload crossing a route becomes a contract:

```python
class TaskState(TypedDict):
    status: Status          # one of the 12 values above
    brief_version: int
    sources_verified: bool
    hn_claim: Literal["over 1,700"]

if target == "publish" and not state["sources_verified"]:
    raise IllegalTransition()
```

Python’s `TypedDict` declares required fields for static checking; `Literal` narrows an allowed value. Runtime validation and Postgres constraints must still reject bad writes. The publish guard then stops a stale claim at the boundary.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Prompts describe intent, loops repeat work, graphs expose routes, and typed state checks what crosses them.</p></div>

## A type changes the failure mode

Types cannot prove a source true. They make malformed state fail loudly and preserve snapshots around accepted transitions. Verification debt, the gap between a claim and its evidence, becomes visible in fields such as `brief_version` and `sources_verified`. Stored snapshots let a team restore a known state, making reversibility an engineered property.

This is why model-layer alignment is insufficient. Anthropic audited Opus 5 before deployment. When a team cannot reconstruct the production context around an action, that claim becomes alignment theater at the system layer.

The craft move is old. Ruby on Rails, the web framework released as version 1.0 in December 2005, made database changes manageable through migrations: schema changes became versioned code that teams could review and reverse. Software has used type discipline since the 1970s. Independent agent projects across five implementation languages arrived at typed state during 2025 and 2026, evidence of direction rather than adoption.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Typed state buys loud failure, traceable evidence, and rollback; correctness still requires verification.</p></div>

## Make one transition boring by Monday

Start with `draft → slop_review`. Store the brief version, source IDs, claim policy, draft version, and worker identity in Postgres. Give one engineer ownership of the schema and review changes as an API contract. Run a two-engineer, two-week trial without rewriting the platform.

The trial passes when an on-call engineer can query the transition and state what the writer knew without rereading its conversation. Test the rejection of missing evidence and restoration of the previous snapshot. The operating model becomes legible, and verification debt becomes work the team can see.

Jonas wrote, “We replaced the code with a prompt, and then slowly started reintroducing the code around the prompt.” Reintroducing that discipline lets teams give agents more consequential work without surrendering the record of how it was done.
