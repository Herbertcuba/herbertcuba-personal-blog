AI engineering is changing faster than its production habits. On July 25, 2026, engineer [Jonas Risbrandt](https://www.linkedin.com/posts/jonas-risbrandt-8309263_i-find-the-evolution-of-agentic-coding-slightly-activity-7485292345890865152-xymz) described the sequence:

> “Then we realized one prompt was not enough, so we added loops. Then loops were not enough, so we introduced graphs. Now we are adding typed state, control flow, persistence, retries, error handling, observability, reusable components, and testing.”

His question was: “Haven’t we just invented... a programming language?” Each wave extended what agents could do while concealing another production failure.

A day earlier, AI lab Anthropic [introduced its Claude Opus 5 language model](https://www.anthropic.com/news/claude-opus-5) and said a pre-deployment behavioral audit found it to be the company’s “most aligned model to date.” The discussion on [Hacker News](https://news.ycombinator.com/item?id=49038433), a technology forum, drew over 1,700 upvotes, showing attention rather than endorsement. Yet model alignment cannot tell a CTO what an agent knew when it changed a production record. Typed state can make that answer inspectable.

## One audit question across four waves

Use the content engine behind this article as the running example. Hermes CLI, a command-line agent runner, coordinates ideator, researcher, writer, slop-reviewer, fact-checker, persona-panel, visual-designer, and publisher workers. Postgres, an open-source relational database, stores cards in `content_engine.tasks` across `ideas_inbox`, `approved`, `research`, `draft`, `slop_review`, `fact_check`, `persona_panel`, `design`, `human_approval`, `publish`, `done`, and `escalated`.

The audit question is: what did the writer know when it moved a card to `slop_review`?

### Prompt

A prompt is an instruction sent to a language model. The first system puts the workflow inside one instruction:

```text
Research → draft → review → fact-check → publish.
```

Incident fixes then accumulate beside tools and exceptions. Even “use ‘over 1,700,’ never an exact Hacker News score” becomes part of a prompt acting as program, schema, and runbook.

### Loop

ReAct, a 2022 method whose name means Reason plus Act, lets a model choose an action, inspect the result, and repeat:

```python
while status != "done":
    context.append(run(model(context)))
```

The growing message history becomes state. If a fact-checker corrects a stale score while an earlier message retains it, both values remain available. Answering the audit question now means reading the transcript by hand.

### Graph

[LangGraph](https://docs.langchain.com/oss/python/langgraph/graph-api), a framework for agent workflows, uses `StateGraph` to connect processing nodes. Its convenient `MessagesState` schema centers shared state on message history:

```python
graph = StateGraph(MessagesState)
graph.add_conditional_edges("fact_check", route_by_verdict)
```

The graph exposes routes, but nodes can still contain prompts, loops, and critical values in messages. LangGraph supports custom typed schemas; teams gain control only by enforcing them at every boundary.

### Typed state

Typed state defines the fields and allowed values an agent may carry. Python’s `TypedDict` declares that shape for developer tools; runtime validation and database constraints must enforce it on write.

```python
class CardState(TypedDict):
    status: CardStatus          # only the 12 states above
    brief_version: str
    sources_verified: bool
    hn_claim: Literal["over 1,700"]
    draft_sha256: str

state = validate(candidate)     # illustrative pseudocode
if target == "publish" and not state["sources_verified"]:
    raise IllegalTransition
persist_snapshot(state)
```

The `slop_review` transition now stores an immutable snapshot of the brief version, source status, approved claim, and draft hash. Types cannot prove a claim true, but they turn malformed state and illegal transitions into visible failures before another agent inherits them.

## The type is the control boundary

Between March 2025 and July 2026, independent agent projects in TypeScript, Rust, Python, and Zig converged on typed state or persisted transitions. This revives type discipline used in software since the 1970s.

Ruby on Rails 1.0, the web framework released in December 2005, was dynamically typed, but versioned database migrations made stored changes explicit and reproducible. Agent systems need that operational discipline around model context.

Transition history makes an [AI operating model](/posts/building-the-ai-operating-model/) inspectable. The gap between required and recorded state exposes [verification debt](/posts/2026-03-09-verification-debt-crisis/), the unverified output later work depends on. Preserved snapshots make [reversibility](/posts/reversibility-is-the-new-correctness/) a system property because operators can restore the last valid state.

The European Union’s [AI Act, Regulation 2024/1689](https://eur-lex.europa.eu/eli/reg/2024/1689/oj), requires automatic event logging for high-risk AI systems under Article 12. Obligations for the high-risk uses listed in Annex III began applying on August 2, 2026. This content engine is not automatically high-risk, but the direction is clear. Auditing a model before deployment while leaving its production state unreadable is alignment theater.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Explicit, versioned state connects software discipline to operating control, verification, and reversibility.</p></div>

The mapping is limited: coherent behavior reveals little about reliability until operators can inspect the state carried between actions. Typed snapshots provide that record without pretending an agent has become predictable.

## A Monday test

Choose one long-running agent and one consequential transition. Define its fields, allowed values, and required evidence. Persist the before-and-after states in Postgres, add one runtime guard, and replay a failed run. Assign a schema owner and reviewer. Two engineers can test this in two weeks without replacing the platform.

A model that labels one input and exits may not need durable state. An agent that publishes, pays, approves, or changes customer data does. Ask what it knew when it acted without opening the chat log. If the record cannot answer, the system still carries verification debt.

Risbrandt called agent frameworks “programming languages for orchestrating unreliable semantic functions.” His description matters because the semantic function may be new, while the engineering discipline around it has decades of proof.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Start with one risky transition, persist its typed state, enforce one guard, and test whether the record can explain and reverse a real decision.</p></div>
