On July 21, [engineer Jonas Risbrandt described the evolution of agentic coding](https://www.linkedin.com/posts/jonas-risbrandt-8309263_i-find-the-evolution-of-agentic-coding-slightly-activity-7485292345890865152-xymz):

> First, we talked about prompting.
>
> Then we realized one prompt was not enough, so we added loops.
>
> Then loops were not enough, so we introduced graphs.
>
> Now we are adding typed state, control flow, persistence, retries, error handling, observability, reusable components, and testing.

His punchline was, “Haven't we just invented... a programming language?”

Three days later, [Anthropic launched Claude Opus 5](https://www.anthropic.com/news/claude-opus-5), saying a pre-deployment audit found it the company’s “most aligned model to date.” The [Hacker News discussion](https://news.ycombinator.com/item?id=49038433) drew over 1,700 points.

I think the timing reveals the fault line. Better model behavior still leaves teams unable to reconstruct an agent’s production action. I don't know whether typed state will remain the label, but long-running agents need smaller loops around inspectable state.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Model alignment describes behavior before deployment. Typed state records the evidence and authority behind an action in production.</p></div>

## Four waves inside one publishing pipeline

Consider a pipeline that researches an article, drafts it, checks its claims, and publishes after human approval.

### Prompt

The first version puts the workflow in one instruction:

```text
Research, draft, fact-check, and publish after approval.
Use “over 1,700 points” for the changing HN score.
```

Each incident adds a sentence until the prompt carries policy, status, and volatile facts. It becomes a prompt wearing a toolbelt.

### Loop

A [ReAct loop](https://arxiv.org/abs/2210.03629), short for reasoning and acting, gives the model another turn after each tool result:

```python
while card.status != "done":
    result = agent(card.history)
    card.history.append(result)
```

The transcript becomes state. During this article’s production cycle, an exact HN score was corrected, then returned from stale context. No field rejected it. I think autonomy generates [verification debt](/posts/2026-03-09-verification-debt-crisis/) here because history holds several versions but cannot declare which one governs the next action.

### Graph

A graph exposes the route:

```text
research -> draft -> fact_check -> human_approval -> publish
                       fail -> draft
```

The route is visible, while each node may still carry an informal transcript. [LangGraph supports shared state schemas](https://docs.langchain.com/oss/python/langgraph/graph-api), so the capability exists. Enforcement remains an engineering choice.

### Typed state

A simplified typed contract defines the allowed shape of every important value and the rule for moving forward:

```python
class CardState(BaseModel):
    status: Literal["fact_check", "human_approval", "publish"]
    publish_text: Literal["over 1,700 points"]
    source_url: HttpUrl
    sources_verified: StrictBool
    approved_by: str | None
    transition_id: UUID


def publish(s: CardState):
    if s.status == "human_approval" and s.sources_verified and s.approved_by:
        return store.put_once(
            s.transition_id, s.model_copy(update={"status": "publish"})
        )
    raise IllegalTransition
```

Pydantic validates writes at runtime. The transition rejects missing evidence or approval; `put_once` lets the same ID write once. Fact-checking still decides truth. The contract makes missing proof or an illegal move fail loudly.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>The same publishing job evolves from prose, to transcript history, to visible routing, and finally to a validated state contract at the publish boundary.</p></div>

## The old discipline inside the new stack

Typed state is special because retries and observability need a stable object. A trace shows what ran; the contract shows what the system accepted. Durable execution owns scheduling and recovery; the state contract owns legal data and transitions.

[Strong type discipline reaches back to the 1970s](https://doi.org/10.1016/0022-0000(78)90014-4). [Rails 1.0 arrived in 2005](https://rubyonrails.org/2005/12/13/rails-1-0-party-like-its-one-oh-oh) and made database schema changes reproducible and reviewable in dynamic Ruby. My take is that agent systems repeat the craft move by making state explicit and its changes controlled.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Typed state gives retries and recovery one accepted record instead of competing transcript versions.</p></div>

## Production authority needs its own evidence

Anthropic’s Opus 5 claim is scoped to a model before deployment. Once an agent receives tools and stored context, the workflow creates a separate control problem. In a science-fiction ship, the simulator tests the onboard intelligence; the flight recorder preserves which command opened the airlock during the mission.

I think alignment theater begins when a model audit is presented as control for an unreplayable production action. An [AI Operating Model](/posts/building-the-ai-operating-model/) attaches ownership and retention to each consequential transition. That record pays down verification debt because evidence travels with the decision. Preserving the last accepted state makes [reversibility](/posts/reversibility-is-the-new-correctness/) a property of the workflow.

[EU AI Act](https://eur-lex.europa.eu/eli/reg/2024/1689/oj) Articles 12 and 26(6) point in the same direction through logging and retention duties for high-risk systems. This publishing example sits outside that claim.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>A pre-deployment model audit cannot reconstruct a production action. Consequential workflows need retained state linking evidence to authority and recovery.</p></div>

## Review one costly boundary on Monday

Ordinary logs may cover a one-shot classifier with no lasting side effect. Start with a long-running agent crossing a costly boundary.

In a 30-minute design review, put four fields on one page: required evidence, owner, retention and access, and an illegal transition. Give two engineers two weeks to put that contract around one action. Procurement can then ask whether a vendor exports the state record with its approval.

I think state contracts at approval boundaries will become a normal production artifact by July 2027, before most orchestration rewrites. That prediction fails if ordinary traces can consistently reproduce authorized state and evidence for long-running agents.

Jonas wrote, “We replaced the code with a prompt, and then slowly started reintroducing the code around the prompt.” Put that code around the boundary that can cost you. When an agent can act with delegated authority, that authority belongs in a state contract people can inspect and use to reverse the transition.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Define the state that authorizes one consequential action, then retain enough evidence to replay or reverse the transition.</p></div>
