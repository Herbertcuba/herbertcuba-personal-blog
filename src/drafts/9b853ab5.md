On July 21, engineer Jonas Risbrandt [described the evolution of agentic coding](https://www.linkedin.com/posts/jonas-risbrandt-8309263_i-find-the-evolution-of-agentic-coding-slightly-activity-7485292345890865152-xymz): “Then we realized one prompt was not enough, so we added loops. Then loops were not enough, so we introduced graphs. Now we are adding typed state, control flow, persistence, retries, error handling, observability, reusable components, and testing.” Each wave looked like a feature. Each exposed a fault line.

Jonas asked, “Haven't we just invented... a programming language?” On July 24, Anthropic [announced Claude Opus 5](https://www.anthropic.com/news/claude-opus-5) and said a pre-deployment audit found “our most aligned model to date.” Its [Hacker News discussion](https://news.ycombinator.com/item?id=49038433) drew over 1,700 points, which shows attention. The engineering claim rests elsewhere: a model can improve in evaluation while a production workflow still lacks a durable record of accepted evidence and authority. I think typed state answers that separate problem.

## Four waves through one publishing job

Use this article as the example. An early revision froze a live HN count. Fact-checking approved a later revision with “over 1,700 points” and the source URL, yet another pass reloaded the frozen wording. This is a revision conflict, so `approved_revision` must govern publication.

**Prompt.** A prompt is an instruction sent to a model:

```text
Research, draft, fact-check, approve, publish.
Use the approved HN wording.
```

Incident rules accumulate until the prompt is wearing a toolbelt. No field enforces the approved revision.

**Loop.** A loop repeats model reasoning and tool use until a stopping condition:

```python
while status != "done":
    result = agent.run(messages)
    messages.append(tool(result))
```

Raw tool traces can hold both revisions, while execution history records their order. Neither identifies authority. I think larger context only lengthens the search.

**Graph.** A graph names workflow steps and the routes between them:

```text
research -> draft -> fact_check -> approval -> publish
               ^          |
               +----------+  kickback
```

The route is visible, though a node may still loop over conflicting messages. [LangGraph](https://docs.langchain.com/oss/python/langgraph/graph-api) supports shared schemas. The engineering step is enforcing them at writes and transitions.

**Typed state.** Typed state is a persisted record with named fields, allowed values, and checked transitions:

```python
Evidence = {source_url, checked_at, points: Int > 1700,
            publish_text: "over 1,700 points"}
ArticleState = {revision, approved_revision, approved_by,
                status, version, evidence, effect_id}

publish(s):
    require s.revision == s.approved_revision and s.approved_by
    commit(status="publish", outbox_once=s.revision)
```

The threshold agrees with the wording and runs when tool output becomes accepted evidence. Source review records provenance and acceptance; people still judge credibility. The outbox is a durable send record committed with state. Its idempotency key makes retries deliver once, while `effect_id` links accepted state to the result.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Prompts and loops mix evidence, while typed state makes the approved revision enforceable.</p></div>

## Why typed state changes the boundary

Four records often collapse into one log, although they answer different questions. Raw tool traces may conflict, while execution history shows which workers ran. Accepted state identifies the evidence and approval that govern the next move; an effect record links that authority to the result.

A durable workflow engine owns history and retry position; the typed contract owns business authority. I think recovery needs both because replaying corrupted state reproduces the incident. Types guarantee shape and allowed movement, while people judge credibility.

Strong type discipline reaches back to the 1970s. Rails 1.0 migrations made database schema changes versioned and repeatable in 2005. Agent-state contracts apply that lifecycle discipline to delegated work. Inngest AgentKit describes typed routing, while MemState validates memory on write. These are design signals; adoption remains unproven. I don't know which framework will dominate.

The gap between declared policy and carried state is [verification debt](https://cubagarcia.com/posts/2026-03-09-verification-debt-crisis/). Stored versions and effects make [reversibility](https://cubagarcia.com/posts/reversibility-is-the-new-correctness/) testable.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Execution history explains the run; typed state explains its authority.</p></div>

## Logs without authority create false confidence

Prompts accumulate rules, loops accumulate conflicts, and graphs can hide both behind tidy routes. Logs still may not explain why one revision crossed the publish boundary.

Anthropic's Opus 5 claim covers pre-deployment model behavior. It cannot reconstruct a production approval or effect. I think alignment theater begins when evaluation substitutes for accepted state.

Think of the pod-bay door in *2001: A Space Odyssey*. A transcript preserves HAL's words. An inspectable record pairs the accepted command and authority with the door's movement, supplying the missing link between conversation and accountability.

For high-risk AI systems, Article 12 of the [EU AI Act](https://eur-lex.europa.eu/eli/reg/2024/1689/oj) requires event logging, while Article 26(6) requires deployer log retention. Applicability depends on the system and role. A legible [AI Operating Model](https://cubagarcia.com/posts/building-the-ai-operating-model/) needs an owner who can retrieve accepted state during an incident.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Model evaluations can coexist with production actions that nobody can reconstruct.</p></div>

## Put one boundary under contract on Monday

A one-shot classifier with no external effect may need little durable state. Choose one consequential transition and run a 30-minute review. The one-page result has four fields:

- **Evidence:** Which accepted record authorizes the move?
- **Owner:** Who approves the contract and this action?
- **Retention and access:** Who can retrieve the record, and for how long?
- **Illegal transition:** Which condition blocks the action?

Give two engineers two weeks to persist the contract and crash-test delivery. An unapproved revision must fail; an approved retry must create one retrievable effect.

My take is that teams running consequential agents will standardize state contracts at approval boundaries by July 2027. The prediction fails if raw traces and execution history alone can consistently reproduce the authorized revision and its delivered effect during incident drills.

Jonas ended with the sharper line: “We replaced the code with a prompt, and then slowly started reintroducing the code around the prompt.” A consequential agent earns trust when that returning code explains why its action was allowed after the worker forgets everything.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Persist one consequential transition, then prove recovery produces one approved effect.</p></div>
