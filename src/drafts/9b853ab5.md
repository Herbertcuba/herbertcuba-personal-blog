AI engineering changes so quickly that every new abstraction can look final. On July 25, 2026, engineer [Jonas Risbrandt described the sequence](https://www.linkedin.com/posts/jonas-risbrandt-8309263_i-find-the-evolution-of-agentic-coding-slightly-activity-7485292345890865152-xymz): “Then we realized one prompt was not enough, so we added loops. Then loops were not enough, so we introduced graphs. Now we are adding typed state, control flow, persistence, retries, error handling, observability, reusable components, and testing.”

His punchline was sharper: “We replaced the code with a prompt, and then slowly started reintroducing the code around the prompt.” Each wave increased capability while revealing a failure the previous design could not express cleanly.

The previous day, AI company Anthropic announced [Claude Opus 5](https://www.anthropic.com/news/claude-opus-5), its new top-end language model, as its “most aligned model to date” based on tests before deployment. The related [Hacker News discussion](https://news.ycombinator.com/item?id=49038433), on a technology forum popular with software practitioners, drew over 1,700 upvotes. Yet a model test cannot tell a CTO what an agent knew when it changed a production record.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Better model behavior matters, but production accountability begins with a durable answer to what the agent knew when it acted.</p></div>

## Follow one content card through the four waves

Consider a content engine where Hermes CLI, a command-line agent runner, executes eight workers: ideator, researcher, writer, slop-reviewer, fact-checker, persona-panel, visual-designer, and publisher. Postgres, a relational database, stores cards in `content_engine.tasks` across twelve statuses: `ideas_inbox`, `approved`, `research`, `draft`, `slop_review`, `fact_check`, `persona_panel`, `design`, `human_approval`, `publish`, `done`, and `escalated`.

### Prompt

A prompt is a natural-language instruction sent to a model. The first version compresses the system into prose:

```text
Research, draft, review, fact-check, then publish.
Ask a human when uncertain.
```

Incidents add instructions until the prompt is wearing a toolbelt: workflow, policy, memory, and exceptions. It still cannot prove which rule shaped an action.

### Loop

A loop lets the model use a tool, inspect the result, and repeat. ReAct, short for Reason and Act, is a 2022 pattern built around this cycle:

```python
while card.status != "done":
    history.append(worker.run(history))
```

The message history becomes the state, the information carried between steps. If a stale exact Hacker News score survives after fact-check approves “over 1,700,” a later pass can restore it. Auditing the writer’s knowledge now requires reconstructing a transcript.

### Graph

A graph names the steps and their allowed routes:

```text
research → draft → slop_review → fact_check
             ↑                      │
             └────── kickback ──────┘
```

[LangGraph](https://docs.langchain.com/oss/python/langgraph/graph-api), a library for stateful agent workflows, calls this a `StateGraph`. It supports shared typed schemas, so graphs are not inherently untyped. A node can still contain the loop and prompt above; implementations that carry chat messages or free-form dictionaries expose the route while hiding the evidence entering each node.

### Typed state

Typed state gives each relevant field a name and an allowed shape. Python’s `TypedDict` describes that shape for type-checking; runtime validation and database constraints must enforce it.

```python
class CardState(TypedDict):
    status: CardStatus  # one of the twelve values above
    brief_version: str
    evidence_version: str
    sources_verified: bool

if next_status == "publish" and not state["sources_verified"]:
    raise IllegalTransition("unverified sources")
```

Persist a snapshot at every transition and the audit answer becomes specific: at `slop_review`, the writer had a named brief, one evidence version, and `sources_verified = false`. Types do not make the draft correct. They turn silent corruption into a rejected or traceable change.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Prompts hold instructions, loops accumulate history, and graphs expose routes. Typed, persisted state exposes the facts carried across those routes and can reject an illegal transition.</p></div>

## The old discipline creates the new control point

Strong typing requires values to match declared kinds before software relies on them, a discipline used since at least the 1970s. Rails 1.0, the 2005 web framework release, made a related move with explicit database schemas and repeatable migrations. Rails uses the dynamically typed Ruby language; the connection is state made named, versioned, and reviewable.

Independent agent projects in TypeScript, Python, Rust, and Zig added typed, validated, or reversible state during 2025 and 2026. This indicates architectural convergence, not broad adoption.

I think typed state matters because it makes Risbrandt’s other additions accountable. Retries can restart from known snapshots, logs can record named fields, and [reversibility becomes an architectural property](/posts/reversibility-is-the-new-correctness/). The gap between the intended schema and the evidence carried is [verification debt made visible](/posts/2026-03-09-verification-debt-crisis/).

Anthropic’s alignment audit describes behavior before deployment; it cannot reconstruct a production run. Treating the former as the latter becomes alignment theater. The [European Union’s 2024 AI Act](https://eur-lex.europa.eu/eli/reg/2024/1689/oj) points the same way: Article 12 requires automatic event logging for high-risk AI systems, while Article 26(5) requires deployers to retain logs under their control. An inspectable [AI operating model](/posts/building-the-ai-operating-model/), the roles and controls around agent work, needs records that explain state, not merely route.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Typed state applies established software discipline to agent work, giving retries, logs, reviews, and rollback a shared record instead of asking a prompt to carry accountability.</p></div>

## What to do on Monday

A one-shot classifier may not need durable state. Start with one long-running agent that can publish, book, pay, or change the outside world. Define the facts it must know, the allowed statuses, and one transition that must fail when evidence is missing.

Give the schema one engineering owner. Keep the current model and framework, store a snapshot at each boundary in Postgres, and review schema changes like API changes. Two engineers can test one workflow in two weeks without rebuilding the platform.

Then ask what the agent knew when it acted. A transcript search means state remains part of the risk. A validated record lets the team improve models without surrendering control of the surrounding system.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Choose one consequential agent, persist its typed state, enforce one illegal transition, and test whether the team can reconstruct an action from records rather than chat history.</p></div>
