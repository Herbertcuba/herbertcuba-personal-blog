On July 21, [engineer Jonas Risbrandt described agentic coding](https://www.linkedin.com/posts/jonas-risbrandt-8309263_i-find-the-evolution-of-agentic-coding-slightly-activity-7485292345890865152-xymz): “Then we realized one prompt was not enough, so we added loops. Then loops were not enough, so we introduced graphs. Now we are adding typed state…” He then asked, “Haven't we just invented... a programming language?”

Three days later, [Anthropic said](https://www.anthropic.com/news/claude-opus-5) its pre-deployment behavioral audit found Claude Opus 5 to be its “most aligned model to date.” The [Hacker News discussion](https://news.ycombinator.com/item?id=49038433) drew over 1,700 points. A stronger response still leaves a team unable to prove which source, accepted revision, and human approval authorized a publish after a retry or crash.

That missing record connects the stories. Each wave looked like a feature. Each exposed a fault line below it.

## Four waves through one publishing card

A publishing card is the job record carrying a draft, evidence, approval, and status. Follow one card describing a changing Hacker News score.

A **prompt** makes natural language the program:

```text
Research, draft, fact-check, request approval, then publish.
Describe the HN score as “over 1,700 points.”
```

Each incident adds an instruction until the prompt carries policy. It becomes a prompt wearing a toolbelt.

A **loop** repeats reasoning and acting, the pattern commonly called ReAct:

```python
while card.open:
    card.history += agent.run(card.history)
```

Every retry receives the full transcript. The obsolete exact score remains beside the accepted wording, so a later revision can select stale text when the card lacks an `accepted_revision` field.

A **graph** names the route:

```text
research -> draft -> fact_check -> human_approval -> publish
                       ^-- revision --|
```

The roads are visible while each node can still hide a loop and transcript. [LangGraph supports shared state schemas](https://docs.langchain.com/oss/python/langgraph/graph-api); a team can also leave accepted evidence implicit in message history.

**Typed state** declares one valid record at the boundary:

```python
PendingPublish(
  revision=7,
  claim=VerifiedClaim(text="over 1,700 points", source_url=HN_URL),
  approval=Approval(revision=7, reviewer_id="u42"),
  idempotency_key="card-42-r7",
  result=None,
)
```

`DraftState` carries no approval. `PendingPublish` requires a verified claim and matching approval. One database transaction stores the record with an outbox event, a queued side effect. The publisher uses the key once and saves the result; after a crash, the retry resumes it. I think types earn their place by rejecting an illegal transition while the source checker remains responsible for truth.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>The fourth wave moves the accepted claim, source, approval, and pending action outside the transcript.</p></div>

## Why typed state changes the engineering

Typed state gives Jonas's other disciplines a shared object: retries resume an accepted record, error handlers receive declared failures, and tests assert legal transitions.

Durable workflow history says which steps completed and supports resumption. Typed state says which values and authority the system accepts now. Traces say how one execution behaved. A workflow engine can own history while the application schema owns state.

Rails 1.0 made schema changes reproducible through versioned migrations in 2005. Ruby remained dynamic, so the analogy concerns reviewable state evolution. Strong type discipline reaches back to ML work in the 1970s; LangGraph schemas and [AgentKit's typed routing](https://news.ycombinator.com/item?id=43426164) already apply it to agents. I think the wave begins when teams enforce it around lasting side effects.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>History supports resumption, traces explain execution, and typed state governs the next action.</p></div>

## The cost of informal state

Informal state turns larger context into more archaeology because accepted facts remain mixed with obsolete ones.

Anthropic's audit and a production record answer different questions. In *Blade Runner*, the Voight-Kampff test examines behavior under controlled conditions; a flight recorder preserves what happened after takeoff. I think alignment theater begins when a pre-deployment test is presented as evidence for a production action nobody can replay.

A legible [AI Operating Model](/posts/building-the-ai-operating-model/) assigns an owner, access rules, retention, and a reversible transition. [Verification debt](/posts/2026-03-09-verification-debt-crisis/) is the gap between action and proof; accepted state makes it visible. For high-risk systems, [EU AI Act Articles 12 and 26(6)](https://eur-lex.europa.eu/eli/reg/2024/1689/oj) require event logging and deployer retention. A one-shot classifier with no lasting side effect can carry a lighter control burden.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Consequential actions need replayable state, a named owner, controlled access, retention, and reversal.</p></div>

## Start with one boundary on Monday

Run a 30-minute design review around one consequential transition. Record four fields: accepted evidence, decision owner, retention and access, and the illegal transition the machine must reject. For a vendor-hosted agent, require an exportable accepted record.

Give two engineers two weeks to define state variants, a pending outbox entry, and an idempotency key. Kill the worker between database commit and side effect. The retry should execute once and leave the accepted revision for incident review.

I don't know whether “typed state” will remain the label. I think approval-boundary state contracts will become normal by July 2027, before most teams replace their orchestration framework. The prediction fails if traces alone reproduce the authorized transition, accepted evidence, revision, and retry result after a crash.

Jonas wrote, “We replaced the code with a prompt, and then slowly started reintroducing the code around the prompt.” Typed state gives delegated authority a record engineers can inspect and reverse.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>A two-week boundary test should produce one retained action, one retry key, and a recovery record.</p></div>
