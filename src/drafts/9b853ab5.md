AI engineering is evolving so quickly that each new abstraction feels permanent for about six months. On July 25, 2026, engineer [Jonas Risbrandt](https://www.linkedin.com/posts/jonas-risbrandt-8309263_i-find-the-evolution-of-agentic-coding-slightly-activity-7485292345890865152-xymz) described the sequence: “First, we talked about prompting. Then we realized one prompt was not enough, so we added loops. Then loops were not enough, so we introduced graphs. Now we are adding typed state, control flow, persistence, retries, error handling, observability, reusable components, and testing.” Then he asked: “Haven't we just invented... a programming language?”

A day earlier, Anthropic [introduced Claude Opus 5](https://www.anthropic.com/news/claude-opus-5) and called it its “most aligned model to date” based on a pre-deployment behavioral audit. The [Hacker News discussion](https://news.ycombinator.com/item?id=49038433) drew over 1,700 upvotes, a sign of attention rather than agreement. Yet a model audit cannot tell an engineering team what a deployed agent knew when it acted. Typed state can connect that action to inspectable evidence.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Better model behavior does not create production accountability. Inspectable state connects an agent's action to the information behind it.</p></div>

## One content card, four architectures

Consider a content engine whose ideator, researcher, writer, slop-reviewer, fact-checker, persona-panel, visual-designer, and publisher run as Hermes CLI workers, meaning command-line agent processes. They update tasks in `content_engine.tasks`, a table in the Postgres relational database.

**Prompt.** A prompt is a natural-language instruction sent to a model.

```text
Research the idea, draft it, review it, fact-check it, then publish it.
```

Every incident adds another instruction until the prompt is wearing a toolbelt: policy, workflow, and memory carried in prose. The current stage and verified facts remain implicit.

**Loop.** ReAct, short for Reason and Act, is a 2022 agent pattern that alternates model reasoning with tool use.

```python
while status != "done":
    context.append(run(model(context)))
```

The loop keeps working by treating message history as state. In this article's task, fact-checking replaced a drifting Hacker News score with “over 1,700”; stale context could later restore an exact figure. Reconstructing what the writer believed at `slop_review` requires digging through the chat log.

**Graph.** LangGraph, LangChain's graph-based agent framework, uses `StateGraph` to connect work nodes around shared state.

```text
research -> draft -> slop_review -> fact_check -> publish
```

The graph reveals routes and kickbacks. A node can still hide a loop whose prompt reads a loose `MessagesState`, LangGraph's message-history container. LangGraph permits typed schemas, so teams already have the capability. The important choice is enforcing it.

**Typed state.** A state machine defines allowed statuses and transitions. Python's `TypedDict` tells development tools which fields and types a dictionary should contain.

```python
Status = Literal["ideas_inbox", "approved", "research", "draft",
 "slop_review", "fact_check", "persona_panel", "design",
 "human_approval", "publish", "done", "escalated"]
class Card(TypedDict):
    status: Status
    draft_sha: str
    verified_draft_sha: str | None

if to == "publish" and card["draft_sha"] != card["verified_draft_sha"]:
    raise IllegalTransition
```

`TypedDict` does not validate data while the program runs. A runtime validator and Postgres constraints must reject bad writes and persist each snapshot. The audit answer then becomes concrete: the writer moved the card with brief version X, source snapshot Y, and an unverified draft hash.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Prompts carry instructions, loops carry history, and graphs carry routes. Typed, persisted state records what crossed each boundary.</p></div>

## The type is the control boundary

Types do not make an agent correct. They make some failures loud. A false claim can fit a `str` field, but a changed draft cannot inherit an old fact-check approval when the schema binds approval to the draft hash.

This boundary makes the rest of Risbrandt's list useful. Retries can restart from a known snapshot, tests can target legal transitions, and observability can report named fields instead of dumping conversations. Without structured snapshots, “aligned” risks becoming theater: careful model evaluation paired with a production system nobody can reconstruct.

Ruby on Rails 1.0, the web framework released in December 2005, used versioned database migrations to make schema changes explicit. Rails made web state legible. Typed state can do the same for agent state by applying a software discipline that predates the current AI cycle by decades.

The consequence reaches the [AI operating model](/posts/building-the-ai-operating-model/). When an agent enters a high-risk domain, Article 12 of the European Union's 2024 AI Act points in the same direction by requiring systems to support automatic event logs. Governance cannot be legible while agent state remains implicit.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Typed state cannot guarantee truth. It links validation, approval, retry, and audit to the exact version of work an agent handled.</p></div>

The mapping to agent systems is narrow: observing an output is weaker than seeing the state and constraints that produced it. Typed state gives operators somewhere concrete to look before a hidden conflict becomes an incident.

## Start with one consequential transition

A one-shot classifier may not need durable state. A content pipeline that can publish an unverified claim does.

On Monday, choose one consequential transition, such as `human_approval` to `publish`. Give one engineer ownership of its schema, set a two-engineer and two-week limit, persist the input snapshot and validation result, and make the database reject incomplete records. This is a boundary repair, not a platform rewrite.

Compare the schema with what the agent actually carries. That gap is [verification debt](/posts/2026-03-09-verification-debt-crisis/) made visible. Keep the previous valid snapshot, and [reversibility](/posts/reversibility-is-the-new-correctness/) becomes a system property rather than a hopeful instruction.

Risbrandt closed with the sharper summary: “We replaced the code with a prompt, and then slowly started reintroducing the code around the prompt.” The useful code is the part that can tell us what happened.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Make one consequential transition typed, persisted, owned, and rejectable. Expand only after that boundary produces evidence.</p></div>
