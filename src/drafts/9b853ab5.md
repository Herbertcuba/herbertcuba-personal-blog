On July 21, engineer Jonas Risbrandt wrote in [a LinkedIn post](https://www.linkedin.com/posts/jonas-risbrandt-8309263_i-find-the-evolution-of-agentic-coding-slightly-activity-7485292345890865152-xymz) that agentic coding moved from prompts to loops, then graphs, and now “typed state, control flow, persistence, retries ... and testing.” He asked, “Haven't we just invented... a programming language?” Each wave looked like a feature and exposed a fault line below.

Three days later, Anthropic [introduced Claude Opus 5](https://www.anthropic.com/news/claude-opus-5) and said a pre-deployment audit found “our most aligned model to date.” The [Hacker News thread](https://news.ycombinator.com/item?id=49038433) drew over 1,700 upvotes. I think the connection is direct: model evaluation covers pre-release behavior; production state records a live action's evidence and authority.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Better model behavior expands what agents can attempt. Typed state records an agent's accepted evidence, authority, and action.</p></div>

## Four waves in one publishing job

This article's task carried an exact Hacker News score. Research replaced it with “over 1,700,” then a later revision restored the stale integer from older context. Review history documents the failure.

### Prompt

The first version puts workflow and policy into one instruction:

```text
research -> draft -> fact_check -> human_approval -> publish -> done
Publish the HN claim as “over 1,700.”
```

Incidents add rules until the prompt wears a toolbelt. The accepted score still has no field or version.

### Loop

The pipeline then repeats reasoning and action until `done`. ReAct means Reason and Act:

```python
while status != "done":
    step = agent.run(status=status, history=history)
    history.append(step)
    status = step.next_status
```

Both wordings can coexist in history. I think the fault line appears when execution succeeds with the wrong belief.

### Graph

Next, the route becomes nodes and edges:

```text
research -> draft -> fact_check -> human_approval -> publish -> done
               ^        |
               +--------+  kickback
```

The graph exposes order, though a node may run a loop over mixed history. [LangGraph supports shared schemas](https://docs.langchain.com/oss/python/langgraph/graph-api); production must enforce one at every boundary.

### Typed state

The fourth version puts accepted values into named fields. Pydantic validates raw tool output before publication:

```python
class Evidence(BaseModel):
    revision_id: str
    text: str
    source_url: str
    verified: bool

class Card(BaseModel):
    status: Literal["research", "draft", "fact_check", "human_approval", "publish", "done"]
    revision_id: str
    approved_revision_id: str | None
    approved_by: str | None
    evidence: list[Evidence]
    idempotency_key: str
    version: int

def move_to_publish(raw: dict) -> Card:
    state = Card.model_validate(raw, strict=True)
    if state.status != "human_approval":
        raise IllegalTransition("approval state required")
    if state.approved_revision_id != state.revision_id or state.approved_by is None:
        raise IllegalTransition("current revision lacks approval")
    if not state.evidence or any(e.revision_id != state.revision_id or not e.verified
                                 for e in state.evidence):
        raise IllegalTransition("current revision has unverified evidence")
    return state.model_copy(update={"status": "publish", "version": state.version + 1})
```

`TypedDict` documents shape for static checking. Runtime rejection requires the validator above. A valid transition and an outbox item, the pending publish action, commit together:

```python
with db.transaction():
    current = Card.model_validate(db.lock(card_id), strict=True)
    next_state = move_to_publish(current.model_dump())
    db.replace(next_state, expected_version=current.version)
    db.outbox_once(next_state.idempotency_key, next_state.revision_id)
```

Version checking blocks stale writes; the unique key suppresses a crash duplicate. Model accuracy stays where it was. Unsupported evidence is rejected before the side effect commits.

## Typed state makes failure inspectable

I think typed state carries weight because retries, tests, and observability can refer to one accepted record. Durable workflow systems preserve activities and retry positions; typed agent state carries facts and authority. A replay can repeat stale evidence. I don't know which framework will dominate, but [AgentKit](https://github.com/inngest/agent-kit) and [GraphFlow](https://github.com/a-agmon/rs-graph-llm) show the direction across languages.

Rails 1.0 made a comparable move in 2005 by putting database changes into version-controlled migrations. Teams could add an approval column and backfill old records before new code used it. Type discipline reaches back through [Hindley-Milner work in the 1970s](https://doi.org/10.1016/0022-0000(78)90014-4). Agent engineering is applying it to state produced by unreliable models.

That discipline clarifies the Opus 5 control boundary. In *Blade Runner* terms, its audit is a Voight-Kampff test before the replicant walks into the city. Live review asks whether someone can reconstruct the accepted evidence, authorized transition, and side effect without replaying chat history. When a team cites model evaluation and cannot answer, I think “alignment theater” is fair.

That test belongs in the [AI Operating Model](https://cubagarcia.com/posts/building-the-ai-operating-model/). The record needs an owner, a retention period, and incident access. Procurement should require vendors to export both state and evidence. Its absence creates [verification debt](https://cubagarcia.com/posts/2026-03-09-verification-debt-crisis/); version history supports [reversibility](https://cubagarcia.com/posts/reversibility-is-the-new-correctness/) through a corrective transition. For high-risk systems, the [EU AI Act](https://eur-lex.europa.eu/eli/reg/2024/1689/oj) requires event logging and deployer log retention.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Execution history shows how work ran. Typed agent state shows which evidence and authority the system accepted, giving audits and recovery a stable contract.</p></div>

## Put one boundary under contract

A one-shot classifier without persisted authority or an external side effect may need little durable state. Start with a long-running agent that retries after a crash and changes the outside world.

Book a 30-minute review of one transition and write four fields into the repository:

- `Evidence`: required source-backed values for the current revision.
- `Owner`: the person authorized to approve it.
- `Retention`: storage duration and incident access.
- `Illegal transition`: the exact condition that blocks action.

Give two engineers two weeks to add validation, a versioned write, an outbox, and an idempotency key. Reject stale approval in tests, then crash after a valid commit and confirm recovery sends one publication.

Jonas wrote, “We replaced the code with a prompt, and then slowly started reintroducing the code around the prompt.” My take is that approval-boundary contracts will be normal by July 2027. That prediction fails if traces alone recover consequential actions and pass incident review consistently. Shared memory is the next fault line when agents act on different versions.

I think the next agent wave begins when an authorized action can survive a crash and still explain itself.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Choose one consequential transition, define its evidence, owner, retention, and rejection rule, then prove the accepted action remains recoverable and duplicate-safe after a crash.</p></div>
