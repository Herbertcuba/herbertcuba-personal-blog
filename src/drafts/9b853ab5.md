On July 21, 2026, an engineer named Jonas Risbrandt [described on LinkedIn](https://www.linkedin.com/posts/jonas-risbrandt-8309263_i-find-the-evolution-of-agentic-coding-slightly-activity-7485292345890865152-xymz) how agentic coding, software work delegated to tool-using AI systems, moved from prompts to loops, then graphs, and finally typed state. "Haven't we just invented... a programming language?" he asked. "We replaced the code with a prompt, and then slowly started reintroducing the code around the prompt."

Three days later, AI company Anthropic [announced Claude Opus 5](https://www.anthropic.com/news/claude-opus-5), a model for long-running agents, and said an automated behavioral audit during pre-deployment testing found it to be "our most aligned model to date." Here, aligned meant better results against Anthropic's own safety and behavior criteria, including its written Constitution and tests for deception or misuse. The [Hacker News discussion](https://news.ycombinator.com/item?id=49038433), a thread on a practitioner forum where members vote stories up, drew over 1,700 points.

I think the two events belong together, because public attention centered on model capability while framework builders moved reliability into explicit state. Each wave expanded what agents could do and buried a new failure deeper. Typed state gives that failure a field, a rule, and a retained outcome.

## Follow one publishing card through four architectures

Consider the card for this article. An early revision used an exact Hacker News score, which kept changing as members voted. A reviewer approved a later revision that said "over 1,700," while a paused worker still held the stale draft. Its publish attempt should fail.

A **prompt** is an instruction sent to a model:

```text
Research card-42, verify every claim, request approval, then publish.
```

That prompt authorizes tools and states a policy, but stores no accepted revision. The worker can still submit stale text, and nothing in the instruction can stop it.

A **loop** asks the model for another action and appends each result to history, the pattern popularized in 2022 by ReAct, a method that interleaves model reasoning with tool actions:

```python
while card.open:
    result = agent.run(history)
    history.append(result)
```

Both revisions and the approval now sit in one growing transcript. A retry has no checked field naming the governing revision, so a stale number can leave the spec, get fixed in review, and reappear from history on the next pass. A larger context window merely increases the history the worker must search.

A **graph** names steps as nodes and routes as edges:

```text
draft -> fact_check -> human_approval -> publish
  ^            |
  +--- revise -+
```

The route is visible, yet the `publish` node may retry the old payload. [LangGraph](https://docs.langchain.com/oss/python/langgraph/graph-api), a Python toolkit for graph-based agent workflows, already permits shared typed schemas. The remaining step is an engineering choice: validate writes and enforce transitions.

**Typed state** makes the accepted workflow record explicit. Evidence review establishes whether a claim is supported; the state contract checks whether that reviewed record may act.

```text
PublishState {
  revision_id: RevisionId
  approved_revision_id: RevisionId
  evidence: SourceCheck[]
  version: Integer
  status: approved | publishing
}

publish(state):
  require revision_id == approved_revision_id
  require every evidence item is verified
  commit_if_version(version,
    status="publishing",
    pending_send="publish:card-42:v8")
```

The `require` lines are transition guards, checks that run before a status change. `commit_if_version` performs one all-or-nothing database update, writing the new status and the pending send only if the stored version still matches. The pending-send value is an idempotency key, a unique token every retry presents. The publisher records one publish result for that key and stores a receipt, its durable confirmation of the original result; a later retry returns that confirmation instead of publishing again.

The recovery path is where the contract earns its keep. Suppose the worker commits `publishing` and crashes before calling the publisher. On restart it reads the persisted record, finds the pending send, and calls the publisher with the same key. If the publisher never saw the key, it publishes once and stores the receipt. If it saw the key before the crash, it returns the stored confirmation and nothing is sent twice. Either way the card publishes exactly once, and the record shows which case occurred.

I think this is the engineering win. The source review supports the sentence, while the state contract prevents an older worker from substituting another one.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Prompts carry intent while loops accumulate history. Graphs expose routes, and typed state lets only the approved revision cross the publishing boundary, with a receipt that survives crashes and retries.</p></div>

## Meanwhile in sci-fi

The test characterizes the subject at examination time; it says nothing about what the subject does next month.</p></div>

That is the right way to read Anthropic's pre-deployment audit. It is a careful examination of the model under test conditions, and I think it is genuinely useful for model selection. The argument of this article is that production authority needs a different kind of record, one written at the moment of the action itself. A model can pass every examination and still publish the stale revision, because the examination never saw the revision.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>A pre-deployment audit characterizes a model the way Voight-Kampff characterizes a subject: at examination time. Each production action still needs its own evidence.</p></div>

## Turn an old discipline into production evidence

Type discipline reaches back to computer scientist Robin Milner's [1978 work on type polymorphism](https://doi.org/10.1016/0022-0000(78)90014-4), which formalized how languages constrain values and operations. A type annotation, a declared shape for a record, remains documentation until a runtime validation boundary checks each record against it. That boundary does two things at once: it validates the state shape, and it enforces the allowed transition, persisting the accepted version and rejecting illegal moves.

Rails belongs beside this history for another reason. [Rails 1.0](https://rubyonrails.org/2005/12/13/rails-1-0-party-like-its-one-oh-oh), the December 2005 release of the Ruby web framework, shipped migrations, which are version-controlled records of database-schema changes. Ruby is dynamically typed, checking value types while code runs, so migrations are a separate craft from strong typing. Types constrain a record; migrations preserve its contract history. I think typed state brings both to agent transitions.

The prior art is honest about this split. Durable execution systems such as Temporal, a workflow engine that persists each step's result so a crashed workflow resumes from its last checkpoint, have kept workflow history for years. A durable workflow history records which steps ran; typed agent state records the business facts those steps accepted. An execution trace can show that `publish` ran, yet the trace alone cannot explain why revision `v8` had authority. Together, history and accepted state let a reviewer reproduce the authorized transition.

That difference, between a trace of what ran and a record of what was accepted, sharpens the [AI Operating Model](https://cubagarcia.com/posts/building-the-ai-operating-model/), the ownership and controls around AI work. It turns the operating model from a policy document into an evidence requirement: every consequential action needs an owner and a retrievable record of what authorized it. The March 2026 essay [The Verification Debt Crisis](https://cubagarcia.com/posts/2026-03-09-verification-debt-crisis/) names the gap between a rule and proof that it ran. A retained rejection pays down that debt by showing the rule evaluated at a specific transition. And [reversibility](https://cubagarcia.com/posts/reversibility-is-the-new-correctness/) becomes concrete when restoring a superseded revision creates a new state version and preserves the old one.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Runtime validation constrains the current record while versioned transitions preserve its history. Retained outcomes give operations and risk owners evidence they can retrieve.</p></div>

## Guard one boundary on Monday

Run a 30-minute design review on one costly transition, such as `human_approval -> publish`. Write down four fields: the required evidence, its owner, the retention and access rule, and one illegal transition. Then give two engineers two weeks to prove three things: stale work creates no pending send, approved work creates exactly one, and a crash after acceptance recovers the original publisher confirmation. The artifact from that review is the state contract itself, and it belongs in the same review process as any other contract the system depends on.

A one-shot classifier, a single model call that labels or routes an input without taking a multi-step external action, needs a lighter record, because there is no pending consequence to recover. Long-running agents with write authority create a higher recovery and audit burden, so proportion the control to the consequence.

I don't know which framework will dominate, and my forecast may be wrong: if write-capable agents consistently pass incident review and crash recovery from execution traces alone, the state contract adds little. I don't expect that. My take is that state contracts will be a standard review artifact for write-capable agents by the end of 2027. The standard an agent has to meet before it earns write authority is the state contract, and teams that adopt it early will spend their incident reviews reading records instead of reconstructing chat logs.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Give an agent broader write authority only after its state contract can reject a stale transition and return the existing publisher confirmation after a retry.</p></div>
