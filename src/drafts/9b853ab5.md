An engineer named Jonas Risbrandt described agentic coding in [one LinkedIn post](https://www.linkedin.com/posts/jonas-risbrandt-8309263_i-find-the-evolution-of-agentic-coding-slightly-activity-7485292345890865152-xymz): “Then we realized one prompt was not enough, so we added loops. Then loops were not enough, so we introduced graphs. Now we are adding typed state, control flow, persistence, retries, error handling, observability, reusable components, and testing.” He asked, “Haven't we just invented... a programming language?”

Days later, Anthropic [introduced Claude Opus 5](https://www.anthropic.com/news/claude-opus-5) and said a pre-deployment audit found “our most aligned model to date.” Its [Hacker News discussion](https://news.ycombinator.com/item?id=49038433) drew over 1,700 points. I think the two events expose the same fault line: model evaluation covers behavior before release, while production accountability requires a record of the evidence and authority behind each action.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Better model behavior expands what agents can attempt. Typed state records what a production agent accepted and was allowed to do.</p></div>

## Four waves in one publishing job

The running example is the pipeline producing this article. An early brief held the Hacker News score `1,723`; the live source later supported “over 1,700,” with its URL and capture time. A later revision pulled the old integer from context. Which observation governs the current revision?

### The prompt

A prompt is the instruction sent to a model:

```text
Research -> draft -> fact-check -> approval -> publish.
For HN item 49038433, write “over 1,700.”
```

Incidents add sentences until the prompt wears a toolbelt. It holds the preferred wording without fields for the source observation, capture time, or accepting revision, so stale data can still ship.

### The loop

A loop repeats reasoning, tool use, and review until a stopping condition. [ReAct](https://arxiv.org/abs/2210.03629), introduced in 2022, alternates model reasoning with actions and tool results:

```python
while status != "done":
    step = agent.run(status, messages)
    messages += tools.execute(step)
```

Now `1,723`, the live result, the correction, and the next draft coexist in `messages`. The loop preserves chronology without identifying which claim has authority. I think more context makes the archaeology longer.

### The graph

A graph makes the route explicit through nodes and edges:

```text
research -> draft -> fact_check -> approval -> publish
               ^        |
               +--------+  kickback
```

The route is visible, yet `draft` may contain the same loop over mixed messages. [LangGraph supports shared schemas](https://docs.langchain.com/oss/python/langgraph/graph-api), so the graph wave already permits typed state. The gain arrives when teams enforce that schema at ingestion, storage, and transition boundaries.

### Typed state

Typed state is a persisted record whose fields and allowed values are checked by code. The HN observation now belongs to one article revision:

```python
class HNObservation(BaseModel):
    item_id: int
    points: int
    captured_at: datetime
    source_url: HttpUrl
    article_revision: str
    wording: Literal["over 1,700"]

accepted = HNObservation.model_validate(
    {**tool_output, "article_revision": "r8", "wording": "over 1,700"},
    strict=True,
)
if accepted.item_id != 49038433 or accepted.points < 1700:
    raise EvidenceRejected()

if card.approved_revision != card.current_revision \
        or accepted.article_revision != card.current_revision:
    raise IllegalTransition()

with db.transaction():
    db.save(card.to("publish"), expected_version=card.version)
    db.outbox_once(card.idempotency_key, card.current_revision)
```

Pydantic validates untrusted tool output at ingestion, before the accepted evidence is stored. A transition is a checked move between statuses; the guard rejects an `r7` observation when the approved card is `r8`. Source review establishes truth, while the type contract makes stale state fail loudly.

The outbox is a durable send record written in the same database transaction. The idempotency key is its stable identity, allowing a worker that crashes after commit to resume without publishing twice. Reversibility becomes a property of the state machine because a corrective transition can target the accepted version and recorded effect.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>The prompt carries policy, the loop carries history, and the graph carries the route. Typed state adds the enforced record of evidence, approval, and action.</p></div>

## Why typed state changes the failure

I think typed state earns its place because retries, tests, and observability can refer to one accepted record. A durable workflow system may already preserve execution history and retry position. That orchestration layer explains how work ran; the domain contract explains which evidence and authority governed the next action. The two layers belong together.

Rails made a comparable craft move in 2005 by putting database changes into version-controlled migrations. Rails made web state legible. Typed state makes agent state legible. Strong type discipline reaches back to the 1970s, and projects such as [Inngest AgentKit](https://github.com/inngest/agent-kit), [GraphFlow](https://github.com/a-agmon/rs-graph-llm), and [MemState](https://github.com/scream4ik/MemState) now apply it to agents. I don't know which framework will win, but the architecture is converging.

The audit test is concrete: select a run, inspect its state version, open the linked evidence, identify the approver for that revision, and connect the outbox to the delivered effect. In *Blade Runner*, a model audit resembles a Voight-Kampff test before the replicant enters the city. The live case file still needs its authority and effects. When a team cannot produce that path, I think “alignment theater” is fair.

A legible [AI Operating Model](https://cubagarcia.com/posts/building-the-ai-operating-model/) gives the state an owner, a retention rule, and incident access. Procurement should require vendors to export state with evidence. In high-risk domains, the [EU AI Act](https://eur-lex.europa.eu/eli/reg/2024/1689/oj) points the same way through event recording and deployer log retention. Versioned state pays down [verification debt](https://cubagarcia.com/posts/2026-03-09-verification-debt-crisis/) because an operator can reconstruct and correct the accepted decision.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Execution history shows how work ran. Typed state shows which evidence and authority the system accepted, giving audits and recovery a stable contract.</p></div>

## Put one boundary under contract

A one-shot classifier may need little durable state. Start with an agent that waits for approval, retries after failure, or changes an external system. Book a 30-minute review of one transition and record four things: its evidence, owner, retention and incident access, and exact rejection rule.

Give two engineers two weeks to persist that contract and its outbox. Test that revision `r8` rejects evidence from `r7`, then crash the worker after commit and confirm recovery publishes once under the same idempotency key. This is a bounded control improvement with no platform rewrite.

My take is that approval-boundary contracts will be normal in serious agent systems by July 2027. The prediction fails if traces alone let teams recover consequential actions and pass incident review consistently. I think longer-running agents will push the evidence the other way.

Jonas wrote, “We replaced the code with a prompt, and then slowly started reintroducing the code around the prompt.” That code is craft discipline under a new workload. The next agent wave begins when every consequential action carries a state record that can survive a crash and explain its authority.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Choose one consequential transition, define its evidence and authority, then prove recovery produces one approved side effect from one accepted state version.</p></div>
