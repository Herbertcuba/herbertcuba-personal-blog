The agent field now moves fast enough to have its own archaeology. Last week an engineer named Jonas Risbrandt posted a short history of agentic coding [on LinkedIn](https://www.linkedin.com/posts/jonas-risbrandt-8309263_i-find-the-evolution-of-agentic-coding-slightly-activity-7485292345890865152-xymz), and I think it is the sharpest summary of the last four years:

> "First, we talked about prompting. Then we realized one prompt was not enough, so we added loops. Then loops were not enough, so we introduced graphs. Now we are adding typed state, control flow, persistence, retries, error handling, observability, reusable components, and testing."

Then he lands the punch: "Haven't we just invented... a programming language?"

The timing matters. The day before his post, Anthropic [shipped Claude Opus 5](https://www.anthropic.com/news/claude-opus-5) and called it their most aligned model to date, and [the Hacker News thread](https://news.ycombinator.com/item?id=49038433) passed over 1,700 upvotes. The industry is celebrating the model layer. The interesting work is one layer down, in the scaffolding.

My reading of Jonas's waves: each one looked like a feature. Each one was a fault line. It fixed the failure above it and hid a new failure below.

<div class="article-tldr">
<span class="article-tldr__label">The takeaway</span>
<p>Agentic coding has moved through prompts, loops, and graphs, and is now landing on typed state. Each earlier wave solved one failure and hid the next one. Typed state is the first wave that exposes the failure below it: the schema becomes a contract, illegal moves get rejected at the boundary, and "what did the agent know when it did this" gets a structured answer. Fifty years of database craft is arriving for agent state.</p>
</div>

## Four waves, one pipeline

Take a content production pipeline, the kind my team runs to produce articles like this one. An idea moves through twelve states, from inbox to publish. Watch what happens to it across the four waves.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>One pipeline, four architectures. The prompt became a junk drawer. The loop smuggled state into the chat log. The graph showed the roads and hid the plumbing. Typed state makes the state itself a contract.</p></div>

### Wave one: the prompt is the program

In 2022 the whole architecture was a paragraph:

```
You are a content pipeline. Take this article idea.
Research it, write it, review it, fact-check it, publish it.
Ask the human if anything is unclear.
```

What breaks: the prompt becomes a junk drawer. Every production incident adds a paragraph. Six months in, the prompt is doing the job of a schema, a state machine, and a runbook, and it is bad at all three. A prompt wearing a toolbelt.

### Wave two: the loop hides the state

The fix was the agent loop, usually called ReAct (Reason plus Act). The model thinks a thought, calls a tool, reads the result, and repeats until done. LangChain, AutoGen, CrewAI, and the Assistants API all wrap some version of this loop:

```
while not done:
    thought = model.reason(context)
    action = model.act(thought)
    result = tools[action.name](action.args)
    context.append(result)   # state = the whole chat log
```

What breaks: state now lives in the message history, smuggled along as chat. Corruption is silent. The brief for the article you are reading said 1,723 upvotes. The first draft repeated the number. Fact-check caught it. A later revision reintroduced it from stale context. The error was just another message in the log, indistinguishable from a fact.

### Wave three: the graph hides the loop

Frameworks like LangGraph let you draw the agent as a graph. Its StateGraph class connects nodes (steps like research and draft) with edges (the allowed moves between them). Control flow becomes visible:

```
graph = StateGraph(MessagesState)
graph.add_node("research", research_node)
graph.add_node("draft", draft_node)
graph.add_node("fact_check", fact_check_node)
graph.add_conditional_edges("fact_check", route_by_verdict)
```

What breaks: the graph shows you the roads while the plumbing stays hidden. A node can contain a loop, which contains a prompt, which contains a toolbelt. To be fair, [LangGraph's own docs](https://docs.langchain.com/oss/python/langgraph/graph-api) define state as a shared schema. But in default practice that state is a free-form dictionary mutated in place.

### Wave four: the schema is the contract

The fourth wave makes the state itself a declared type. A TypedDict is a normal Python dictionary where you declare up front which keys exist and what type each value holds:

```python
class CardState(TypedDict):
    card_id: str
    status: Literal["ideas_inbox", "research", "draft",
                    "fact_check", "publish", "done", ...]
    brief: str | None        # None until research completes
    draft: str | None        # None until the writer completes
    kickback_count: int      # hard cap
    sources_verified: bool   # False blocks publish
    hn_points: str           # "over 1,700", never an exact int

def transition(state: CardState, to: str) -> CardState:
    if to == "publish" and not state["sources_verified"]:
        raise IllegalTransition("unverified sources")
```

What changes: the illegal move is rejected at the boundary, before a stale number ever ships. The state is a database row with a shape, and the auditor's question finally has a structured answer. When the card moved to review, the writer had brief version four, sources unverified, one kickback. I think this is the first wave that survives contact with an audit.

Projects like [Agd](https://news.ycombinator.com/item?id=47224560) store agent state the way git stores commits: every transition addressable and replayable. Reversibility stops being a vibe in the prompt and becomes a property of the state machine, a thread I pulled in [Reversibility is the new architectural correctness](/posts/reversibility-is-the-new-correctness/).

## Why this wave is different

Three reasons, quickly.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Waves one to three hid state. Wave four exposes it. Agent state is cognition, and cognition is finally getting a type system. Independent teams in four languages arrived here in sixteen months.</p></div>

First, waves one to three hid state. Wave four exposes it. It makes the failure below it visible instead of burying it under a nicer abstraction.

Second, plumbing versus cognition. Workflow state is plumbing. Agent state is cognition: what the system currently believes. The first three waves automated cognition and left the plumbing informal. This wave types the beliefs.

Third, it is convergent. In sixteen months, independent teams in four languages shipped typed agent state: [Inngest](https://news.ycombinator.com/item?id=43426164) in TypeScript, GraphFlow and [Turn](https://news.ycombinator.com/item?id=47220136) in Rust, [MemState](https://github.com/scream4ik/MemState) in Python, Agd in Zig. One vendor's roadmap is a trend. Four languages is a direction.

## What breaks without it

The failure compounds, and the bill arrives in two currencies: audit hours and alignment theater.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Without typed state, corruption ships silently, alignment claims stay in the lab, and the logging obligations regulators just switched on have nothing to answer them with.</p></div>

The pain is real enough that people build languages to escape it. Turn's makers started after writing "500 lines of Pydantic models, JSON-parsing retry loops, and async spaghetti just to coordinate two agents."

Then there is the alignment theater. Anthropic's "most aligned" claim rests on a qualifier that I think matters more than the claim: pre-deployment testing, an automated behavioral audit. In Blade Runner, the Voight-Kampff test measures a replicant in an interview room. A pre-deployment audit is the same kind of instrument. It tells you how the model behaves in the room. Your production system is off-world. Alignment at the model layer is the vendor's problem. Accountability at the system layer is yours.

Regulation is arriving on the same schedule. [The EU AI Act](https://eur-lex.europa.eu/eli/reg/2024/1689/oj) requires high-risk AI systems to automatically record events over their lifetime (Article 12), and deployers must keep those logs (Article 26(5)). The main high-risk obligations apply from August 2, 2026. That was yesterday. When your agent touches a high-risk domain, "what did the system know when it made this decision" stops being a debugging question and becomes a legal one. At enterprise scale, one corrupted field in an unauditable agent can stall the month-end close and trigger a restatement conversation.

The next fault line is already visible. Typed state inside one agent becomes shared typed memory across many. The agent forgets. The graph does not. My prediction: the unauditable mess of 2028 is multi-agent shared memory, and it fails the same way at month-end.

## What to do on Monday morning

The craft move here is the oldest one we have, and it is back.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Pick one agent whose mistakes are expensive. Write its schema, give it one named owner, and put every change through review like any other contract.</p></div>

Type discipline dates to the 1970s, and Rails carried it into web apps in 2005: schema as contract and transitions as migrations. I think we are watching the same move land in agent systems twenty years later. Jonas said it in one line: "We replaced the code with a prompt, and then slowly started reintroducing the code around the prompt."

One concession: a one-shot agent that classifies a ticket and dies does not need a schema. This argument is for agents whose mistakes are expensive: the ones that publish, pay, book, or deploy.

Start on Monday. Pick one such agent. Write its schema: the states, the fields, the allowed transitions, and the one transition that must be guarded. For our pipeline it was publish. One named engineer owns the schema. Changes go through review like any other contract. Two engineers, two weeks, no platform rewrite.

Then diff the schema against what the agent actually carries at runtime. I would bet you find two or three times the fields you declared. That gap is your verification debt, finally visible, the same debt I wrote about in [the verification debt crisis](/posts/2026-03-09-verification-debt-crisis/). I don't know a faster way to find it.

The models will keep improving on the vendor's roadmap. The scaffolding is yours, and it is finally becoming engineering again.
