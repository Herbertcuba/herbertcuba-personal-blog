On July 21, engineer Jonas Risbrandt [described agentic coding’s progression](https://www.linkedin.com/posts/jonas-risbrandt-8309263_i-find-the-evolution-of-agentic-coding-slightly-activity-7485292345890865152-xymz): “Then we realized one prompt was not enough, so we added loops. Then loops were not enough, so we introduced graphs. Now we are adding typed state, control flow, persistence, retries, error handling, observability, reusable components, and testing.” He asked, “Haven’t we just invented... a programming language?”

Three days later, Anthropic [said](https://www.anthropic.com/news/claude-opus-5) an automated pre-deployment audit found Opus 5 to be “our most aligned model to date.” The [Hacker News discussion](https://news.ycombinator.com/item?id=49038433) drew over 1,700 points. I think the timing exposes an engineering gap: a model can perform well in testing while an incident team still cannot identify which facts authorized a production action.

Each wave looked like a feature, yet buried authority deeper. Typed state makes it inspectable before a tool call leaves the system.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Pre-deployment model audits still leave production teams needing a durable record of each consequential action’s authority.</p></div>

## Follow one claim through four waves

Take a publishing pipeline with two revisions. `v7` gives a fixed score of 1,723; fact-check approves `v8`, “over 1,700,” because the score moves. Both remain available, but only `v8` may publish.

A **prompt** is one instruction sent to the model:

```text
Research, draft, fact-check, and publish the approved revision.
```

The instruction can call several tools, but it cannot keep an authoritative revision record. This prompt wears a toolbelt while approval remains prose.

A **loop** repeats reasoning and tool calls:

```python
while card.open:
    result = agent.run(history)
    history.append(result)
```

History now contains `v7` and `v8`, yet no field says which may advance. I think the next gain comes from a smaller loop around checked state; larger context only eases the archaeology.

A **graph** names steps and routes:

```text
draft -> fact_check -> approved -> publish
   ^          |
   +-- revise-+
```

[LangGraph](https://docs.langchain.com/oss/python/langgraph/graph-api) supports shared schemas; [Inngest AgentKit](https://github.com/inngest/agent-kit) calls its router a “fully typed state machine.” Yet a node can hold a loop with mixed history when writes bypass the contract. The graph resembles the Nostromo deck plan in *Alien*: clear corridors, with danger still running inside a room.

**Typed state** gives each fact a named field and an allowed form. Its schema checks shape; a guarded **transition**, an allowed move between statuses, checks `approved -> publishing`. One transaction then persists the accepted revision and evidence before creating a delivery record.

```python
class PublishState(BaseModel):
    card_id: str
    revision_id: str
    approved_revision_id: str
    evidence_ids: tuple[str, ...]
    status: Literal["approved", "publishing", "published"]
    version: int

require(s.status == "approved")
require(s.revision_id == s.approved_revision_id)
require(s.evidence_ids)
with db.transaction():
    card.accept(s.revision_id, s.evidence_ids,
                status="publishing", expected_version=s.version)
    outbox.put_once(f"publish:{s.card_id}:{s.revision_id}",
                    {"revision": s.revision_id, "evidence": s.evidence_ids})
```

An **outbox** is a durable pending send. Its **idempotency key**, `publish:{card_id}:{revision_id}`, is a stable label sent to the publisher so a duplicate retry is ignored; the worker stores the receipt. Stale `v7` changes nothing, while `v8` persists evidence and one delivery.

Fact review judges truth; types establish structure. I think their win is turning disagreement into a loud rejection at a known boundary.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Prompts express intent, loops retain activity, graphs expose routes, and typed state lets one evidenced revision cross the publish boundary.</p></div>

## Make state carry authority

Strong typing has disciplined software since the 1970s. In 2005, [Rails 1.0](https://rubyonrails.org/2005/12/13/rails-1-0-party-like-its-one-oh-oh) migrations made database changes inspectable and repeatable. Agent transition contracts apply the same move, and persistence keeps the checked record alive across retries.

Workflow history records pauses and resumes; accepted state records the revision and evidence authorizing the next move. The outbox carries the intended effect, the receipt records delivery, and raw traces diagnose steps without granting authority.

**Verification debt** is the gap between what a prompt requires and what the system can prove. Typed transitions expose and pay it down. They also make reversibility concrete: correction becomes `published -> amendment_pending`, with the original receipt retained.

Anthropic scoped its claim to pre-deployment behavior. I think that audit cannot explain why `v8` published or whether a retry duplicated it. Calling it production accountability would be alignment theater. A legible AI operating model ties accepted state to an owner, retention and access rules, and a correction path. I don’t know which framework will dominate; this contract can outlast it.

A one-shot classifier can carry a lighter record. A long-running agent with write authority creates a stronger burden because its decisions survive the model call.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Execution history supports recovery; accepted state and delivery receipts give incident review a replayable account of production authority.</p></div>

## Put one boundary under contract on Monday

Run a 30-minute review of `approved -> publishing`. Produce one page covering evidence, owner, retention and access, and the illegal transition. A risk owner should ask who can retrieve the accepted state and receipt during an incident, and for how long.

Give two engineers two weeks to prove four tests: stale `v7` leaves state and outbox unchanged; `v8` persists evidence and one outbox row; retry after worker death yields one receipt; amendment retains the original effect.

Jonas wrote, “We replaced the code with a prompt, and then slowly started reintroducing the code around the prompt.” My take: by the end of 2027, teams with write agents will standardize boundary contracts before switching frameworks. Raw traces that reliably reconstruct approved evidence, legal transition, and delivered effect through retries without accepted state would disprove me.

A team earns the next increment of write authority when stale `v7` fails loudly, approved `v8` ships once, and the amendment path already exists.
