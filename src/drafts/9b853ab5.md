AI engineering now moves so fast that each solution reveals its next problem. On July 25, 2026, [engineer Jonas Risbrandt](https://www.linkedin.com/posts/jonas-risbrandt-8309263_i-find-the-evolution-of-agentic-coding-slightly-activity-7485292345890865152-xymz) described agentic coding, in which AI models use tools and repeat actions to complete software work: “Then we realized one prompt was not enough, so we added loops. Then loops were not enough, so we introduced graphs. Now we are adding typed state, control flow, persistence, retries, error handling, observability, reusable components, and testing.” Then he asked, “Haven't we just invented... a programming language?”

One day earlier, AI company Anthropic called its new model, [Claude Opus 5](https://www.anthropic.com/news/claude-opus-5), its “most aligned model to date” after pre-deployment tests. Its launch drew [over 1,700 upvotes on Hacker News](https://news.ycombinator.com/item?id=49038433), a discussion site for technologists. That measures attention, not endorsement.

Yet a model test cannot reveal what an agent knew when it changed a production record. Without that answer, model alignment becomes theater: a pre-deployment claim without production evidence. Typed state makes the record around the model explicit, enforceable, and persistent.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Better model behavior does not create a production audit trail. Typed state creates a system-level record around the model.</p></div>

## Follow one claim through four architectures

The content engine behind this article runs eight agents as Hermes command-line workers: ideator, researcher, writer, slop-reviewer, fact-checker, persona-panel, visual-designer, and publisher. PostgreSQL, a relational database, stores each card in `content_engine.tasks` across 12 possible states:

```text
ideas_inbox → approved → research → draft → slop_review → fact_check
→ persona_panel → design → human_approval → publish → done | escalated
```

The audit question is what the writer knew when it moved the card to `slop_review`. Follow one changing Hacker News score through four designs.

### Prompt

A prompt is a natural-language instruction to a model:

```text
Research, draft, fact-check, and publish this article.
Describe changing vote counts with a stable, sourced phrase.
```

Each incident adds an instruction, but a longer prompt still cannot record a reliable handoff.

### Loop

A loop lets the model act, observe, and try again. ReAct, short for Reason and Act, is a 2022 pattern from AI researcher Shunyu Yao and colleagues that formalized this cycle.

```python
while not done:
    messages.append(run(model.reason_and_act(messages)))
```

The message history becomes state. A fact-checker can replace a stale exact score with “over 1,700,” while a later pass restores the old claim. A larger context stores more conflict; without a named field, the loop cannot detect it.

### Graph

A graph uses named nodes and permitted routes. [LangGraph](https://docs.langchain.com/oss/python/langgraph/graph-api), an open-source framework for stateful agent workflows, provides `StateGraph`, a builder that connects steps around shared state.

```python
graph = StateGraph(MessagesState)
graph.add_conditional_edges("fact_check", route_by_verdict)
```

The route and its kickback are visible. LangGraph supports typed schemas; trouble starts when `MessagesState`, its message-list schema, becomes the effective contract. The disputed claim still sits inside the conversation.

### Typed state

Typed state declares fields and allowed values. Python's `TypedDict` describes that shape for development tools, while `Literal` restricts a field to listed values. Runtime checks must enforce both when model output arrives.

```python
class CardState(TypedDict):
    status: Status                 # one of the 12 states
    brief_version: int
    source_snapshot: str
    sources_verified: bool
    hn_claim: Literal["over 1,700"]

if to == "publish" and not state["sources_verified"]:
    raise IllegalTransition
```

This design persists each accepted snapshot. The team can inspect the brief version, source snapshot, and verification flag present at `slop_review`. An invalid write or publish attempt fails at the boundary instead of surviving as another message.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Prompts hold instructions, loops accumulate history, and graphs expose routes. Typed, persisted state makes the handoff inspectable and enforceable.</p></div>

## The useful outcome is a louder failure

Types do not prove truth. With runtime checks and allowed transitions, they turn silent corruption into a rejected write. Retries start from a named snapshot, operational logs report named fields, and tests assert permitted transitions.

Ruby on Rails 1.0, a web framework released in December 2005, made database changes easier to operate through schemas and versioned migrations. Ruby is dynamically typed, so the parallel is not language-level typing. It is discipline around state. Strong typing adds a much older rule: incompatible values and illegal transitions should be refused.

LangGraph's shared schemas and [Inngest AgentKit](https://github.com/inngest/agent-kit), a TypeScript framework with typed routing state, show teams arriving at the same architecture. They do not prove broad adoption.

Inspectable snapshots give an [AI operating model](/posts/building-the-ai-operating-model/), the ownership and controls around AI work, something concrete to govern. They render [verification debt](/posts/2026-03-09-verification-debt-crisis/) as missing evidence and make [reversibility](/posts/reversibility-is-the-new-correctness/) a property of persisted transitions.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Typed state improves accountability rather than truth: it makes invalid transitions rejectable, evidence gaps visible, and prior states recoverable.</p></div>

## Start with one consequential handoff

A one-shot classifier, which labels one item and exits, may not need durable state. A publishing, finance, or HR workflow does because a wrong transition can affect another system.

On Monday, choose one handoff. Write the smallest schema that answers what the agent knew, persist the before-and-after snapshots, and add one guard that blocks a costly transition. Name an owner and review changes like database-schema changes. Give two engineers two weeks; if the work does not fit, narrow it.

Risbrandt wrote, “We replaced the code with a prompt, and then slowly started reintroducing the code around the prompt.” Make one handoff answerable, then judge the rest of the architecture against evidence instead of confidence.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Begin with one consequential transition, one owned schema, persisted snapshots, and one enforced guard. The goal is an answerable system, not a platform rewrite.</p></div>
