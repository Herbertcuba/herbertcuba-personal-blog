On July 21, 2026, engineer Jonas Risbrandt [described on LinkedIn](https://www.linkedin.com/posts/jonas-risbrandt-8309263_i-find-the-evolution-of-agentic-coding-slightly-activity-7485292345890865152-xymz) how agentic coding, software work delegated to tool-using AI systems, moved from prompts to loops, then graphs, and finally typed state. “Haven’t we just invented... a programming language?” he asked. “We replaced the code with a prompt, and then slowly started reintroducing the code around the prompt.”

Three days later, AI company Anthropic [announced Claude Opus 5](https://www.anthropic.com/news/claude-opus-5), a model for long-running agents, and said a pre-deployment audit found it to be “our most aligned model to date.” Here, aligned meant better results against Anthropic’s safety and behavior criteria, including its written Constitution and tests for deception or misuse. Its [Hacker News discussion](https://news.ycombinator.com/item?id=49038433) had over 1,700 points; Hacker News members vote stories up.

I think they belong together because public attention centered on model capability while framework builders moved reliability into explicit state. Each wave expanded capability and buried a new failure deeper. Typed state gives that failure a field, a rule, and a retained outcome.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Model evaluations describe behavior before release; production control needs a durable record showing what authorized an agent’s action.</p></div>

## Follow one publishing card through four architectures

Consider this publishing card. An early revision used an exact Hacker News score, which changed as people voted. A reviewer approved a later revision saying “over 1,700,” while a paused worker held the stale draft. Its publish attempt should fail.

A **prompt** is an instruction sent to a model:

```text
Research card-42, verify every claim, request approval, then publish.
```

That prompt authorizes tools and states a policy, but stores no accepted revision. The worker can still submit stale text.

A **loop** asks the model for another action and appends each result to history:

```python
while card.open:
    result = agent.run(history)
    history.append(result)
```

Both revisions and the approval now sit in one growing transcript. A retry has no checked field naming the governing revision. A larger context window merely increases the history the worker must search.

A **graph** names steps as nodes and routes as edges:

```text
draft -> fact_check -> human_approval -> publish
  ^            |
  +--- revise -+
```

The route is visible, yet the `publish` node may retry the old payload. [LangGraph](https://docs.langchain.com/oss/python/langgraph/graph-api), a Python toolkit for graph-based agent workflows, permits shared typed schemas. Teams must validate writes and enforce transitions.

**Typed state** makes the accepted workflow record explicit. Evidence review establishes whether the claim is supported; the state contract checks whether that reviewed record may act.

```text
PublishState {
  revision_id: RevisionId
  approved_revision_id: RevisionId
  evidence: SourceCheck[]
  version: Integer
  status: approved | publishing
}

publish(state):
  require revision_id == approved_revision_id
  require every evidence item is verified
  commit_if_version(version,
    status="publishing",
    pending_send="publish:card-42:v8")
```

The `require` lines are transition guards, checks before a status change. `commit_if_version` performs one all-or-nothing database update, writing the status and pending send only for the current version. The pending-send value is an idempotency key: every retry uses it, so the publisher records one result and returns its receipt later.

I think this is the engineering win. The source review supports the sentence, while the state contract prevents an older worker from substituting another one.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Prompts carry intent while loops accumulate history. Graphs expose routes, and typed state lets only the approved revision cross the publishing boundary.</p></div>

## Turn an old discipline into production evidence

Type discipline reaches back to computer scientist Robin Milner’s [1978 work on type polymorphism](https://doi.org/10.1016/0022-0000(78)90014-4), which formalized how languages constrain values and operations. An annotation remains documentation until the system validates the record at runtime. The same boundary must persist the accepted version and reject illegal transitions.

Rails belongs beside this history for another reason. [Rails 1.0](https://rubyonrails.org/2005/12/13/rails-1-0-party-like-its-one-oh-oh), the 2005 release of the Ruby web framework, used migrations, version-controlled database-schema changes. Ruby is dynamically typed, checking value types while code runs, so migrations remain separate from strong typing. Types constrain a record; migrations preserve its contract history. I think typed state brings both to agent transitions.

A durable workflow history records which steps ran. Typed agent state records the business facts they accepted. Together they let reviewers reproduce the authorized transition. An execution trace logs calls and results, yet `publish` alone cannot explain why revision `v8` had authority.

This sharpens the [AI Operating Model](https://cubagarcia.com/posts/building-the-ai-operating-model/), the ownership and controls around AI work. The March 2026 essay [The Verification Debt Crisis](https://cubagarcia.com/posts/2026-03-09-verification-debt-crisis/) names the gap between a rule and proof that it ran. A retained rejection pays down that debt by showing the rule evaluated at a specific transition. [Reversibility](https://cubagarcia.com/posts/reversibility-is-the-new-correctness/) becomes concrete when restoring a superseded revision creates a new state version and preserves the old one.

Anthropic’s audit can guide model selection, but production authority requires another record. In director Ridley Scott’s 1982 film *Blade Runner*, the fictional Voight-Kampff test measures physical reactions during an interview. It characterizes the subject in that examination; later actions need their own evidence. I think model audits have the same boundary.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Runtime validation constrains the current record while versioned transitions preserve its history. Retained outcomes give operations and risk owners evidence they can retrieve.</p></div>

## Guard one boundary on Monday

Run a 30-minute design review on one costly transition, such as `human_approval -> publish`. Write down four fields: required evidence, its owner, the retention and access rule, and one illegal transition. Then give two engineers two weeks to prove that stale work creates no pending send, approved work creates one, and a crash after acceptance recovers the original receipt.

A one-shot classifier, a single model call that labels or routes an input without taking a multi-step external action, needs a lighter record. Long-running agents with write authority create a higher recovery and audit burden.

I don’t know which framework will dominate. My take is that state contracts will become a standard review artifact for write-capable agents by the end of 2027. That forecast fails if such agents consistently pass incident review and crash recovery from execution traces alone.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Give an agent broader write authority only after its state contract can reject a stale transition and return the existing receipt after a retry.</p></div>
