AI builders often discuss graphs as advanced and pipelines as primitive. A straight, linear pipeline is already the simplest graph topology: one ordered path. Some systems also use “pipeline” for a branched directed acyclic graph, so I use *straight pipeline* for the one-path case. Topology is only the arrangement of stages and connections.

I think the production question is how little topology can express the work honestly. Every extra route creates another path to schedule, observe, retry, and recover. It adds no model judgment by itself.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Choose topology by the work’s dependencies, not by how advanced the diagram looks.</p></div>

## Start with real dependencies

A data dependency exists when one job consumes another job’s result. A resource dependency exists when jobs can conflict through something mutable, such as a shared file, database record, workspace, approval, or service quota. [PostgreSQL, an open-source relational database](https://www.postgresql.org/docs/current/transaction-iso.html), documents concurrent writers waiting on one record; [Stripe, a payments platform](https://docs.stripe.com/rate-limits), documents separate rate and concurrency limits.

Apply the fake-edge test. If B consumes nothing from A, and the jobs share no conflicting write, lock, approval, quota, or external effect such as charging a card, the A → B edge may be artificial. Both can read the same immutable input because neither changes it. I think separate model calls prove neither independence nor safe concurrency.

Keep schema checks, counting, deduplication, routing rules, and merge-completeness checks in deterministic code where possible. Reserve models for judgment.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Map consumed outputs and shared mutable resources before counting agents or drawing edges.</p></div>

## Choose the minimum truthful shape

Keep a straight pipeline when sequence is real: ingest a request → validate its schema → apply policy → persist the result. Replay reconstructs workflow state from recorded history; it is distinct from retrying an external action. [Temporal, a durable workflow platform](https://docs.temporal.io/workflow-definition), documents this separation. A retried side effect still needs idempotency or reconciliation so it does not create an unintended duplicate.

Use a directed acyclic graph, or DAG, when independent work can fan out into concurrent branches and later fan in at a merge, with no route back to an earlier stage. If every result is required, the critical path, or longest required chain, includes the slowest required branch. [AWS Step Functions, a managed workflow service](https://docs.aws.amazon.com/step-functions/latest/dg/state-parallel.html), documents an all-branch wait in its Parallel state. I think breadth earns a DAG; a dramatic speedup is never automatic.

A conditional graph selects the next route from current workflow state. A cyclic graph can return to earlier work, so it needs both a meaningful stop rule and a hard attempt, time, or cost limit. A hybrid keeps a straight control spine around one bounded branch or cycle.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Use a straight path for real sequence, a DAG for independent breadth, and state-driven routes only when runtime evidence changes the next move.</p></div>

## Write the merge contract first

The coordination tax arrives at the merge: partial failures, shared-workspace conflicts, quotas, traces, retries, and more model calls. A join policy says which results are required. Provenance records which branch and input produced each result. Idempotency means repeating one logical external action retains the same intended effect instead of creating another charge, message, or write; [Stripe documents idempotency keys for API retries](https://docs.stripe.com/api/idempotent_requests).

I think a framework-neutral merge record is more useful than another node:

```text
run: r42
branches:
  market:      {required: true,  status: complete}
  regulation:  {required: true,  status: running}
  competitors: {required: false, status: timed_out}
join: all_required
retry_budget: 2
stop: deadline_or_budget
owner: research-service
guard: reject merge(required_pending: regulation)
```

Accepting this merge while the required regulation branch is still active is an illegal transition. The operator-visible error explains why. The record should preserve run and branch identities so control state can be reconstructed or replayed. Before production, a named service owner should approve the deadline, retry policy, evidence requirement, and rollback condition.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Define required branches, failures, retries, stop rules, illegal transitions, and ownership before fan-out enters production.</p></div>

## Promote topology with evidence

Topology is framework-independent. The same logical shape can run on a durable workflow engine, queue workers, or state-machine code. An agent-graph library is an implementation option, not the architecture decision.

Ask four questions in the design review:

1. What must wait because it consumes an earlier result?
2. What can run independently without touching the same mutable resource?
3. Can current state change the next route or stopping condition?
4. Can the system detect, explain, and replay a partial failure?

Baseline the straight route, test one bounded alternative, then compare critical-path latency, accepted evidence, duplicate effects, incomplete merges, recovery success, and cost per successful run. I don’t know which shape wins before measurement. I think a change is earned only when its named owner can show that the gain beats the coordination tax and can state how to roll it back.

For deeper treatment of cycles, [“Everyone Discovered Loops. Nobody Agrees What the Word Means.”](https://www.cubagarcia.com/posts/everyone-discovered-loops/) covers loop terminology and exit conditions. Once topology is chosen, [“The 105 minutes after the graph”](/drafts/67821675/) examines evaluation, declared state, and the evidence needed to trust a production run. Unearned topology becomes coordination debt precisely when nobody owns its failure paths.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Measure before promotion, govern partial failure, and choose the smallest graph that tells the truth about the work.</p></div>
