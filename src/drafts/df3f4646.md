AI builders often treat a graph as advanced and a pipeline as primitive. That confuses topology with capability. Workflow topology means how stages and routes are arranged; a pipeline is already its simplest graph: one ordered path.

I think production calls for the minimum topology that represents the work truthfully. More routes widen the work but cannot supply judgment, retry safety, or ownership. Each creates scheduling and recovery work.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Choose workflow shape from real dependencies, not diagram sophistication.</p></div>

## Draw dependencies before topology

Map what must wait. A data dependency means one job consumes another's result. A resource dependency means jobs share something either can change or exhaust: a file, database record, workspace, approval, quota, or external system. [PostgreSQL, an open-source relational database](https://www.postgresql.org/docs/current/transaction-iso.html), documents writers waiting on one record; [Stripe, a payments platform](https://docs.stripe.com/rate-limits), documents separate rate and concurrency limits.

Apply the fake-edge test. If B consumes nothing from A and the jobs share no conflicting write, lock, approval, quota, or external effect, their edge may be artificial. Sharing an immutable input creates no write conflict. I think teams will mistake concurrent model calls for independent work and find the hidden dependency during recovery.

Keep a linear pipeline when sequence is real: ingest request → validate schema → apply policy → persist result. Use deterministic code for checks, deduplication, routing, and counting. An ordered path is strongest when each stage needs the previous result.

Replay depends on the runtime. [Temporal, a durable workflow platform](https://docs.temporal.io/workflow-definition), rebuilds Workflow state from event history. Its external Activities may run again under retry policy, so workflow replay and repeated side effects need separate controls.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Keep real sequence linear; remove an edge only after checking data flow and shared resources.</p></div>

## Make the merge operational

A directed acyclic graph, or DAG, has directed dependencies but no route back. It earns its place when jobs fan out into independent branches and fan in at a merge: research five market angles concurrently, verify each, then merge the survivors into one report.

The coordination tax arrives at the merge: partial failures, shared limits, extra calls, and recovery. A join policy names required results and the action for a missing one. The critical path is the longest required chain, so an all-required merge cannot finish before its slowest branch. [AWS Step Functions, a managed workflow service](https://docs.aws.amazon.com/step-functions/latest/dg/state-parallel.html), waits for every Parallel branch before continuing. I think the merge contract matters more than the fan-out.

```text
branches:
  market:      {required: true,  status: complete, retries: 0}
  regulation:  {required: true,  status: running,  retries: 1}
  competitors: {required: false, status: timed_out, retries: 2}
join_policy: all_required
retry_budget: 2
stop_condition: deadline_or_budget
owner: research-service
guard: required_branches_must_be_terminal
```

The guard rejects a merge while the required regulation branch is running. Require a run record with branch IDs, immutable inputs, results or errors, retry counts, and the merge decision. These fields are an explicit observability requirement, not an automatic graph feature. Before release, the service owner should approve deadlines, retries, recovery, and rollback.

A retried charge, message, or write also needs idempotency: repeating the same logical request preserves one intended external effect. [Stripe's API documentation](https://docs.stripe.com/api/idempotent_requests) shows one implementation using an idempotency key.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Parallel work earns production status only when required results, missing branches, retry safety, illegal transitions, and recovery ownership are explicit.</p></div>

## Add routes only when state earns them

A conditional graph selects its next route from current state. A cyclic graph can return to earlier work, so it needs a reason to return, a stop rule, and a hard attempt, time, or cost limit. [LangGraph, an open-source framework for stateful agent workflows](https://docs.langchain.com/oss/python/langgraph/graph-api), documents state-based routing and bounded execution. I think a cycle earns its place only when state alters what happens next.

Choose topology before a workflow engine or agent-graph library. The same shape can run on a durable engine, queue workers, or state-machine code. Implementation does not create the dependency.

A hybrid keeps a linear backbone with a bounded graph-shaped section. Intake and policy stay ordered while research fans out into two required branches and one optional branch, then merges before approval. Compare it with the linear baseline on latency, accepted evidence, duplicate effects, incomplete merges, recovery time, and cost per successful run.

Four questions are enough for the design review:

1. What must wait because it consumes an earlier result?
2. What can run independently without touching the same mutable resource?
3. Can current state change the next route or stopping condition?
4. Can the runtime detect, explain, and recover from a partial failure?

If independence and a latency need are proven, start with a DAG. I don't know which shape wins before measurement. I think change is earned when its owner proves the gain beats the tax and can restore the simpler route after a breached limit.

[“Everyone Discovered Loops. Nobody Agrees What the Word Means.”](https://www.cubagarcia.com/posts/everyone-discovered-loops/) covers loop terminology and exit conditions. [“The 105 minutes after the graph”](https://www.cubagarcia.com/drafts/67821675/) covers evaluation, declared state, and evidence after topology selection. My take: the advanced architecture is the smallest graph that tells the truth.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Measure the straight path, add routes only for declared gains, and require an owner who can recover and reverse them.</p></div>
