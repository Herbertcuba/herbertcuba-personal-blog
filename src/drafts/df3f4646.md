AI builders often treat a graph as advanced and a pipeline as primitive. The distinction is misleading. Workflow topology means the arrangement of stages and routes, and a straight linear pipeline is already the simplest graph shape: one ordered path.

I think the production question is how little topology can represent the work accurately. Every added route creates scheduling, failure, and recovery obligations, while adding no model judgment by itself.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Choose the arrangement of work from real dependencies, not from how sophisticated its diagram looks.</p></div>

## Draw the edges before choosing the shape

A data dependency exists when one job consumes another job’s result. A resource dependency exists when jobs conflict over a mutable resource: a shared file, database record, workspace, approval gate, or service quota that either can change or exhaust. [PostgreSQL, an open-source relational database](https://www.postgresql.org/docs/current/transaction-iso.html), documents writers waiting on the same record; [Stripe, a payments platform](https://docs.stripe.com/rate-limits), documents separate rate and concurrency limits.

That gives us the fake-edge test. If B consumes nothing from A and the jobs share no conflicting write, lock, approval, quota, or external side effect, the A → B edge may be artificial. Both can read the same immutable input. I think concurrent model calls prove neither independence nor safe concurrency.

Keep schema checks, counting, deduplication, routing rules, and merge-completeness checks in deterministic code; reserve models for judgment.

Keep a straight pipeline when sequence is real: ingest a request → validate its schema → apply policy → persist the result. Replay rebuilds workflow state from recorded history; it does not blindly repeat an external action. [Temporal, a durable workflow platform](https://docs.temporal.io/workflow-definition), documents that separation. An obviously ordered route is a strength when ownership and recovery must stay clear.

Use a directed acyclic graph, or DAG, when independent work can fan out into concurrent branches and fan in at a later merge, with no route back to an earlier stage. Its critical path is the longest chain of required work. If every result is required, that path includes the slowest branch, so parallel execution promises no fixed speedup. [AWS Step Functions, a managed workflow service](https://docs.aws.amazon.com/step-functions/latest/dg/state-parallel.html), documents this all-branch wait.

Choose a conditional graph when current workflow state selects the next route. Choose a cyclic graph when that route can return to earlier work, and give it a meaningful stop rule plus a hard attempt, time, or cost limit. A hybrid keeps a linear control spine around a bounded branch or cycle. I think this is often the strongest production shape. For more on cycles, [“Everyone Discovered Loops. Nobody Agrees What the Word Means.”](https://www.cubagarcia.com/posts/everyone-discovered-loops/) explains loop terminology and exit conditions.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Use one path for real sequence, a DAG for independent breadth, and state-driven routes only when runtime evidence changes what happens next.</p></div>

## Make the merge operational

The coordination tax appears at convergence: partial failures, workspace conflicts, service limits, extra model calls, and harder recovery. A join policy states which results are required and what happens when one is missing. A trace records each branch’s identity, inputs, outputs, errors, and retries for one run. I think the merge contract matters more than the fan-out.

Consider a framework-neutral hybrid whose research stage checks market, regulation, and competitors:

```text
run_id: r42
status: pending | running | complete | failed | timed_out
branches:
  market:      {required: true,  status: complete, retries: 0}
  regulation:  {required: true,  status: running,  retries: 1}
  competitors: {required: false, status: timed_out, retries: 2}
join_policy: all_required
retry_budget: 2
stop_condition: deadline_or_budget
provenance: branch_id_and_input_version_required
owner: research-service
guard: reject_merge_if_required_branch_is_not_terminal
```

The guard rejects this merge because regulation is still running. Accepting it is a forbidden state change, and the trace should show `required_branch_not_terminal: regulation` to the operator. Before release, the service owner should approve the deadline, retry and recovery rules, required evidence, and rollback condition.

Retries that can repeat a charge, message, or write need idempotency: repeats of the same logical request must retain the same intended external effect. [Stripe’s idempotency guidance](https://docs.stripe.com/api/idempotent_requests) shows one implementation. If the outcome is uncertain, reconciliation means comparing the workflow record with the external system before acting again.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Define branch identities, required results, safe retries, stop rules, rejected state changes, recovery, and ownership before parallel work enters production.</p></div>

## Promote topology with evidence

Topology is framework-independent. The same shape can run on a durable workflow engine, queue workers, or state-machine code; an agent-graph library is one implementation choice.

Ask four questions in the design review:

1. What must wait because it consumes an earlier result?
2. What can run independently without touching the same mutable resource?
3. Can current state change the next route or stopping condition?
4. Can the system detect, explain, and replay a partial failure?

Baseline the straight route, test one bounded alternative, then compare critical-path latency, evidence passing the declared validation rule, duplicate external effects, incomplete merges, recovery success, and cost per successful run. I don’t know which shape wins before measurement. I think a change is earned only when its owner can show that the gain beats the coordination tax and explain how to reverse it.

Once the shape is chosen, [“The 105 minutes after the graph”](https://www.cubagarcia.com/drafts/67821675/) examines evaluation, declared state, and evidence for trusting a production run. Teams that mistake concurrent model calls for independent work will discover the difference during incident recovery, when every unearned route becomes an unowned failure path.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Measure the straight path first, add only the routes that improve a declared outcome, and require an owner who can explain and recover every failure path.</p></div>
