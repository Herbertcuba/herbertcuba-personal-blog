AI builders often talk as if a graph is advanced and a pipeline is primitive. I think that gets production architecture backwards.

A pipeline is already a graph: one directed path in which each required stage follows the previous one. Topology simply means the arrangement of stages and connections. The useful question is: what is the minimum topology that tells the truth about the work?

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>A pipeline is the smallest graph. Add routes only when the work requires them.</p></div>

## Start with real dependencies

A data dependency exists when one job consumes another job’s result. A resource dependency exists when jobs interfere through a mutable resource: a shared file, database record, workspace, approval, or service quota they can change or exhaust. [PostgreSQL, an open-source relational database](https://www.postgresql.org/docs/current/transaction-iso.html), documents concurrent writers waiting on one record; [Stripe, a payments platform](https://docs.stripe.com/rate-limits), documents separate rate and concurrency limits.

Apply the fake-edge test. If B consumes nothing from A, and running both creates no conflicting write, lock, approval, quota, or external effect, the A → B edge may be artificial. Both can read one immutable input because neither changes it. I think separate prompts prove nothing about operational independence.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Map consumed outputs and possible interference before counting agents.</p></div>

## Choose the shape the work requires

Keep a linear pipeline when sequence is real: ingest request → validate schema → apply policy → persist result. Each stage consumes or authorizes the next. Replay means rerunning known work after failure while controlling repeated external effects. I think this is often the strongest production shape when predictable recovery matters more than parallel speed.

Use a directed acyclic graph, or DAG, when independent work can branch and no route returns to an earlier stage. Fan-out starts branches; fan-in merges them. Its critical path, the longest required chain, still includes the slowest required branch. [AWS Step Functions, a managed workflow service](https://docs.aws.amazon.com/step-functions/latest/dg/state-parallel.html), documents a Parallel state that waits for all its branches before continuing.

A conditional graph selects its next route from current workflow state. A cyclic graph can return to earlier work, so it needs a stop rule and a hard attempt, time, or cost limit. A hybrid keeps a linear backbone around a bounded branch or return. [“Everyone Discovered Loops. Nobody Agrees What the Word Means.”](https://www.cubagarcia.com/posts/everyone-discovered-loops/) examines loop terminology and exit conditions.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Use a pipeline for sequence, a DAG for independent breadth, a conditional or cyclic graph for state-driven routing, and a hybrid for a bounded mix.</p></div>

## Write the merge contract first

Branches and cycles carry a coordination tax: partial failures, deadlines, retries, isolated writes, quotas, traces, and more model or tool calls. A join policy states which branch results are required before a merge may proceed. Retried external effects need idempotency, meaning one logical action keeps the same intended effect when repeated. Result provenance records which branch and input produced each output. [AWS documents explicit retry and catch behavior](https://docs.aws.amazon.com/step-functions/latest/dg/concepts-error-handling.html), while [Stripe documents idempotency keys for safe API retries](https://docs.stripe.com/api/idempotent_requests).

Consider a hybrid research stage with three isolated branches before a policy gate:

```text
run R42
market: required, complete, attempts 1
regulation: required, running, attempts 1
competitors: optional, timed_out, attempts 2
join: ALL_REQUIRED   retry_budget: 2
stop: deadline_reached OR retry_budget_exhausted
owner: research-service
merge(R42) -> REJECT MERGE_REQUIRED_BRANCH_PENDING(regulation)
```

The rejected transition tells an operator which required branch blocks the merge. Replay keeps the run and branch identities, writes to an isolated result, and reuses an idempotency key for an external effect. The product owner defines required evidence, the platform owner supplies the controls, and the service owner approves deadlines, recovery, and rollback. I think this contract matters more than another agent node.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Declare branch identities, requirements, retries, stop rules, replay, illegal transitions, and one accountable owner.</p></div>

## Make complexity prove its value

Topology does not choose the runtime. The same contract can run in a workflow service, queue workers, or state-machine code. A graph does not inherently add reliability or better judgment; those outcomes require alternate paths, validation, evidence, and controls.

Ask four questions in the design review:

1. What must wait because it consumes an earlier result?
2. What can run independently without touching the same mutable resource?
3. Can current state change the next route or stopping condition?
4. Can the system detect, explain, and replay a partial failure?

I don’t know which shape wins before measurement. Baseline the linear route, test a bounded alternative, then compare critical-path latency, accepted evidence, duplicate effects, recovery, and cost per successful run. [“The 105 minutes after the graph”](/drafts/67821675/) covers evaluation and declared state after topology selection.

I think the next fault line will be concurrent model calls mistaken for independent work, with the hidden dependency discovered during recovery. Every unearned edge is another failure path somebody must eventually own.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Promote topology only when measured value beats its coordination tax.</p></div>
