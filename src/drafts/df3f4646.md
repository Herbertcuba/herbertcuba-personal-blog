# Choose the smallest workflow topology that tells the truth

AI teams call graphs advanced and pipelines primitive. I think that reverses the choice. A pipeline is a graph with one directed path. A directed acyclic graph, or DAG, can branch and merge without returning; a cyclic graph contains a return path.

In an [X article about graph engineering](https://x.com/AnatoliKopadze/status/2080668775796314331), Anatoli Kopadze writes: “A graph buys breadth. It does not buy better judgment.” Edges coordinate work; they do not create validation, safe retries, or better decisions.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Choose the minimum topology that reflects order, width, and state change; extra arrows add coordination, not judgment.</p></div>

## Separate precedence from resource control

Take ingest request → validate schema → apply policy → persist result. Every stage needs the previous result, so a pipeline keeps recovery and replay visible.

A dependency edge says B waits because it consumes A’s result. Resource control asks whether A and B may run together. A mutable resource is a shared file, record, workspace, or approval state either can change. Two jobs may read one immutable snapshot safely, while writers to one record need serialization or a transaction; [PostgreSQL, an open-source relational database, documents waiting on a locked row](https://www.postgresql.org/docs/current/transaction-iso.html).

Apply the fake-edge test. If B does not consume A’s result and neither job conflicts through mutable state or quota, their edge may be artificial. A shared API limit needs a queue, not a false dependency. I think many overbuilt workflows confuse precedence with resource control.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Use edges for required order; use queues, limits, locks, or transactions when independent work shares capacity or state.</p></div>

## Design the join before the fan-out

When work is genuinely wide, fan-out starts independent branches and fan-in merges them. Five jobs can research and verify separate market angles before merging surviving evidence. [AWS Step Functions, Amazon’s managed workflow service, documents a Parallel state](https://docs.aws.amazon.com/step-functions/latest/dg/state-parallel.html) that waits for every branch. That is one policy, not a universal rule.

I think the merge is the decision. Define branch identities, required and optional results, a deadline, and a missing-result policy. Preserve provenance, meaning the inputs, sources, models, and tools behind each output. An all-required merge waits for its slowest branch.

The typed contract can stay small: Open, Ready, and Finalized(version). A success carries a branch ID, output hash, and idempotency key, the stable name of one intended effect. Reject an unknown branch, audit a duplicate without repeating its effect, and let a late optional result propose v2 without changing v1.

A branch retry repeats recorded input with the same effect key. A resume rebuilds control state without repeating committed effects; a full rerun gets a new identity and needs authority for new effects. [Temporal, a durable-execution platform, requires deterministic workflow code for replay](https://docs.temporal.io/workflow-definition) and excludes external calls from replay. Keep counting, deduplication, validation, routing, and join completeness in deterministic code; use models for judgment.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Fan out only after branch identity, merge completion, late results, replay scope, and duplicate effects have contracts.</p></div>

## Let runtime state earn routes and cycles

Conditional routing means current state selects the next edge. A risk score might choose automatic approval or human review while the workflow remains acyclic. A cycle sends execution back to earlier work.

I think a return edge earns its place only when changed state can alter the next attempt. Record that change, a stop rule, and a hard step, time, or cost limit. If two passes are known before execution, use two DAG stages instead. [“Everyone Discovered Loops. Nobody Agrees What the Word Means.”](https://www.cubagarcia.com/posts/everyone-discovered-loops/) covers loop language and exits.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Use a condition when state chooses a route, and a cycle only when changed state justifies returning and a rule stops it.</p></div>

## Promote the smallest useful hybrid

A hybrid is a linear backbone with bounded graph sections. I think it fits production: ordered intake, policy, approval, and persistence around parallel research.

Starting linear is a default, not dogma. If mandatory network calls are independent, stay within quotas, and miss a serial latency target, start with bounded fan-out. [Google Cloud’s Workflows guidance](https://docs.cloud.google.com/workflows/docs/execute-parallel-steps) warns that non-blocking parallel work can run slower because orchestration adds overhead. The workload decides.

Freeze baseline and publish acceptance bars. A promotion test might require 95th-percentile latency below 25 seconds versus a measured 40-second baseline, every required result, zero duplicate effects under retries, cost below €0.40 per run, and fewer than two operator minutes per 100 runs. Inject a timeout, duplicate completion, and late result. Miss one bar and stay linear.

Record the promotion approver, service and data owners, incident owner, rollback authority, and risk tier. Ask what needs an earlier result; what can run without mutable conflict; whether state can change the route or stop rule; and whether partial failure can be explained and replayed. I don’t know whether width pays until the trace survives. [“The 105 minutes after the graph”](https://www.cubagarcia.com/drafts/67821675/) covers evaluation, typed state, and trust controls.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Keep the linear backbone; retain branches or return paths only when measured benefit, controlled failure, and named authority beat the coordination tax. Choose the smallest graph that tells the truth.</p></div>
