AI workflow diagrams imply a status hierarchy: graphs look advanced, while pipelines look basic. That hides the choice. A pipeline is a graph with one directed path, where each required stage follows the previous one. More arrows do not make the work smarter.

Anatoli Kopadze’s [graph-engineering article](https://x.com/AnatoliKopadze/status/2080668775796314331) warns: “A graph buys breadth. It does not buy better judgment.” I think the practical question is: what minimum topology tells the truth?

<div class="chapter-tldr">
<span class="chapter-tldr__label">In short</span>
<p>Use a pipeline for sequence, a DAG for independent branches, and conditional or cyclic routing when state changes the path. A hybrid localizes breadth.</p>
</div>

## Start with two kinds of dependency

Draw two kinds of edge. A data edge means B consumes A’s result. A resource edge means both jobs change the same mutable resource, such as a file, database row, or approval state, or consume the same API quota. [PostgreSQL’s database documentation](https://www.postgresql.org/docs/current/transaction-iso.html) shows concurrent writers waiting; [Stripe’s payments API documentation](https://docs.stripe.com/rate-limits) separates request-rate limits from concurrency limits. Data-independent jobs can still collide.

The A → B edge may be artificial if B does not consume A’s result and concurrent runs neither race nor exhaust shared capacity. Reading an immutable snapshot is not a write conflict.

<div class="chapter-tldr">
<span class="chapter-tldr__label">In short</span>
<p>Keep an edge when work needs an earlier result or conflicts through shared state, capacity, or control.</p>
</div>

## Keep real sequence linear

Keep the straight path when every stage truly waits. Ingest request → validate schema → apply policy → persist result is a pipeline because each step needs the prior result or authorization. The route is known, and a failed run has an obvious replay point.

I think an ordered path is often the strongest artifact when sequence is real. Keep schema checks, deduplication, counting, and fixed routing in code; use a model for judgment. Instrument before promoting a stage into a branch.

<div class="chapter-tldr">
<span class="chapter-tldr__label">In short</span>
<p>A linear pipeline keeps dependencies, recovery, and ownership clear when each stage genuinely enables the next.</p>
</div>

## Use a DAG only for real breadth

A DAG, or directed acyclic graph, can branch and merge but cannot return to earlier work. Fan-out starts independent jobs; fan-in combines their outputs. Researching five market angles in separate branches, verifying each, then merging the survivors is honest breadth.

[AWS Step Functions](https://docs.aws.amazon.com/step-functions/latest/dg/state-parallel.html), Amazon’s managed workflow service, shows one concrete join: its Parallel state waits for every branch. Other policies may retry or accept incomplete work, but they must be explicit.

The merge needs expected branch identities, a schema, a deadline, a missing-result policy, and provenance: the sources, inputs, models, and tools behind each output. When all branches are required, the slowest sets the earliest finish; shared quotas can erase the gain. I think the merge is the architecture decision, not the fan-out.

<div class="chapter-tldr">
<span class="chapter-tldr__label">In short</span>
<p>Parallelize real breadth only when the branches are independent and the merge can account for expected results, failures, and sources.</p>
</div>

Turning the launch into a fleet graph adds mission-control paths without changing the work.</p>

## Add a return path only when state changes

Conditional routing means current state selects the next edge. A cyclic graph can return to earlier work. An evidence score might trigger specialist verification, or a retryable tool error might return after backoff.

If the passes are known before execution, use a fixed DAG. I think a cycle earns its place only when runtime state changes what happens next. Give it a stop rule and a hard step, time, or cost limit. [LangGraph](https://docs.langchain.com/oss/python/langgraph/graph-api), a framework for stateful agent workflows, documents state-selected edges and an execution limit. [“Everyone Discovered Loops. Nobody Agrees What the Word Means.”](https://www.cubagarcia.com/posts/everyone-discovered-loops/) goes deeper on feedback terminology and exit conditions.

<div class="chapter-tldr">
<span class="chapter-tldr__label">In short</span>
<p>Add a condition or cycle only when current state changes the next action, and give every return path a reason to stop.</p>
</div>

## Price the coordination tax

A branch can leave a run partly done. Choose whether failure stops, retries, accepts survivors, or escalates. Idempotency means a retry does not duplicate its intended effect; [Stripe’s documentation](https://docs.stripe.com/api/idempotent_requests) shows one API implementation. Isolate writes and trace branch inputs, errors, retries, and merge decisions. Extra model branches can multiply token and tool use.

I don’t know whether wider execution will repay that tax in your system. Measure duration, throttling, retries, join completeness, and replay success. I think the strongest production default is often a hybrid: a linear spine with a bounded fan-out/fan-in section for research or verification. After topology selection, [“The 105 minutes after the graph”](https://www.cubagarcia.com/drafts/67821675/) covers evaluation, typed state, and trust.

Before adding another edge, ask four questions:

1. What must wait because it consumes an earlier result?
2. What can run independently without touching the same mutable resource?
3. Can runtime state change the next route or stopping condition?
4. Can the system detect, explain, and replay a partial failure?

My take: start with the smallest truthful shape and make every added edge earn its place.

<div class="chapter-tldr">
<span class="chapter-tldr__label">In short</span>
<p>Choose the smallest graph that matches the dependencies and can explain failures. Measured work, never decorative arrows, earns complexity.</p>
</div>
