OpenClaw’s public numbers still look dominant. By August 17, 2026, its open-source repository had reached 386,457 GitHub stars, even as the public conversation around the project became much quieter.

A GitHub star is a public bookmark. It measures accumulated attention, not active use or retention, so this gap does not justify an obituary. My take is that OpenClaw’s more important result was making large-scale demand for AI systems that act on a user’s behalf impossible to ignore.

What happened next showed why proving that demand and capturing the category are different jobs.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>OpenClaw’s rising star count proves accumulated attention, not retained use; its stronger signal is the market’s appetite for AI that can take action.</p></div>

## What OpenClaw made visible

[OpenClaw](https://github.com/openclaw/openclaw) is an open-source AI agent created by Austrian developer Peter Steinberger. An AI agent gives a language model tools and permissions so it can complete work rather than only answer. OpenClaw was self-hosted, meaning it ran on a user’s own computer, and could work through messaging services, a browser, or the machine’s text-based shell while continuing tasks in the background.

The project’s [official history](https://github.com/openclaw/openclaw/blob/main/docs/start/lore.md) records a rapid naming sequence in January 2026: ClawdBot became Moltbot on January 27, then OpenClaw on January 30. Through each name, the proposition stayed clear: message the agent where conversation already happens and let it reach the tools where work happens.

[Anthropic, the AI company behind the Claude models, had introduced experimental computer use in 2024](https://www.anthropic.com/news/3-5-models-and-computer-use), so OpenClaw did not invent action-taking AI. It validated demand for a particular combination of local control, messaging access, computer tools, and background operation in one accessible system.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>OpenClaw turned several existing agent capabilities into a compelling package and made demand for that package visible at unusual scale.</p></div>

## The cost of letting software act

The permissions that made OpenClaw useful also raised the stakes. An agent that can read messages, handle credentials, browse websites, and run commands has broad authority. If someone compromises it, the damage can reach the user’s machine and accounts.

By August 17, the project’s [official list](https://github.com/openclaw/openclaw/security/advisories) contained 143 published security advisories. One critical flaw, tracked as [CVE-2026-25253](https://github.com/openclaw/openclaw/security/advisories/GHSA-g55j-c2v4-pjcg), described a one-click route to remote code execution, meaning an attacker could make code run on another person’s computer. The count represents disclosed weaknesses, not 143 successful attacks, but it shows the review burden created when powerful local software spreads quickly.

Model access created separate pressure. Anthropic’s current [consumer terms](https://www.anthropic.com/legal/consumer-terms) prohibit automated access unless an application uses an Anthropic API key or receives explicit permission. An API is the paid software connection through which another product calls a model; [billing](https://platform.claude.com/docs/en/about-claude/pricing) charges by tokens, the small units of text the model processes. This does not prove every OpenClaw setup cost more, but it removed a flat consumer subscription as a safe long-term assumption.

Managed agents can remove installation and update work, but they move trust and control to the vendor. The competitive opening was the chance to make these trade-offs easier for more people to accept.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>OpenClaw’s broad permissions raised security and maintenance demands, while provider rules added model-access pressure.</p></div>

## Stars lag product reality

Stars kept climbing through those pressures because they accumulate. They do not reveal how often the software runs, whether a user still trusts it with important work, or whether that user adopted something else.

Less social-media attention does not prove that OpenClaw lost users either, and repository data cannot show where anyone went. The narrow conclusion is the useful one: 386,457 stars establish extraordinary awareness, while retention and migration remain unmeasured. Visible growth can continue after a product’s original distinction has begun to spread.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Repository stars measure accumulated awareness. They cannot establish active use, loyalty, decline, or migration to a competitor.</p></div>

## Action became an expectation

Once OpenClaw had made the package legible, “this agent can act” became easier to copy. Model vendors could add computer control to existing products, managed services could absorb setup, and open-source projects could combine the same ingredients with different design choices.

[Hermes Agent](https://github.com/NousResearch/hermes-agent), an open-source agent harness from AI research company Nous Research, shows this diffusion; its first formal GitHub release appeared on March 12, 2026. A harness is the software around a model that coordinates its tools and multi-step work. Hermes’ [documentation](https://hermes-agent.nousresearch.com/docs/user-guide/features/skills) describes persistent memory, reusable skills, and post-task review that can refine those skills.

That supports an architectural comparison, not a migration story. There is no evidence that OpenClaw users moved to Hermes in matching numbers, and documentation cannot prove superior security. The signal is that action and memory were becoming category features rather than one project’s durable edge.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>As other systems reproduced action-taking capabilities, the category gained a standard feature and OpenClaw’s first-mover lead narrowed.</p></div>

## What compounds after the breakthrough

Explosive adoption can outrun even an active project. On August 17, the [OpenClaw repository](https://github.com/openclaw/openclaw) showed 1,243 open issues and 1,338 open pull requests, which are proposed code changes awaiting review. Yet it had published 25 releases since July 19, and its latest 100 pull requests had been merged within roughly 15.5 hours. Together, these figures show incoming demand and maintainer throughput rising at once rather than abandonment.

Safe review does not scale automatically with popularity. More contributors can produce more fixes, but each change still needs people who understand its interaction with permissions, credentials, and operating systems. A backlog does not prove that maintenance failures caused a vulnerability. It shows why review capacity and security response are part of defensibility.

Steinberger’s move adds continuity rather than a clean break. On February 14, he [announced that he was joining OpenAI](https://steipete.me/posts/2026/openclaw), the AI company behind ChatGPT, and said OpenClaw would move to an independent foundation. That supports an intended transition, not an acquisition or proof of completed legal status.

I think OpenClaw’s record matters more than either a victory or failure story. It showed how many people wanted an agent woven into existing tools and trusted to continue beyond one reply. Once competitors could copy that promise, lasting leadership had to come from what compounds afterward: trusted distribution, safer defaults, learning from repeated work, and enough capacity to keep the system reliable.

OpenClaw validated the demand. Who captures that demand will be decided by the systems built around the capability once the capability itself is common.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>OpenClaw proved the market, but category leadership depends on earning trust and improving the whole system after competitors copy the core idea.</p></div>
