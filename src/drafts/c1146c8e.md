On 17 August 2026, the [GitHub repository for OpenClaw](https://github.com/openclaw/openclaw), an open-source system that lets AI act through a person’s tools, had 386,514 stars. A repository is the public page where a project keeps its code. Yet the YouTube channel BetterWay was already asking [“What Happened To OpenClaw?”](https://youtu.be/moRJqv1z6ww?is=NVS3vjDxPFuWwxzP). The number suggested growth, while the question suggested the moment had passed.

Neither tells us how many people still use OpenClaw. GitHub describes a [star](https://docs.github.com/en/get-started/exploring-projects-on-github/saving-repositories-with-stars) as a way to save a project or show interest. Stars measure attention over time, not installations, paid use, repeat use, or completed work.

My take is that OpenClaw made a large appetite for AI that could act on a person’s behalf visible. That is category validation: evidence that a product idea can attract serious interest. Category capture means turning that interest into lasting, valuable use. OpenClaw clearly helped with the first; the second remains open.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>OpenClaw attracted unusual attention, but stars are not usage data. The evidence shows strong interest in the idea, not a settled winner or a dead product.</p></div>

## What people saw in OpenClaw

Peter Steinberger, an Austrian software developer, created the repository in November 2025. The project’s [official history](https://github.com/openclaw/openclaw/blob/main/docs/start/lore.md) says Clawdbot became Moltbot on 27 January 2026, then OpenClaw on 30 January.

OpenClaw calls itself a [self-hosted gateway](https://docs.openclaw.ai/llms.txt): software that a person runs on their own computer to connect an AI model with messaging apps and tools. A user could send a request through WhatsApp or Telegram while OpenClaw [controlled a browser](https://docs.openclaw.ai/tools/browser), [ran commands](https://docs.openclaw.ai/tools/exec), and [worked in the background](https://docs.openclaw.ai/automation/tasks). An AI agent is software that uses tools to pursue a goal instead of stopping after it writes an answer.

OpenClaw did not invent computer-using AI. In October 2024, Anthropic, the company behind the Claude family of AI models, introduced [computer use](https://www.anthropic.com/news/3-5-models-and-computer-use), which let a model inspect a screen, move a cursor, click, and type. OpenClaw put local control, messaging, tool access, and background work into one clear product. Its GitHub response showed broad interest in that combination, though not long-term use.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>OpenClaw made one product idea easy to understand: message an AI through familiar apps and let it use real tools on your computer. The response made interest in that idea hard to ignore.</p></div>

## The cost of letting software act

The access that made OpenClaw useful also made mistakes more serious. A [GitHub security advisory](https://github.com/advisories/GHSA-g55j-c2v4-pjcg), a public notice about a software weakness and its fix, reported that a program on the same computer could change gateway settings without proving it had permission. It could then run commands with the user’s rights. The flaw was fixed. The advisory is not evidence of a breach or broad company ban; it shows why software that acts needs stronger limits than software that only answers.

The model adds a second dependency. [Anthropic’s consumer terms](https://www.anthropic.com/legal/consumer-terms) say automated tools must use an API key, a software credential for calling its models, or have explicit permission. Its [API pricing](https://platform.claude.com/docs/en/about-claude/pricing) charges for model use. A self-hosted agent therefore still inherits supplier rules and costs, although these records do not establish a universal OpenClaw cutoff or price increase.

The project’s growth added a large review job. A GitHub snapshot taken for this article on 17 August recorded [3,425 open issues](https://github.com/search?q=repo%3Aopenclaw%2Fopenclaw%20is%3Aissue%20is%3Aopen&type=issues) and [2,198 open pull requests](https://github.com/search?q=repo%3Aopenclaw%2Fopenclaw%20is%3Apr%20is%3Aopen&type=issues). An issue is a reported problem or request; a pull request is a proposed code change. The snapshot also found [8,601 pull requests merged in the previous 30 days](https://github.com/search?q=repo%3Aopenclaw%2Fopenclaw%20is%3Apr%20is%3Amerged%20merged%3A%3E%3D2026-07-18&type=issues). This shows heavy work and fast maintenance, not abandonment or the cause of any security flaw.

The ownership story also changed. In February 2026, Steinberger said he was [joining OpenAI](https://steipete.me/posts/2026/openclaw), the company behind the ChatGPT AI assistant, and that OpenClaw would move to a foundation. His [profile](https://steipete.me/about) now says the independent OpenClaw Foundation looks after the project. That tells us who is responsible for OpenClaw, but it says nothing about a purchase by OpenAI or whether users left.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Letting software act creates security, supplier, and maintenance work. OpenClaw faced real pressure, but the public record also shows an active project handling a very large workload.</p></div>

## When action stops being special

Action now comes in several forms. [OpenAI’s ChatGPT agent](https://openai.com/index/introducing-chatgpt-agent/) uses a provider-run virtual computer to navigate websites and execute code. [Hermes Agent](https://github.com/NousResearch/hermes-agent), an open-source project from AI research company Nous Research, documents browser and command-line tools, [memory between sessions](https://hermes-agent.nousresearch.com/docs/user-guide/features/memory), and reusable instructions called [skills](https://hermes-agent.nousresearch.com/docs/user-guide/features/skills).

These features show that action is no longer unique. Feature overlap cannot tell us whether OpenClaw users moved to Hermes, which system is safer, or which one costs less to run. A managed agent runs on a vendor’s computers, reducing local setup but moving trust to that vendor. A self-hosted agent gives its operator more control and more responsibility for updates, permissions, where data is stored, and recovery.

I think buyers will ask “Can it act?” less often as the feature becomes normal. They will ask how much work people accept, how often a person must step in, who can stop the system, how quickly mistakes can be reversed, and what each accepted result costs. A durable edge is an advantage that survives repeated use. Here, it will come from trusted work and proof that others can check, not action alone.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>As more agents gain browser and command access, action becomes a basic feature. The products that last will prove useful results, clear control, fast recovery, and a cost people can sustain.</p></div>

## How to test lasting use

Public attention cannot prove category capture, but repeated work can. Run 50 to 100 cases of one recurring process over six weeks, alongside the current method. Keep the model and tool versions, permissions, and maximum repeat attempts fixed.

Name the owners before the first case. A business owner defines an accepted result and its target rate. Technology and security teams approve access and name who can pause the agent. Legal or procurement owns the provider terms, where data is stored, the budget, and the exit route. A result counts only when the business can use it without repair.

Count every attempt, including repeats. Track the share of all attempts accepted, how often a person steps in, actions beyond approved limits, recovery time, and full cost per accepted result. Full cost includes model use, infrastructure, setup, review, and repair.

Set the acceptance target, the maximum number of human interventions, and the maximum cost before the test. Scale only when all three are met. Pause after an unapproved action, and stop after data loss or a change that cannot be reversed. Keep a plan for undoing changes and a way to change suppliers.

The public sources used here do not contain this kind of repeat-use evidence for OpenClaw. Its importance lies elsewhere: the project made interest in action visible at unusual scale as action became a basic capability across the market. The first product to reveal an appetite is not guaranteed to keep it. What compounds over time is repeated work that people trust, plus evidence that the system stays inside its limits.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Category capture begins when repeated work meets an agreed standard under named ownership, fixed permissions, clear costs, and stop rules set in advance. OpenClaw revealed the appetite; which product earns lasting use remains open.</p></div>
