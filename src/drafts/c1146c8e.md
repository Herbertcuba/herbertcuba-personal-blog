OpenClaw is an open-source AI agent: software that can use tools and complete multi-step work instead of only returning text. Its [official documentation](https://docs.openclaw.ai/) describes a self-hosted gateway, meaning it runs on a user’s computer or server and connects messaging services such as WhatsApp and Telegram to a browser and a command-line shell, the text interface for controlling a computer. Users can message it where they already communicate and let it continue working in the background.

The current picture looks contradictory. OpenClaw’s repository on GitHub, the code-hosting platform, had more than 386,000 stars on 17 August 2026; a star is a user-created bookmark and signal of interest. Yet a project with that number can now be discussed as though its moment has passed. That tension does not prove active use fell. It shows how easily cumulative attention gets mistaken for live product leadership.

My take is that OpenClaw’s most important result sits underneath that argument. It made demand for a particular bundle of capabilities visible at unusual scale: local control, familiar messaging, browser and shell access, and background work. Proving that demand and building the durable edge to serve it are different jobs.

<span class="chapter-tldr__label">In short</span>
<p>OpenClaw turned action-taking AI into visible market demand, but its rising public metric cannot tell us whether first-mover attention became lasting leadership.</p>

## Machine authority creates operating pressure

Peter Steinberger, the Austrian software developer who created OpenClaw, first released the project under other names. The project’s [official history](https://github.com/openclaw/openclaw/blob/main/docs/start/lore.md) records the late-January 2026 sequence as Clawdbot, Moltbot, and finally OpenClaw on 30 January. The names changed quickly; the consequential design choice remained local authority over a user’s tools and data.

That authority expands the attack surface, the paths through which software could be misused. As of 17 August 2026, the project’s official GitHub endpoint listed 647 published security advisories. An advisory records a disclosed weakness, not an attack or breach, but the volume makes the review burden concrete. One [official advisory](https://github.com/openclaw/openclaw/security/advisories/GHSA-g55j-c2v4-pjcg) used CVE-2026-25593, a standard public vulnerability identifier, for an unauthenticated local remote-code-execution flaw in the gateway’s WebSocket configuration channel. A WebSocket is a persistent connection between software systems; here, a process already on the same machine could make the gateway execute commands as its user. Version 2026.1.20 patched the flaw.

Model access added a separate constraint. [Anthropic’s consumer terms](https://www.anthropic.com/legal/consumer-terms) restrict automated or non-human access unless it uses an Anthropic API key or the company explicitly permits it. An API key lets software call a model, while [API billing](https://platform.claude.com/docs/en/about-claude/pricing) charges by the text processed and produced. This does not establish a universal price increase for OpenClaw users, but it can replace a predictable consumer subscription with a variable operating cost.

<div class="chapter-tldr">
<span class="chapter-tldr__label">In short</span>
<p>The permissions that made OpenClaw useful also created security, review, and model-access costs that a product must manage as it scales.</p>
</div>

## GitHub stars do not measure retained use

A star stays in GitHub’s total until its user deliberately removes it, as [GitHub’s documentation](https://docs.github.com/en/get-started/exploring-projects-on-github/saving-repositories-with-stars) explains. The count can therefore keep rising after early users change tools, use the project less, or stop paying attention.

Stars answer how much cumulative interest a project attracted. They cannot tell us how many people still run it, how often it completes useful work, or where former users went. Social visibility cannot fill that gap. OpenClaw’s repository remains active, so inactivity would be the wrong conclusion, but repository activity is not a retention measure either.

<div class="chapter-tldr">
<span class="chapter-tldr__label">In short</span>
<p>OpenClaw’s star total is strong evidence of extraordinary attention, but it cannot establish active use, retention, or migration to another product.</p>
</div>

## Action stopped being a rare capability

OpenClaw did not invent software that controls a computer. Anthropic, the company behind the Claude AI models, [introduced computer use](https://www.anthropic.com/news/3-5-models-and-computer-use) in October 2024. What OpenClaw demonstrated was appetite for a self-hosted agent that combined computer control with messaging and background execution in one accessible package.

That bundle became easier to find elsewhere. OpenAI, the company behind ChatGPT, added a [ChatGPT agent](https://openai.com/index/introducing-chatgpt-agent/) that navigates websites, runs code, and completes multi-step work. Open-source teams built other agent harnesses, the software layer connecting a model to tools, memory, and workflows. Managed products can remove installation and maintenance work, although they move trust and data exposure to the vendor rather than eliminating risk.

Hermes Agent, an open-source agent harness from AI research company Nous Research, is one relevant entrant. Its [documentation](https://hermes-agent.nousresearch.com/docs/user-guide/features/skills) describes persistent memory and reusable skills, including a `/learn` command that can turn a completed approach into a skill for later use and refinement. Its repository had more than 231,000 stars on 17 August. Those facts establish visibility and a design difference. They do not establish that OpenClaw users migrated to Hermes, or that Hermes avoids comparable security and pricing exposure.

Once action becomes available from many directions, the feature itself stops carrying the strategy. Defensibility has to come from what compounds around it: reliability, distribution, governance, and the ability to learn from real work without losing control.

<div class="chapter-tldr">
<span class="chapter-tldr__label">In short</span>
<p>OpenClaw validated a valuable combination of agent capabilities, but competing vendors and open-source harnesses made action increasingly common and shifted the contest to the system around it.</p>
</div>

## Validation is only the first job

Explosive adoption can outrun even an active project. A 17 August snapshot of GitHub search showed roughly 3,400 open issues, meaning reported problems or requests, and about 2,200 open pull requests, meaning proposed code changes awaiting a decision. Yet more than 8,600 pull requests had been merged during the preceding 30 days. That points to heavy contribution pressure and high throughput at the same time, not to maintainers simply walking away. Nor does it prove that backlog caused any specific vulnerability.

Governance changed as the project grew. On 14 February 2026, Steinberger [announced](https://steipete.me/posts/2026/openclaw) that he was joining OpenAI and that OpenClaw would move to a foundation intended to keep it open and independent. Current OpenClaw documentation describes that foundation as a non-profit. This was a change in stewardship, not an announcement that OpenAI had acquired the project.

I think this is where the strategic lesson becomes useful. OpenClaw made a large audience’s interest in delegated action impossible to dismiss, even though computer-control products existed before it. Once that signal was visible, every competitor could study the same demand while choosing a different balance of convenience, control, cost, and risk.

The project that validates a category has done valuable work. Category capture begins afterward, when attention must become repeatable outcomes and the operating burden must be carried at scale. OpenClaw did not need to own the category to prove it, but proof alone does not decide who will serve that category over time.

<div class="chapter-tldr">
<span class="chapter-tldr__label">In short</span>
<p>OpenClaw proved substantial demand for action-taking agents; lasting leadership now depends on whether a project can turn that demand into reliable use while governing security, cost, contribution volume, and trust.</p>
</div>
