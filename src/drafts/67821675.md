# The graph is the easy 15 minutes

Your agent graph can look finished before it survives one support ticket its author did not write.

Lance Martin's [2024 AI Engineer workshop](https://www.youtube.com/watch?v=ib-wTAvCZqg) sketches a controllable agent early, then keeps returning to testing. Jey [compressed that structure](https://x.com/0xJeyx/status/2081364222856831271) into 15 minutes of graph and 105 minutes of evaluation.

A viral [recap](https://x.com/0xMovez/status/2081011657807925604) attached a 70% Anthropic adoption claim and a three-to-six-month "no more prompting" forecast to the workshop. Neither claim appears in the recording or five Martin posts audited for this piece. Martin [confirmed](https://x.com/RLanceMartin/status/2081408482344149047) that the talk predates Anthropic. If sourced later, 70% would forecast tooling assumptions without supplying release evidence this quarter. I think the verified ratio is sharper: routes are quick; trust is slow.

## One refund exposes the graph

Use one ticket: "Order 8841 charged me twice. Refund it now."

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Prompts and context shape each model call; the graph assigns the surrounding jobs. The refund case becomes a diamond that gathers evidence before review and approval.</p></div>

[Greg Isenberg's graph-engineering video](https://youtu.be/JWhICz1QR8M) separates prompt, context and graph engineering. A prompt instructs the model using the ledger and refund policy as context. The graph assigns work outside one giant chat.

Nodes are jobs; edges are allowed routes. A transition is one move along an edge. Shared state holds what the system knows. Conditional routing reads that state before choosing the next node.

Order 8841 is classified first. Ledger lookup and policy search then fan out in parallel. Their findings meet at a checker, or skeptic, which attacks weak evidence. A merge node drafts the answer. A human gate approves any refund before money moves. This split and merge is the diamond topology. Sequential steps wait for a dependency; parallel steps run together.

The policy node may use ReAct, short for reasoning and acting. The model chooses a search tool, reads the result and may continue. ReAct stays inside one node; the graph controls the next handoff.

A knowledge graph connects the customer to the order and payment record. An agent graph carries the ticket through support work. I think this keeps the diagram honest: one maps information relationships; the other maps movement.

## State gives the arrows memory

The refund route needs a record that survives every handoff.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Typed state exposes the workflow contract, while persistent files preserve evidence and decisions. Automate the smallest route that improves the manual work.</p></div>

```python
from typing import Literal, TypedDict
from langgraph.graph import StateGraph

class TicketState(TypedDict):
    ticket: str
    ledger_result: str | None
    policy_result: str | None
    route: Literal["reply", "human_review"]
    approved: bool

graph = StateGraph(TicketState)
```

A [`TypedDict`](https://docs.python.org/3/library/typing.html#typing.TypedDict) declares expected keys and value types in a Python dictionary. Static type checkers can catch a malformed node result. Python leaves runtime enforcement to code, so `approved: bool` cannot block a refund by itself.

LangGraph is a Python framework for stateful agent workflows. Its [`StateGraph`](https://docs.langchain.com/oss/python/langgraph/graph-api) class connects nodes around shared state. Edges can branch or loop, while checkpoints let a run pause and resume.

Run the jobs manually with separate prompts first. Next, save artifacts such as `ledger.json`, `policy.md` and `review.md`. Add orchestration after repeated runs expose a stable route. I think teams should remain at the file stage until the workflow improves decisions.

Saved files provide persistent memory. A rejected refund can become a sourced policy note or eval case. More nodes add coordination cost, so aim for the smallest graph that improves quality.

Risk sets the human gate. A shipping reply may pass after checking. A refund pauses for approval. Account access needs tighter authority plus an event record. The reviewer must see the evidence behind the draft.

## A checker still sees one ticket

Separation inside the graph improves a run without proving the system across unfamiliar cases.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>A skeptic reviews one ticket. An eval set repeats that separation across inputs selected outside the build loop, turning a review pattern into release evidence.</p></div>

Isenberg's 26-minute video contains zero eval mentions. Its case stops at workflow design. Martin's workshop and [Anthropic's guidance](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents) supply evaluation.

The checker may catch a missing policy quote on Order 8841. It may share the writer's blind spot when one model handles both roles. Separate instructions and tools help. Deterministic checks should enforce every rule visible in state.

HAL 9000 in *2001: A Space Odyssey* follows a clean command chain while incompatible goals corrupt the mission. The path stays orderly as the outcome fails. I think an agent graph can carry a bad refund decision through every correct arrow.

Martin's workshop tests final responses and tool-use paths. Its description covers runtime correction, pre-production testing and production monitoring. Jey's 15/105 ratio points to that burden.

## The eval set becomes the release asset

Order 8841 needs siblings the builders did not choose.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Start with 20 to 50 failure-derived tasks, repeat important trials and keep a hidden slice under independent ownership. The graph routes work; the eval set decides whether a release earned trust.</p></div>

Anthropic defines a task as one input with a success rule. Each attempt is a trial. A grader scores the trace, the final outcome or both. Anthropic recommends 20 to 50 simple tasks from real failures.

Include two settled charges, one settled charge plus a pending authorization, the same complaint in Spanish and an ordinary shipping request. A code grader can inspect state and block forbidden refund transitions. A model grader checks the explanation. A human owns ambiguous policy calls.

Keep part of the set with an independent reviewer. The support owner defines acceptable outcomes; a platform team maintains the runner. Repeat key cases when comparing releases. Corrected failures then become fresh cases. This pays down [verification debt](/posts/2026-03-09-verification-debt-crisis/) without centralizing domain judgment.

The graph is the control plane because it routes work. Typed state and evals form the trust plane because they expose the contract across releases. That durable evidence also answers [who owns the agent layer](/posts/who-owns-the-agent-layer/).

"No more prompting" belongs beside "no more code." Both slogans exaggerate a real move toward orchestration. Prompts remain inside the classifier and checker. I don't know when agent templates will create serious eval datasets by default.

Until a hidden ticket passes, the graph records an intention rather than a result.
