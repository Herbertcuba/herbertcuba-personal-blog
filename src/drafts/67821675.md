# The subtle art of context engineering: 15 minutes to draw, 105 to prove

“Which node in your graph has never met an input you did not write yourself?” [Jey asked](https://x.com/0xJeyx/status/2081364222856831271) after framing Lance Martin’s workshop as 15 minutes of graph drawing and 105 minutes of evaluation. His ratio is an interpretive contrast. The official 2024 recording raises [testing at 15:35](https://youtu.be/ib-wTAvCZqg?t=935), discusses [evaluation at 23:06](https://youtu.be/ib-wTAvCZqg?t=1386), and returns to [eval datasets near 1:42:00](https://youtu.be/ib-wTAvCZqg?t=6120). The diagram travels; learning accumulates in the evidence loop.

[Martin defines context engineering](https://rlancemartin.github.io/2025/06/23/context_engineering/) as giving each step the right information. [Greg Isenberg separates the layers](https://youtu.be/JWhICz1QR8M?t=84): the prompt shapes the request, context supplies inputs, and the graph moves work. I think token use improves when each model step gets actionable evidence and each consequential transition has a test.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>The 15/105 contrast exposes production reality: graphs route context, while unfamiliar cases show whether the routes deserve trust.</p></div>

## Route context through explicit state

Take a hypothetical refund request for order 8841. A model classifier reads the request and order ID. A deterministic step fetches the ledger and writes `payment_state: pending` into shared state; policy retrieval adds `policy_version`. Only then does a deterministic router read those fields and send the case to payment review. The reviewer receives only the ledger excerpt and policy section.

[Isenberg calls](https://youtu.be/JWhICz1QR8M?t=233) nodes jobs and edges allowed handoffs. A transition is the edge a case takes; shared state is the compact case file each job updates. Conditional routing reads named state and chooses the next edge.

A proposed typed case file allows `order_id`, `payment_state`, `policy_version`, `proposed_action`, `review_required`, and `evidence_refs`. Its release test can assert that `payment_state: pending` never reaches `refund_approval`, while a missing `policy_version` fails before routing. I think this connects context to evaluation: the schema limits what travels, and the test checks what those fields cause.

A knowledge graph represents relationships among the customer, order, payment, and policy. An agent graph controls movement through the work. This keeps token use concrete: each node receives a selected case file instead of an expanding chat history.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>Typed state focuses context; transition tests expose missing fields and unsafe routes.</p></div>

## Build the smallest graph you can inspect

Dependent work stays sequential. After classification, ledger and policy retrieval can fan out in parallel, then merge before review. This diamond topology exposes two branches and one merge point, so an engineer can inspect which evidence survived each handoff.

The proposal then reaches a separate checker, or skeptic, with authority to reject it. [Isenberg argues](https://youtu.be/JWhICz1QR8M?t=716) that generation and checking are different jobs. Asking one model to propose and approve the refund resembles asking HAL 9000 in *2001: A Space Odyssey* to steer Discovery One and certify its own flight log. The weakness comes from the combined role.

Human approval should scale with the cost of error. A private internal summary may need sampled review; this hypothetical refund requires approval before money moves. My take is to keep the [smallest graph that improves quality](https://youtu.be/JWhICz1QR8M?t=1252), because every extra node consumes context and creates another failure surface.

Isenberg’s maturity ladder runs from a manual workflow, through file artifacts, to orchestration software. Files stored under an `order_id/run_id` leave a paper trail; a later run retrieves an approved artifact by identifier and policy version. Frameworks add checkpoints, persistence, recovery, and human pauses. I think they preserve state well; they cannot choose representative failures for the team.

<div class="chapter-tldr"><span class="chapter-tldr__label">In short</span><p>The smallest useful graph separates workers from checkers, stores retrievable evidence, and puts human approval beside costly errors.</p></div>

## Make held-back failures the release boundary

Isenberg explains graph mechanics and leaves eval sets outside his scope. The architecture supplies the bridge: a checker inspects one run, while a held-back set repeats that challenge across cases excluded from development. Martin’s workshop supplies the testing emphasis; [Anthropic’s eval guidance](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents) supplies the method.

Anthropic recommends starting with 20 to 50 simple tasks drawn from real failures. For the refund graph, a code grader can reject the unsafe transition and missing fields, a model grader can assess the policy explanation, and a human can settle disputed labels. Multiple trials reveal whether the route succeeds consistently.

I would freeze the held-back partition for each release. Support proposes corrected failures; the policy owner adjudicates labels; engineering owns the harness; and a dataset maintainer alone writes the next version after adjudication. The release approver records the model, policy, eval versions, and deployment decision. Low-risk workflows may combine roles if one owner stays visible. No consequential graph is production-ready until its held-back evidence, policy version, and accountable owner are recorded.

The viral retelling tied a 70 percent adoption claim, a three-to-six-month forecast, and “No more prompting” to Martin’s workshop. The official captions contain none of those phrases, and [Martin clarified](https://x.com/RLanceMartin/status/2081408482344149047) that the recording predates his Anthropic role. I don’t know which framework will dominate. I think graph primitives will converge, while versioned failure sets produce steadier releases across model and policy changes.

A graph is the control plane for moving work. Typed state, stored evidence, and held-back failures make its trust plane auditable and reversible. Drawing the route takes an afternoon. Authority begins when it survives cases its builders did not choose.
